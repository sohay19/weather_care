# 날씨챙겨 앱 탭 구성 현황

- 기준일: 2026-08-24
- 기준: `weather_care_app/lib` 현재 구현 코드
- 수정 진행 순서: **Main → Today → Detail → Week → Setting**
- 하단 내비게이션 표시 순서: **Today → Detail → Main → Week → Setting**
- 앱 최초 진입 탭: **Main** (`selectedIndex = 2`)

> 이 문서는 기획 메모가 아니라 현재 구현 상태를 기준으로 관리한다.
>
> 표기: **완료**는 코드와 회귀 테스트까지 반영된 항목, **부분 완료**는 UI만 있고 저장·운영 연동이 남은 항목이다.

## 적용 상태 한눈에 보기

| 영역 | 상태 | 이번 반영 핵심 |
| --- | --- | --- |
| 공통 날씨 아이콘 | 완료 | 비를 구름+빗방울로 표시하고 맑음·구름 많음·흐림·강수 형태를 구분 |
| Main | 완료 | 상단 날씨 카드 아래 실제 챙김 Check List와 03~24시 간단 타임라인 배치 |
| Today | 완료 | 현재 상세 날씨 카드를 최상단에 배치하고 시간별 예보를 이어서 표시 |
| Detail | 완료 | 생활행동별 체크할 일·판단 근거·공식/계산 자료를 한 카드 세트로 배치 |

## 1. 공통 화면 구조

### 탭 및 상태 유지

- 5개 탭은 `HomeScreen`의 `IndexedStack`으로 구성된다.
- 탭을 이동해도 각 탭의 위젯 상태는 유지된다.
  - 예: Main에서 체크한 준비물, Today에서 펼친 지표, Setting에서 바꾼 토글 상태
- 하단 내비게이션 높이는 74px이며 모든 탭 라벨을 항상 표시한다.
- 선택 전후 아이콘 색상은 동일하게 유지하고 아이콘 모양과 배경 표시로 선택 상태를 구분한다.
- Main의 준비물 정보 버튼이나 타임라인 준비물을 누르면 Detail 탭으로 이동한다.
  - 선택한 준비물과 관련된 근거를 우선 배치하고 해당 카드로 이동한다.

### 날씨 데이터 조회 상태

날씨 데이터는 다음 순서로 조회한다.

1. 저장된 최근 GPS가 유효하면 새 GPS 측정을 기다리지 않고 사용한다.
2. 운영 서버의 경량 Main API와 Today/Weekly API를 병렬 호출한다.
   - Main 핵심 날씨가 먼저 도착하면 상단 날씨 카드를 즉시 표시한다.
   - Check List·타임라인·Today 상세·Week는 자료가 도착할 때마다 이어서 갱신한다.
3. 연결 오류나 선택 지역의 중앙 수집 자료 미준비가 계속되면 안내 팝업을 표시한다.
   - 동작: `운영 서버 다시 시도`
   - `Check List`와 `간단한 타임라인`은 운영 서버가 준비한 자료가 필요하다고 안내한다.
4. 앱은 기상청 API를 직접 호출하거나 고정 날씨로 대체하지 않는다.

| 조회 상태 | Main | Today | Detail | Week | Setting |
| --- | --- | --- | --- | --- | --- |
| 운영 서버 연결 | 전체 기능 | 전체 기능 | 전체 기능 | 전체 기능 | 접근 가능 |
| 서버 자료 준비 중·조회 실패 | 상태 안내 | 상태 안내 | 상태 안내 | 상태 안내 | 항상 접근 가능 |

### 공통 새로고침

- 모든 탭 헤더에서 새로고침 버튼을 제거했다.
- Main, Today, Detail, Week, Setting과 날씨 미지원 상태 화면은 모두 아래로 당겨서 새로고침할 수 있다.
- 새로고침 때도 운영 서버를 먼저 조회하며 실패하면 동일한 선택 팝업을 표시한다.

### 공통 날씨 아이콘 규칙

날씨 상태 아이콘은 Main 현재 날씨, Today 현재/시간별 날씨, Week 날짜별 날씨에 같은 규칙으로 적용한다. **우산 아이콘은 날씨 상태가 아니라 준비물·알림 항목에서만 사용한다.**

- 해+구름, 겹친 구름, 구름+비/눈처럼 여러 요소를 조합한 아이콘은 상태별 독립 위젯으로 캡슐화한다.
- 조합 위젯은 부모 영역이 더 커도 지정한 정사각 크기를 유지해 구름과 강수 요소가 서로 떨어지지 않도록 한다.

| 서버 상태 | 아이콘 표현 | 구분 원칙 |
| --- | --- | --- |
| 맑음 | 해 | 구름 없음 |
| 구름 많음 | 해 + 구름 | 해가 일부 보이는 다소 흐린 상태 |
| 흐림 | 겹친 구름 | 하늘을 구름이 덮은 상태 |
| 빗방울·이슬비·가랑비·약한 비 | 구름 + 빗방울 1개 | 약한 강수 형태 |
| 비 | 구름 + 빗방울 2개 | 일반적인 비 |
| 소나기 | 구름 + 빗방울 3개 | 비와 별도 형태로 구분 |
| 눈날림 | 윤곽 구름 + 작은 눈송이 | 약한 눈날림 |
| 눈 | 구름 + 눈송이 | 일반적인 눈 |
| 빗방울/눈날림 | 윤곽 구름 + 작은 빗방울 + 작은 눈송이 | 약한 혼합 강수 |
| 비/눈 | 채운 구름 + 빗방울 + 눈송이 | 일반 혼합 강수 |
| 알 수 없음 | 물음표 | 미정의 상태를 맑음으로 오인하지 않음 |

## 2. Main 탭

### 목적

현재 예보 구역의 대표 실황과 오늘의 핵심 생활 정보를 한 화면에서 빠르게 확인하는 탭이다.

### 화면 구성 순서

1. **페이지 헤더**
   - 날짜와 요일
   - `{지역명} 오늘 날씨`
   - `화면을 아래로 당기면 최신 날씨 정보를 가져와요`
   - 별도 앞 아이콘과 새로고침 버튼 없음
2. **상단 날씨 카드**
   - 서버가 만든 이유 우선·조건부 행동 요약을 말줄임 없이 표시한다. 눈/비/대기질/자외선·더위/겉옷/바람/기본 안내의 기존 7개 장면 우선순위를 따른다.
   - 현재 시각에 유효한 시간대는 `지금`, 미래 시간대는 시각으로 표시한다. 다음 날 예보에는 `내일 오전 9시`처럼 상대 날짜를 붙이고 끝난 시간대는 선택하지 않는다.
   - 미래 시각이 시작되거나 현재 시간대가 끝나면 `briefExpiresAt`으로 해당 요약을 만료시킨다. 앱은 지난 행동 대신 새로고침 안내를 표시한다. 서버 원문 기온·관측·예보 시각은 바꾸지 않는다.
   - 자외선 근거 문장도 자료 조회일과 예보일이 다르면 날짜를 붙인다. 자세한 계약은 [Main 시간별 행동 안내](Main_시간별_행동_안내.md)를 참고한다.
   - 하늘 상태에 따른 배경 톤
   - 초단기실황 관측 시각·현재 기온과 현재 체감온도를 한 줄에 표시. 좁은 화면에서는 한 줄 전체를 비율에 맞춰 축소하고 줄바꿈하지 않음
   - 체감온도 아래에 `{하늘 상태} 체감 상 {감각} 느껴질 수 있어요.` 형식의 안내와 하늘 상태 아이콘 표시. 바로 위 지표에 있는 체감온도 숫자와 계산 근거는 반복하지 않음
   - 체감 안내는 13pt 글자로 표시하고 작은 화면에서도 말줄임 없이 자연스럽게 줄바꿈
   - 숫자는 기상청 계절별 체감온도 산식, 표현은 한국인 PT 감각 경계와 기상청 `33/35/38℃` 위험값을 함께 사용
   - `어제와 비교` 영역에서 선택 격자의 다음 시간 단기예보와 같은 시각의 어제 초단기실황 기온·체감온도 차이를 단위와 함께 표시
   - 오늘 예보시각과 어제 실황시각을 같이 표시하며, 비교값을 상단 현재 초단기실황으로 대체하지 않음
   - 어제와 오늘의 하늘 상태가 모두 있으면 `어제 맑음 · 오늘 구름 많음`처럼 함께 표시
   - 비교할 어제 실황을 받지 못했거나 운영 서버 미연결이면 비교 자료를 받을 수 있을 때 표시된다고 안내
   - 습도 / 풍속 / 자외선 지수 / 미세먼지
   - 미세먼지는 PM2.5를 우선 표시하고, 없으면 PM10으로 대체
   - 지표 수치는 안전(블루) / 주의(앰버) / 위험(레드) 색상으로 구분
3. **Check List 챙김카드**
   - 기존 Today의 실제 준비물 체크 카드를 상단 날씨 카드 바로 아래에 배치
   - 추천된 우산·양산·겉옷·마스크·물·선크림·폭설 대비 항목만 표시
   - 카드 탭으로 `챙길게요`와 `챙겼어요`를 전환하고 한국시간 날짜별 기기 저장을 유지
   - 정보 버튼을 누르면 Detail의 관련 생활 근거로 이동
   - 추천이 없으면 특별히 챙길 준비물이 없다는 빈 상태를 표시
4. **간단한 타임라인**
   - `03·06·09·12·15·18·21·24시` 8개 시점을 세로로 표시
   - 각 시점에 행동형 타이틀과 `예상기온 / 날씨`, 실제 강수·강설이 있을 때만 둘째 줄 예보를 표시
   - 시점별 준비물 선택 시 Detail의 관련 근거로 이동
   - 운영 서버 미연결 시 Check List와 타임라인을 각각 미지원 카드로 표시

### 레이아웃 규칙

- `CustomScrollView`, `SliverPadding`, `SliverList`로 상단 카드·Check List·타임라인을 자연 높이로 배치한다.
- 콘텐츠가 화면 높이를 넘으면 Main 전체를 아래 방향으로 스크롤할 수 있으며, 최상단에서는 당겨서 새로고침할 수 있다.
- 화면 너비가 380px 미만이면 compact 레이아웃을 사용한다.
  - 카드 간격과 내부 여백 축소
  - 일부 글자와 아이콘 크기 축소
- 상단 날씨 카드와 Check List·타임라인에 고정 높이 비율을 배정하지 않는다.

### 데이터 및 동작

- `TodayWeatherResponse`의 `region`, `brief`, `current`, `recommendations`, `timeline`을 사용한다.
- 첫 진입은 경량 Main 응답의 `brief`, `current`만으로 상단 카드를 먼저 표시하고, 전체 Today 응답이 오기 전까지 Check List와 타임라인 자리에 진행 상태를 표시한다.
- 상단 `TodayWeatherResponse.current`의 기온·습도·풍속은 선택 격자의 기상청 초단기실황을 사용하고, 체감온도도 같은 실황값으로 계산한다. 관측 시각과 `OBSERVATION` 역할을 표시한다. 하늘 상태는 단기예보, 자외선·대기질·시정은 각 별도 자료를 병합한다.
- 초단기실황이 없거나 현재보다 5분 넘게 미래이거나 2시간을 초과해 오래되면 단기예보 기온으로 대체하지 않고 현재 기온·체감온도·습도·풍속을 결측으로 표시한다.
- `comparison/yesterday`는 선택 격자의 현재 시각 이후 가장 가까운 단기예보와 그 예보시각에서 24시간 전의 초단기실황을 반환한다. 이 응답은 `어제와 비교` 카드 안에서만 사용한다.
- 비교 가능한 양쪽 값이 모두 있는 지표만 차이를 표시하며 기온·체감온도는 `°C`, 미세먼지는 `㎍/㎥` 단위를 사용한다.
- 운영 서버는 기상청 생활기상지수 V5의 자외선 예측과 에어코리아 실시간 PM10·PM2.5를 `current`에 병합한다.
- 대기질은 전국 GPS 또는 예보 격자의 대표 지점을 기준으로 가까운 측정소를 선택한다. 측정소별 관측 캐시를 사용하며, Today 지표 상세에서 실제 측정소·관측 시각을 확인한다. [전국 조회 계약](./대기질_전국_조회.md)
- `environmentalSources`로 자외선·대기질의 실시간 조회/캐시/stale/미지원 상태를 구분하며, 환경 Provider 실패는 단기예보 응답 전체를 실패시키지 않는다.
- 생활 문구 응답의 `score`를 중요도 색상 기준으로 사용하며, 구버전 서버에서 점수가 없으면 0점으로 처리한다.
- PM2.5 나쁨 시작값은 화면 색상·서버 마스크 추천·브리핑 모두 36㎍/㎥, PM10은 81㎍/㎥로 통일한다. PM 수치가 낮아도 에어코리아 통합등급이 `나쁨` 이상이면 마스크를 추천한다.
- 강수 장면과 행동 판단은 Detail 강조 기준과 같은 강수확률 40%부터 적용한다.
- 날씨 상태 문자열로 Main의 mood를 결정한다.
- Setting에서 확인한 GPS 위치의 기상청 격자 또는 저장된 수동 지역 격자로 조회한다. 위치 확인 실패나 수동 지역 미선택 시 수원 등 다른 지역으로 대체하지 않는다.

### 지표 색상 기준

| 지표 | 양호(블루) | 주의(앰버) | 위험(레드) |
| --- | --- | --- | --- |
| 습도 | 35% 초과, 70% 미만 | 35% 이하 또는 70~79% | 80% 이상 |
| 풍속 | 6m/s 미만 | 6~8.9m/s | 9m/s 이상 |
| 자외선 | 6 미만 | 6~7 | 8 이상 |
| PM2.5 | 35㎍/㎥ 이하 | 36~75㎍/㎥ | 76㎍/㎥ 이상 |
| PM10 대체값 | 80㎍/㎥ 이하 | 81~150㎍/㎥ | 151㎍/㎥ 이상 |

미세먼지 구간은 [에어코리아 대기환경정보 등급](https://www.airkorea.or.kr/web/main)을 사용한다. 값이 없으면 `--`와 중립 색상을 표시한다.

### 체감온도 표현 기준

| 체감값 | 표현 |
| --- | --- |
| 38℃ 이상 | 위험한 더위 |
| 35~37.9℃ | 더위 경계 |
| 33~34.9℃ | 더위 주의 |
| 28~32.9℃ | 더움 |
| 20~27.9℃ | 조금 더움 |
| 10~19.9℃ | 선선한 편 |
| 0~9.9℃ | 쌀쌀한 편 |
| 0℃ 미만 | 추운 날씨 |

33/35/38℃는 공식 특보의 일 최고값·지속일수 판정 자체가 아니라 현재 한 시점의 행동 신호다. 연구 근거, 산식, 적용 한계와 한국인 대상 추가 연구는 [체감온도 계산·표현 기준](./체감온도_표현_기준.md)에 정리한다.

## 3. Today 탭

### 목적

현재 날씨 수치와 오늘 시간별 예보를 자세히 확인하는 탭이다.

### 화면 구성 순서

1. **페이지 헤더**
   - `TODAY`
   - `오늘 날씨를 자세히 확인해요`
   - `현재 상태와 시간별 예보를 함께 보여드려요`
2. **현재 상세 날씨 카드**
   - 예보 대상 시각과 현재 기온, 하늘 상태를 먼저 표시
   - `체감 → 습도 → 풍속 → 자외선 → 초미세먼지(PM2.5) → 미세먼지(PM10)` 순서를 유지
   - 여섯 지표는 화면 너비와 관계없이 항목당 한 행을 사용
   - 각 행의 정보 버튼을 누르면 같은 행 아래에서 먼저 현재 값의 수준을 굵은 제목으로 표시하고, 이어서 출처·공식 기준·해석 방법·한계를 설명함. 체감온도 제목은 `체감온도는 … 수준이에요`로 표시함
   - 미세먼지는 측정소 이름과 관측 시각만 밝히며 사용자 위치 직접 측정 여부를 반복 안내하지 않음
   - 결측값은 `자료 없음`으로 유지하고 실제 0과 구분하며, PM2.5와 PM10은 서로 대체하지 않음
3. **시간별 예보**
   - 한국시간 오늘에 해당하는 시각별 기온·체감·바람·자외선·대기질과 강수 구간을 표시
   - 각 행 시각 옆의 `정시 예보` 라벨 대신 `예상 기온`, `예상 체감`을 바로 표시
   - 강수량·강설량의 `미만`·`범위`·`이상` 원문 의미를 단일 수치로 바꾸지 않음
   - 다음 날 기온을 오늘 목록에 섞지 않되 다음 날 00시 강수는 오늘 23~24시 구간으로 유지

### 데이터 및 동작

- `TodayWeatherResponse.current`, `hourly`를 사용하며 운영 서버가 중앙 수집한 자료만 표시한다.
- 시간별 숫자 결측·비정상 형식·비유한 값을 0으로 대체하지 않고, 시간별 자료가 비면 빈 안내만 표시한다.
- Today는 준비물 체크 상태를 변경하지 않는다. 실제 챙김 여부 확인은 Main의 Check List가 담당한다.
- 전체 화면은 세로 스크롤이며 당겨서 새로고침할 수 있다.

### 현재 한계 및 확인 포인트

- [x] 현재 상세 날씨 카드를 Today 최상단으로 이동
- [x] 여섯 지표를 항목당 한 행으로 배치하고 펼침형 상세 설명 유지
- [x] Detail의 시간별 예보를 Today로 이동
- [x] 시간별 결측·강수 구간·범위값과 좁은 화면·큰 글씨 회귀 검증

## 4. Detail 탭

### 목적

오늘의 생활행동을 체크할 일과 그 판단 근거·자료가 연결된 형태로 확인하는 탭이다.

### 화면 구성 순서

1. **페이지 헤더**
   - `DETAIL`
   - `날씨 자세히보기`
   - `상세한 날씨 정보를 확인해요`
2. **Check List + 근거와 자료**
   - 서버 `lifestyleMessages`의 생활항목 하나를 카드 하나로 구성하고 전체 항목을 표시
   - 같은 카드 안에서 `체크할 일`, `판단 근거`, `계산 근거`, `사용한 자료`, `자료 상태`를 역할별로 구분
   - `판단 근거`의 앱 내부 출처는 제품명 대신 `앱 자체 분석`으로 표시
   - 공식 자료에 제공자와 유효기간이 있으면 사람이 읽는 한국시간 메타정보로 함께 표시
   - 선택·알림과 연결된 근거는 먼저 배치하고 첫 일치 항목을 강조. 그 외 순서는 서버 응답 순서를 유지
   - 요청한 근거가 최신 자료에 없으면 `선택한 항목의 근거가 현재 자료에 없어요` 또는 `이 알림과 연결된 근거가 현재 자료에 없어요`로 구분. 다른 항목을 대신 강조하거나 위험이 해소됐다고 판단하지 않음
   - `itemTitle`로 생활항목과 연결되는 `dataStatusMessages`만 같은 항목 카드에 배치하고, 연결되지 않는 상태를 다른 항목에 임의 배정하지 않음
   - 생활항목이 없으면 체크 항목과 근거가 없다는 빈 상태를 표시하고, 운영 서버 미연결 시 미지원 카드로 교체

### 데이터 및 동작

- `TodayWeatherResponse.lifestyleMessages`, `dataStatusMessages`를 사용한다. 근거 목록은 준비물 추천 목록과 별개다.
- 서버가 한 `LifestyleMessage` 안에 제공한 행동과 근거만 같은 세트로 묶는다. 서로 다른 생활항목이나 제목이 없는 자료 상태를 임의로 결합하지 않는다.
- Main 타임라인과 Detail의 생활 판단·공식 근거, 비가 그치는 시간, 빨래 마감, 우산·폭설 알림도 강수 구간을 사용한다. 이미 종료된 강수는 미래 행동 판단에서 제외하며 원본 시간별 예보는 유지한다. 산책은 해당 정시부터의 강수 구간과 기온·바람을 맞춰 비교하고, 대응 자료가 없으면 추천하지 않는다.
- [기상청 시간 안내](https://www.kma.go.kr/w/iframe/dfs.do)의 강수량·강수확률·날씨는 이전 1시간, 기온·바람은 정시 기준이다. 1시간 신적설(SNO)은 [기상청 API허브 요소 정의](https://apihub.kma.go.kr/apiList.do?seqApi=10)를 함께 참고한다.
- 서버 응답의 시간별 숫자 결측·비정상 형식·비유한 값은 0으로 대체하지 않는다. 명시된 `false`와 알 수 없는 눈 예상 상태도 구분한다.
- `forecastAt`/이전 `observedAt`에 시간대가 있으면 한국시간으로 변환해 날짜 경계를 판별한다. 시간대 없는 기상청 날짜·시각은 한국시간으로 읽는다.
- 직접 조회에서도 TMP가 빠졌더라도 다른 시간별 자료가 있는 슬롯은 유지한다. TMN/TMX 전용 슬롯은 제외하며, 기온 결측은 일 최저·최고 계산에서 제외한다.
- 전체 화면은 세로 스크롤이며 당겨서 새로고침할 수 있다.
- Main 준비물과 타임라인의 정보 버튼으로 이동하면 관련 근거를 우선 배치하고 자동 스크롤하며 `선택한 항목의 근거`로 강조한다.

### 현재 한계 및 확인 포인트

- [x] Today의 Check List + 근거와 자료를 Detail로 이동
- [x] 생활항목별 체크할 일과 근거·자료를 한 세트로 구성
- [x] 공통 자료상태를 특정 생활항목과 분리하고 전체 원문 표시
- [x] 빈 항목·선택 근거 부재·운영 서버 미연결 상태 구분
- [x] Main에서 선택한 준비물을 관련 Detail 근거에 연결
- [x] 알림·선택 항목을 첫 카드로 배치하고 자동 스크롤·강조 유지

## 5. Week 탭

### 목적

현재 한국 날짜가 속한 주의 일요일부터 토요일까지 날씨와 대표 준비물을 확인하는 탭이다.

### 화면 구성 순서

1. **페이지 헤더**
   - `WEEK`
   - `이번 주 날씨` (하단 탐색 이름 `Week` 유지)
   - 현재 주의 달력 범위와 `일~토`: 예) `9월 6일~9월 12일 · 일~토`
   - 연도가 바뀌는 주는 양쪽 연도를 표시한다.
2. **제공된 주간 자료 요약**
   - `비/눈 예보·관측`: 미래 예보와 지난 날의 실제 관측을 구분해 확인한 강수 일수
   - `확인된 최고기온`: 유효한 최고값만 비교하고 `최고기온 확인 N/M일 중 최고`로 집계 범위를 표시
   - `준비물 추천`: 표시할 활성 추천이 있는 날의 수 또는 `미지원`
   - 각 지표의 자료 확보 일수를 따로 표시한다. `강수 여부 확인 N/M일`, `최고기온 확인 N/M일 중 최고`, `준비물 판단 N/M일`처럼 분자와 분모의 의미를 함께 표시하고, 전부 결측이면 `자료 없음`으로 안내한다.
   - 화면 폭·글씨 크기에 따라 지표를 1~3열로 배치한다.
3. **일~토 카드 목록**
   - 현재 주의 일요일부터 토요일까지 정확히 7개 슬롯을 달력 순서로 표시
   - 월·일·요일: 예) `9월 10일 (목)`
   - 한국시간 실제 날짜에는 카드 우측 끝에 `오늘`, 지난 날짜에는 같은 위치에 `지난 날짜`를 표시
   - `단기예보`, `중기예보`, `실제 관측`, `저장된 예보` 출처 배지. 지난 날짜의 `지난 날짜`와 `실제 관측`은 검은색 계열로 표시
   - 날씨 아이콘과 상태
   - 대표 준비물 최대 3개
   - 빈 추천 목록은 `표시할 준비물 추천 없음`, 추천 미수신·잘못된 목록은 `준비물 추천 자료 없음`으로 구분한다. 준비물이 필요 없다고 단정하지 않는다.
   - 운영 서버 미연결 시 준비물 미지원 안내만 표시하고 남아 있는 추천 배지는 숨긴다.
   - `최저 N℃ · 최고 N℃`를 별도 줄에 표시한다. 한쪽만 없으면 해당 항목만 `자료 없음`으로 표시한다.
   - 시간대별 예보에서 계산한 값은 `시간별 최저/최고`로 구분하고 받은 시간대만 비교한 값임을 안내한다.
   - 기온 아래 `강수 예보`에 대상 시간 구간, 시간대별 강수확률 중 최고값, 예상 누적 강수량을 표시한다. 확률 최고값은 하루 전체 강수확률이 아니며, 누적량은 표시 구간의 예보를 앱에서 합산한 값임을 안내한다.
   - 예: `14~24시 예보 기준 · 하루 중 일부 시간`, `시간대별 강수확률 중 최고 70%`, `예상 누적 강수량 2mm 이상 3mm 미만`.
   - 0%·0mm만 있는 구간은 기본 강수 안내를 생략한다. 확률이 양수라도 누적량 0mm 문구는 기본 노출하지 않는다. 자료 없음·오류는 0과 구분한다.

### 데이터 및 동작

- `WeeklyWeatherResponse.days`에서 현재 주에 속하고 날짜가 유효한 항목만 정확한 요일 슬롯에 연결한다.
- 서버는 단기예보를 우선하고 4~10일 뒤의 빈 날짜는 중기 기온·육상예보로 채운다. 겹친 날짜의 단기예보가 공식 일 최저·최고 없이 일부 시간값만 가진 경우에는 완전한 중기 일 예보를 사용한다.
- 지난 날짜는 기상청 지상·AWS 일통계에서 예보격자 대표점에 가장 가까운 관측소의 실제 최저·최고기온·일강수량·적설을 조회한다. 예보가 아니므로 `실제 관측`로 표시하고 지난 날의 준비물은 추천하지 않는다.
- 실제 일관측을 받지 못하면 D1에 남은 해당 날의 `저장된 예보`를 보조로 사용한다. 관측과 저장 예보가 모두 없을 때만 결측으로 남겨두며 추정하지 않는다.
- 단기와 중기 Provider는 독립적으로 처리한다. 한쪽이 실패해도 다른 쪽 자료를 표시하고, 두 예보가 모두 없으면 해당 미래 날짜를 정상 날씨로 추정하지 않는다.
- 서버는 기존 요일 `date`를 유지하고 `forecastDate: YYYY-MM-DD`를 추가로 제공한다. 직접 기상청 조회도 같은 달력 날짜를 유지한다. 구버전 서버의 요일만으로 달력 날짜를 추정하지 않는다.
- 날짜가 없거나 유효하지 않은 서버 항목은 임의 요일에 끼워 넣지 않는다. 같은 날짜가 중복돼도 하나를 임의 선택하지 않는다.
- 서버의 날짜별 준비물은 해당 날짜의 시간대별 기상청 체감온도로 계산한다. 시간대별 체감값이 없을 때 일 최고기온을 체감온도로 대입하지 않는다.
- 날씨·기온의 결측을 맑음·0으로 보충하지 않는다. 알 수 없는 날씨 문구, 빈 문자열, 비유한 수, 뒤집힌 최저·최고는 유효한 값으로 사용하지 않는다. 실제 0℃·영하기온은 보존한다.
- 지난 날짜는 카드 전체에 투명도나 색상 필터 레이어를 씌우지 않고 카드·글자·아이콘 색을 직접 회색으로 지정해 스크롤 화면의 합성 오류를 피한다.
- 비/눈 집계는 지원하는 기상청 현상명으로만 판별한다. 부분 자료라도 확인된 강수는 포함하지만, 일부 시간대 또는 상태 메타데이터가 빠진 맑음·흐림 자료를 무강수로 확정하지 않는다. `weatherDataComplete`는 받은 첫~마지막 슬롯 사이의 자료 완전성이지 하루 24시간 전체를 보장하는 값이 아니다.
- 서버와 직접 조회가 `weatherDataComplete`, `minTemperatureSource/maxTemperatureSource` (`DAILY`/`HOURLY`)를 전달한다. 서버는 기온만 빠진 시간대도 보존하고, 빠진 PTY·SKY와 공백 숫자를 무강수·맑음·0으로 만들지 않는다. 기존 날짜·요일·기온 응답 형식은 유지한다.
- 날짜별 `precipitationDetail`에 1시간 예보(`HOURLY`)와 연장 예보(`EXTENDED`)를 구분한다. `hours`는 `forecastAt`(구간 종료), `probability`, 원문 `amountText`를 전달한다. Today의 48개 제한 전 전체 자료를 사용하며 기존 API 필드는 유지한다.
- 강수량·강수확률의 1시간 자료는 표기 시각의 이전 1시간에 해당한다. 자정 자료는 전날 23~24시로 배정하고, 날짜·중복·시간 오류가 있으면 합산하지 않는다. [기상청 예보 요소별 시간 안내](https://www.kma.go.kr/w/iframe/dfs.do).
- 받은 첫~마지막 구간만 합산하며, 중간 시간이나 강수량이 빠지면 부분합을 전체 예상량으로 표시하지 않는다. 24시간 미만은 `하루 중 일부 시간`을 명시한다. 확률 자료의 완전성은 강수량과 독립적으로 계산한다.
- 합산은 `미만`의 열린 상한·`이상`의 열린 범위·수치 범위를 유지한다. 예: `1mm 미만 + 1mm 미만 → 2mm 미만`, `5mm + 1mm 미만 → 5mm 이상 6mm 미만`. 음수·오류 문자열·역전 범위·단위 없는 양수 코드를 mm로 읽지 않는다. 모든 날짜 카드에 같은 앱 계산을 적용한다.
- 오전~14시 발표의 글피, 17시 이후 발표의 그글피는 연장 예보로 구분한다. 확인된 시간대의 확률 최고값만 표시하고, 정성 단계인 강수량은 mm 합계를 계산하지 않는다고 안내한다. [기상자료개방포털 단기예보 설명](https://data.kma.go.kr/data/rmt/rmtList.do?code=420&pgmNo=572).
- 날짜 미확인 및 중복 날짜는 요약에서 제외하고 제외 내역을 알린다. 누락 날짜·중복 값 중 하나를 임의로 골라 집계하지 않는다.
- 준비물은 `recommended: true`인 알려진 종류만 중복을 제거해 표시한다. 비활성 추천을 제거한 뒤 최대 3개를 선택한다. 잘못된 종류를 우산으로 대체하지 않으며 일부 추천이 손상돼도 유효한 추천은 유지하고 상태를 안내한다.
- `forecastDate`와 한국시간 오늘 날짜를 비교한다. 한국시간 자정 및 앱 복귀 시 다시 판단하며, 기기 시간대·목록 순서에 의존하지 않는다. 체크리스트와 한국시간 날짜 계산 함수를 공유한다.
- 단기·중기예보, 실제 관측, 저장 예보에 모두 없는 슬롯은 날짜 자체는 유지하되 날씨를 만들지 않는다.
- 서버는 02·05·08·11·14시 발표분의 오늘~글피 최대 4개 날짜와 17·20·23시 발표분의 오늘~그글피 최대 5개 날짜를 모두 보존한다. 기존 4개 절단으로 저녁 발표분의 다섯 번째 날짜가 버려지지 않게 한다.
- 빈 목록에도 일~토 7개 날짜 자리를 표시하지만 0일 요약·맑음·준비물 없음으로 해석하지 않는다.
- 운영 서버 자료를 받지 못하면 날짜별 날씨를 임의로 대체하지 않고 조회 상태 안내를 표시한다.
- 전체 화면은 세로 스크롤이며 당겨서 새로고침할 수 있다.

## 6. Setting 탭

### 목적

지역과 알림 종류를 설정하고 저장·기기 상태 및 데이터·권한 안내를 확인하는 탭이다.

### 화면 구성 순서

1. **페이지 헤더**
   - `SETTING`
   - `설정`
   - `나의 위치와 필요한 알람을 설정할 수 있어요.`
   - 설정 아이콘 표시
2. **지역 선택**
   - 현재 위치 사용
   - 지역 직접 선택
   - GPS 확인 결과와 서버 응답의 지역명을 표시한다. 위치 확인 전에는 현재 위치를 사용 중이라고 안내하지 않는다.
   - 권한 거부·기기 위치 기능 꺼짐·시간 초과·위치 확인 실패·서비스 범위 밖을 구분한다.
   - `위치 권한 허용하고 확인` / `위치 다시 확인`, 필요한 경우 `앱 권한 설정 열기` / `기기 위치 설정 열기` 버튼을 제공한다.
   - 확인 시각은 한국시간 월·일·시·분으로 표시한다. 대략적인 위치는 지역 예보만 사용하고 정밀 강수·도로 분석에는 쓰지 않는다고 알린다.
   - 처음 `지역 직접 선택`을 누르면 전국 목록을 연다. 시·도 → 시·군·구 → 읍·면·동 순서로 탐색하거나 여러 지역명으로 검색한다. 동명 지역은 전체 상위 지역명을 함께 표시한다.
   - 지역과 대표 예보 지점 기준임을 확인한 뒤 `이 지역 사용`을 눌러야 설정이 바뀐다. 취소·뒤로가기는 기존 모드와 지역을 유지한다. 수동 모드의 `지역 선택·변경`으로 다시 선택한다.
   - 시·도/시·군·구 대표 지점도 선택할 수 있으나 그 행정구역 전체의 날씨를 보장하지 않는다. 수동 지역 미선택·확인 실패에는 다시 선택하도록 안내하고 다른 지역으로 대체하지 않는다.
3. **알림**
   - 최상위 `알림` 메뉴에서 알림 시간과 받을 날씨·생활 알림을 한 화면에 설정한다.
4. **날씨 알림**
   - 끄면 하위 준비물/주의 알림 스위치가 비활성화된다.
   - 알림 시간 영역도 흐리게 표시되고 입력을 받지 않는다.
5. **알림 시간**
   - 기본값 `07:00`
   - 시간 선택 대화상자로 변경하고 로컬·서버에 저장한다.
   - 준비물 요약에만 적용됨을 명시하고 `설정 시각`으로 표시한다. 실제 서버 확인 시각은 다음 10분 경계로 안내한다(07:35 → 07:40, 23:55 → 다음 날 00:00). 저장값은 그대로 보존하고 도착 시각을 보장하지 않는다.
   - 준비물 요약을 껐으면 켜야 적용된다고 안내한다.
6. **챙겨요 알림**
   - 우산
   - 양산
   - 겉옷
   - 마스크
   - 물
   - 선크림
   - 준비물 요약에 포함할 항목을 선택한다. 우산 스위치는 현재 비 안내에도 함께 적용됨을 명시한다.
   - 현재 서버의 준비물 추천 6종과 일치하므로 연결되지 않은 스위치는 추가하지 않음
   - 우비·장화·장갑·모자는 향후 서버 추천 타입과 판단 기준이 추가될 때 검토
7. **기상·생활 알림**
   - `발효된 공식 정보와 생활 준비 알림을 관리해요`
   - 호우특보 안내: 발효 상태 진입·단계 변경·해제
   - 대설·많은 눈 안내: 발효 특보와 예보 기반 많은 눈 대비 별도 알림
   - 폭염특보 안내: 발효 상태 진입·단계 변경·해제
   - 한파특보 안내: 발효 상태 진입·단계 변경·해제
   - 현재 비 안내: 관측분석·레이더가 일치한 현재 비이며 우산 켜짐·등록된 정밀 위치 필요. 소나기 예보 알림으로 설명하지 않는다.
   - 준비물 요약 알림: 추천할 준비물이 있을 때 설정 시간에 하루 한 번 최대 3개. 일반 오늘 날씨 예보가 아니다.
   - 블랙아이스·도로통제·그 밖의 공식 특보는 개별 스위치 없이 전체 알림 설정을 따른다고 안내한다.
8. **저장·기기 알림 상태**
   - 확인 중 / 저장 중 / 기기 저장 실패 / 기기 저장 완료·서버 반영 미확인 / 양쪽 저장 완료를 구분한다.
   - 실패 시 `설정 저장 다시 시도`로 현재 선택된 최신 설정을 재전송한다. 서버 반영 미확인에는 이전 설정으로 알림이 발송될 수 있다고 알린다.
   - 기기 알림 권한 확인 중 / 미요청 / 미허용 / 영구 차단 / 허용 / 조용한 알림만 허용 / 확인 실패를 구분한다.
   - `알림 권한 요청`, `권한 다시 확인`, `기기 앱 설정 열기`를 제공한다. 영구 차단이면 요청 대신 기기 앱 설정을 안내한다.
   - 앱 전체 알림 스위치와 기기 권한은 별개다. 전체 알림을 껐어도 OS 권한을 허용으로 표시할 수 있으며, 서버 반영 전 또는 이미 처리 중인 알림은 도착할 수 있다고 안내한다.
   - 서버 저장/권한 허용을 실제 수신 성공으로 표시하지 않는다. 개별 알림 종류·소리·집중 모드는 이 상태로 판별하지 않는다.
9. **데이터·권한 안내**
   - 읽기 어려운 하단 출처 문구를 카드로 교체하고 데이터 출처·위치 권한·알림 권한·저장/전송 정보 화면으로 연결한다. 권한 제어 카드 옆에도 설명 바로가기를 둔다.
   - 예보·자외선·특보 외에 관측분석/레이더·오존·도로 결빙 가능정보·ITS 통제를 포함한다. 공식 기관 링크를 외부 브라우저로 열고 실패 시 주소 복사를 제공한다.
   - 위치 미확인과 서버 등록 정보 삭제, 앱 알림 끄기와 기기 권한을 구분한다. 기능 설명을 법적 개인정보처리방침으로 표시하지 않는다.

### 데이터 및 동작

- 모든 초기 스위치는 켜짐 상태이고 위치 모드는 GPS, 알림 시간은 07:00이다.
- 전체 알림을 끄면 알림 시간과 모든 하위 스위치는 비활성화되지만 각 하위 값은 보존된다.
- 설정은 Home에 전달되어 로컬 저장과 서버 동기화 큐를 통해 저장된다. 시작 시 저장된 설정과 설치 ID를 복구한다. 서버 저장 지연·실패는 로컬 GPS 확인을 막지 않는다.
- 큐는 요청 순서를 보존하되 최신 변경 결과만 상태로 표시한다. 기기 저장의 실패 반환값도 처리한다. 서버 저장 실패를 숨기지 않고 수동 재시도·다음 시작·다음 변경 때 다시 동기화한다. 날씨 조회나 오류 대화상자가 설정 저장 큐를 막지 않는다.
- 알림 설정 API의 strict 스키마에 맞춰 전체 알림·시간·6종 준비물·6종 기상/날씨 토글의 14필드만 보낸다. 설치 ID는 URL 경로, 위치 모드와 격자는 별도의 설치 등록 API로 전달한다. 이전 앱은 로컬 설정 전체를 보내 HTTP 400을 받을 수 있었으며 이번에 바로잡았다.
- 알림 권한은 실행·새로고침·기기 설정 복귀 시 읽고, 사용자가 `알림 권한 요청`을 눌렀을 때만 요청한다. GPS 없이 수동 지역이거나 위치가 없어도 권한을 확인할 수 있다. 조회 중 복귀하면 다시 읽어 늦은 이전 결과를 사용하지 않는다.
- 권한 변경 뒤 유효한 지역이 있으면 FCM 설치 등록도 갱신한다. 등록 큐에서 최신 권한을 읽고 허용되지 않았으면 토큰을 null로 전송한다. 등록 요청 성공/토큰 발급/실제 푸시 수신 여부는 이번 상태 카드의 판정 범위가 아니다.
- 권한 의미는 설치된 `firebase_messaging 16.6.0`/플랫폼 인터페이스 `4.10.0`과 [Firebase Flutter 알림 권한 안내](https://firebase.google.com/docs/cloud-messaging/flutter/receive)를 확인했다. 설치 버전은 Android `deniedPermanently`도 반환한다. iOS의 거부는 별도 영구 차단 값이 아니므로 거부 상태에도 앱 설정 버튼을 제공한다.
- GPS는 앱 실행·백그라운드에서 복귀·당겨서 새로고침·명시적 재확인 시 읽는다. 실행·복귀·새로고침에서는 기존 권한만 확인하고, 권한 요청은 확인 버튼이나 GPS 모드 선택 때만 한다. 백그라운드 연속 추적은 하지 않는다.
- 위치 확인 시간 제한은 8초다. 측정 시각이 2분보다 오래되거나 1분 넘게 미래이면 현재 위치로 사용하지 않는다. 이 값은 앱의 위치 자료 신선도 기준이며 날씨 체감·정확도 기준이 아니다.
- 기기 정밀 위치 권한과 유효한 측정 정확도(0m 초과, 500m 이하)가 함께 확인될 때만 정밀 분석 좌표를 전송한다. 나머지는 대략적 위치로 지역 격자만 사용한다. 이는 500m 기상자료 정확도를 보장하는 값이 아니다.
- 정밀 GPS 좌표는 기기 운영체제의 역지오코딩에도 전달해 Main·Setting 지역명을 `서울 강남구 역삼동` 또는 `수원시 팔달구 인계동` 형태로 표시한다. 첫 주소가 시·구까지만 반환돼도 전체 주소 후보와 도로 주소를 계속 확인해 동·읍·면이 포함된 이름을 우선한다. 도 단위 이름은 상세 시·군이 있으면 생략하고 특별시·광역시는 짧게 표시한다. 운영체제가 어떤 후보에도 동·읍·면을 제공하지 않은 경우에만 확인된 시·구를 대체 표시한다.
- 대략적 위치는 동을 판별할 정밀도가 아니므로 역지오코딩하지 않는다. 역지오코딩이 실패하거나 유효한 행정구역 이름을 받지 못하면 `현재 위치`로 표시하며 서버가 반환한 `선택 지역` 같은 임시명은 GPS 화면에 노출하지 않는다. 역지오코딩 이름은 화면 표시용이며 로컬 저장이나 서버 등록 필드에 추가하지 않는다.
- 좌표는 현재 서버의 지원 범위(위도 30~44, 경도 120~134)에 맞춰 검사한다. 이 사각 범위가 대한민국 행정 경계 검증을 뜻하지는 않는다.
- 위치 모드/저장 지역이 바뀌면 이전 위치·날씨를 비우고 새 지역을 조회한다. 진행 중인 이전 위치/날씨 응답은 새 지역 화면에 적용하지 않는다. 동시 새로고침은 하나로 합친다.
- 위치 확인 실패 시 다른 지역으로 대체하지 않고 날씨를 비워 안내한다. 수동 모드는 유효한 저장 격자(`nx_ny`)가 있어야 조회한다.
- 확인한 위치는 FCM 설치 등록에도 반영한다. 토큰 갱신은 시작 당시 좌표가 아닌 최신 확인 대상을 사용하며 서버 등록 요청은 순서대로 처리한다. 대략적 위치/수동 모드에는 정밀 좌표를 보내지 않는다.
- 위치 확인 실패 시 이전 좌표를 토큰 갱신으로 재전송하지 않지만 서버의 마지막 등록 지역을 삭제하거나 알림을 중단하지는 않는다. 화면에 `알림은 서버에 마지막으로 등록된 지역 기준이에요`를 명시한다. 원시 위치를 새로 로컬 저장하거나 로그에 남기지 않는다.
- 근거: [Geolocator 권한·정확도·설정 API](https://pub.dev/packages/geolocator), [geocoding 패키지](https://pub.dev/packages/geocoding), [Android 대략적/정확한 위치 권한](https://developer.android.com/develop/sensors-and-location/location/permissions/runtime), [Android Geocoder](https://developer.android.com/reference/android/location/Geocoder), [Apple CLGeocoder](https://developer.apple.com/documentation/corelocation/clgeocoder).
- 전국 목록은 기상청 날씨누리의 2026-09-10 공개 목록 3,838행(시·도 16, 시·군·구 257, 하위 지역 3,565)을 앱에 포함한다. 목록 탐색·검색은 오프라인에서도 가능하고 실제 날씨 조회에는 인터넷이 필요하다. 자료 실패·재시도·빈 검색·출처/확인일을 안내한다.
- 기상청 코드가 중복된 하위 지역은 원본 이름·격자까지 포함한 `manualRegionKey`로 구분한다. 앱은 이 키와 기존 `currentRegion: nx_ny`를 로컬 저장한다. 서버 설치 등록에는 `nx/ny` 쿼리로 격자를 보내며 알림 설정 API에는 지역 정보나 키를 보내지 않는다. GPS로 전환해도 마지막 수동 지역은 보존한다.
- 저장된 키가 사라지거나 격자가 변경된 목록에서는 다시 선택하도록 한다. 키가 없는 구버전의 유효한 격자는 계속 사용할 수 있다. 선택한 이름은 기상자료의 반환 격자가 일치할 때만 Main·Today 등의 지역 표시에 적용한다. 다른 격자의 응답을 받은 경우 날씨를 표시하지 않는다. 공식 근거 문장의 원문 지역명을 임의 치환하지 않는다.
- 수동 지역 변경은 날씨 조회와 알림 설치 등록에 같은 격자를 적용하며 정밀 좌표를 보내지 않는다. 서버 등록 실패 시 이전 서버 지역이 남는 기존 한계는 유지된다. 전국 검색 결과는 화면에 보이는 행만 생성해 전체 지역을 한꺼번에 렌더링하지 않는다.
- 원본·갱신 절차·중복 코드 사례는 `weather_care_app/assets/data/README.md`, 갱신 스크립트는 `scripts/update_region_catalog.ps1`에 기록했다. 서버 코드·DB·배포 변경은 없다.
- 전체 스위치/API 필드/발송 경로 대조는 [알림 설정·발송 계약](알림_설정_발송_계약.md)에 정리했다. 화면 이름만 실제 동작에 맞추고 기존 API 필드·설정값·발송 조건은 변경하지 않았다.
