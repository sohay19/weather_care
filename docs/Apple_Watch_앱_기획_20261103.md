# 날씨챙겨 Apple Watch 앱 기획

작성일: 2026-11-03 · 상태: watchOS 앱·WidgetKit 구현, 전용 iPhone/Watch 시뮬레이터 연동 확인. 실제 실행 결과는 12절에 기록했다. 9~11절의 HTML 시안과 실제 실행 캡처는 구분한다.

## 1. 목표와 참고 자료

손목에서 현재 날씨를 확인하고, 외출 준비물을 체크하고, 가까운 시간의 예보와 생활 지표를 읽는다. 첫 버전은 iPhone 동반 앱으로 제안한다.

직접 참고한 원본은 `weather_care_app/store/screenshots/source-wear-20261103`의 `current.png`, `prep.png`, `timeline.png`, `life.png`다. 촬영 명세상 Galaxy Watch9의 438×438 이미지이며 시스템 시계를 숨긴 스토어용 캡처다. 아래 예시 수치는 실제 현재 날씨가 아니라 해당 캡처를 재구성한 예시다.

이어갈 요소:
- 검은 배경, 푸른 회색 카드(#253747 계열), 하늘색 보조 문구, 밝은 본문.
- 큰 현재 기온, 체감·최저/최고, 어제 기온·체감 비교.
- 준비물별 체크와 이유, 시간·날씨·기온·강수확률, 생활 지표의 2열 카드.

Apple Watch에 맞출 요소:
- 원형 화면의 넓은 상하 여백을 줄이고 모서리가 둥근 사각 안전 영역을 이용한다.
- 실제 앱에는 시스템 시계 영역을 확보한다. 참고 캡처의 시계 숨김은 제품 동작으로 옮기지 않는다.
- 하단 4개 탭 대신 세로 페이지와 시스템 페이지 표시기를 사용한다. 화면 순서는 현재 → 준비물 → 타임라인 → 기상·생활이다. 세 번째·네 번째 화면의 좌측 상단 탭 제목도 각각 ‘타임라인’, ‘기상·생활’로 표시한다.
- 날씨는 기존 앱의 컬러 날씨 아이콘 체계를 그대로 사용한다. UI 예시에도 기존 `docs/icon-previews/weather-color/overcast.png`, `rain.png` 원본을 삽입했다. 제품 구현 시 기존 `WeatherIconPainter`의 상태·색·도형을 재사용하며 SF Symbols로 대체하지 않는다. 시스템 표시 모드가 요구하면 기존 단색 날씨 아이콘 체계를 사용한다.
- 본문·날씨 수치는 기존 SUITE 글꼴을 사용한다. watchOS에서 앱 번들 폰트 등록과 SwiftUI 커스텀 폰트를 지원함을 확인했다. 시스템 시계는 OS 글꼴을 유지하고, SUITE가 포함하지 않은 언어·기호는 시스템 폰트로 대체한다. 상세 검증은 10절에 기록했다.

## 2. 첫 버전 범위

| 포함 | 후속 검토 |
|---|---|
| 4개 화면, 준비물 체크·상세, 시간별 예보, 생활 지표 상세 | 워치 독립 서버 조회·독립 GPS |
| iPhone 선택 지역의 날씨 수신, 로컬 캐시, 갱신 요청 | 워치 자체 지역 추가·정렬·삭제 |
| WidgetKit 스마트 스택 사각 위젯, 원형·사각 컴플리케이션 | 워치 별도 푸시 구독과 예약 |
| 미연결·갱신 지연·오래된 자료·자료 없음 처리 | 폰과 준비물 체크 상태의 양방향 동기화 |

지원 하한은 세로 페이지를 사용할 수 있는 watchOS 10 이상을 제안한다. 실제 출시 하한은 iOS 배포 대상·빌드 환경·지원 기기 범위를 확인해 확정한다.

## 3. 화면과 동작

### 현재

1. 시스템 시계와 페이지 제목.
2. 지역명: 기본적으로 iPhone에서 마지막으로 선택한 지역. 긴 이름은 행을 늘리거나 상세에서 전체 표시한다.
3. 날씨 아이콘과 현재 기온(예: 흐림, 13.5°).
4. 체감 10° · 최저 5° / 최고 17°.
5. 작은 비교 카드: 어제보다 1° 높아요 / 체감은 어제보다 1° 낮아요.
6. 날씨 기준 시각과 갱신 버튼. 현재 시계·수신 시각을 관측 기준 시각처럼 표시하지 않는다.

현재 화면은 기본 글자에서 한 화면으로 읽는다. 큰 글자에서는 세로 확장을 허용하며 기온·지역·기준 시각을 보존한다.

### 준비물

- 제목 ‘오늘의 준비물’을 중앙 정렬한다. ‘0/n 챙김’ 완료 개수 문구는 표시하지 않는다.
- 예시: 우산 / 두꺼운 겉옷 / 선크림.
- 행 본문은 이유 상세, 우측 체크는 챙김/해제다. 체크 때문에 상세가 열리지 않는다.
- 상세는 중앙 정렬한 준비물 이름 → 추천 이유 → 지역명 → 기준시각 → ‘목록으로’ 버튼 순서로 구성한다. 별도의 ‘챙겨요’ 강조 문구나 가짜 대표 수치를 넣지 않는다. 이유 안의 시간대·수치는 원문에 있는 경우만 표시한다.
- 체크는 워치 로컬에 저장한다. 키는 `지역키 + Asia/Seoul 날짜 + 준비물 종류`. 날짜·지역 전환 시 다른 체크를 불러오며 같은 날 같은 지역으로 돌아오면 유지한다.
- 추천 변경은 종류 키로 대응하고 추천에서 빠진 항목은 현재 목록에서 숨긴다. ‘준비물 없음’과 ‘자료 없음’은 구분한다.
- 항목 수가 늘면 스크롤한다. 큰 글자는 카드 높이를 늘려 수용한다.

### 시간별

- 타임라인 위에 ‘시간별 예보 · 강수확률’을 중앙 정렬한다.
- 시간 / 날씨 / 기온 / 강수확률을 같은 열에 맞춘다.
- 예시: 12시 비 15° 60%, 13시 흐림 16° 30%, 14시 흐림 17° 30%, 15시 흐림 17° 30%.
- 기본 화면은 가까운 3~4개 행을 표시하고 나머지는 스크롤한다. 기존 워치 계약에 맞춰 미래 최대 12개 슬롯을 목표로 한다.
- 날짜가 바뀌면 날짜 구분을 추가한다. 기온과 확률은 원본 단위·시각을 유지하고 결측을 0으로 채우지 않는다.
- UI 예시의 ‘다음 시간’은 스크롤 이후 구간을 살펴보는 대화용 조작이다.

### 생활

- 목록 위의 ‘기상·생활 지표’ 문구를 ‘항목을 눌러 내용 확인’으로 표시한다.
- 기본 2열 카드: 체감 10°, 습도 48.9%, 자외선 1.5, 바람 2.8m/s.
- 아래 구간에 대기질·대기정체·가시거리·꽃가루·강수량·적설량을 둔다. 원본 캡처에 보이는 대기질은 PM10 55, 대기정체는 보통이다.
- 각 카드를 누르면 중앙 정렬한 항목명 → 큰 값·단위 → 설명 → 지역명 → 해당 항목 기준시각 → ‘목록으로’ 버튼 순서로 표시한다. ‘대기질’과 ‘대기정체’를 같은 수치로 취급하지 않는다.
- 큰 글자에서는 1열로 전환한다. PM10/PM2.5를 작은 카드에 강제로 함께 넣지 않고 상세로 이어준다.
- 관측 강수량·적설량을 예보 확률·신적설과 구분한다. 계절 자료와 결측은 ‘자료 없음’으로 표시한다.

## 4. 진입·이동

- 앱 아이콘: 현재 화면으로 진입.
- 세로 스와이프 / Digital Crown: 4개 페이지 및 긴 목록 이동.
- 카드 본문: 한 단계 상세로 이동. 뒤로 가면 원래 페이지와 스크롤 위치 복원.
- 스마트 스택: 지역·기준 시각 / 날씨 아이콘·기온·체감 / 최저·최고의 세 줄. 탭하면 현재 화면으로 이동.
- 원형 컴플리케이션: 날씨 아이콘·기온, 탭하면 현재 화면.
- 사각 컴플리케이션: 지역·기온·유효한 한 줄 안내. 지원 페이스·표시 모드에 맞게 축약.

세로 페이지와 긴 콘텐츠의 Crown 전환은 SwiftUI 기본 동작을 이용한다. 타임라인·생활 같은 긴 화면은 뒤에 배치하고 고유 제스처를 겹쳐 구현하지 않는다. [Apple 세로 페이지 설계](https://developer.apple.com/documentation/watchos-apps/creating-an-intuitive-and-effective-ui-in-watchos-10)

## 5. 데이터 연결

기획 시작 당시에는 Wear OS Data Layer 경로와 iOS 홈 위젯만 있었다. 이후 iOS Runner에 WatchConnectivity 브리지와 watchOS 앱·WidgetKit 타깃을 추가했다. 서버 코드 입력 방식은 직전 작업에서 앱에서 제거됐으며 Apple Watch에도 코드 입력 화면을 만들지 않는다.

제안 구조:

`기존 서버 → Flutter 날씨 모델 → iOS 네이티브 브리지 → WatchConnectivity → watchOS 로컬 저장소 → 앱 / WidgetKit`

- Flutter와 기존 서버의 날씨·추천 판단을 재사용한다. 워치는 새로운 추천 임계값을 계산하지 않는다.
- 기존 `WatchSnapshot`의 `schemaVersion`, `revision`, `publishedAt`, `widget`, `details`, `cleared` 개념을 재사용하는 플랫폼 공통 계약을 먼저 확정한다. Android 구현을 그대로 iOS에서 실행하는 의미는 아니다.
- 최신 날씨 상태는 `updateApplicationContext`로 보낸다. 새 상태가 이전 대기 상태를 대체하므로 전체 스냅샷을 보낸다.
- 사용자의 갱신 요청은 세션 활성화·상대 도달 가능 여부를 확인한 뒤 `sendMessage`로 요청한다. 도달 불가이면 마지막 캐시를 유지하고 다시 시도할 안내를 표시한다.
- 연결 활성화, 페어링, 앱 설치 상태, Apple Watch 교체에 따른 세션 재활성화를 처리한다. 전송 콜백은 UI 스레드로 전달한다.
- 동일 지역의 이전 revision과 오래된 전송은 무시한다. 지역 전환·삭제를 표현할 상태 세대값과 삭제 표식도 계약에 포함해 지연 수신이 이전 지역을 되살리지 않게 한다.
- iPhone의 앱 그룹 저장소는 Apple Watch로 자동 복제되지 않는다. WatchConnectivity로 보낸 뒤 워치와 워치 WidgetKit 확장 사이의 로컬 앱 그룹에 따로 저장한다.
- 갱신 주기를 분 단위로 보장하지 않는다. OS가 백그라운드 전송·위젯 갱신 시점을 결정하며, 포그라운드 갱신은 가능한 경로에서 시도한다.

위 전송 특성은 [Apple WatchConnectivity](https://developer.apple.com/documentation/watchconnectivity/wcsession)와 [최신 상태 전송](https://developer.apple.com/documentation/watchconnectivity/wcsession/updateapplicationcontext(_:))에 따른다.

## 6. 상태·개인정보·알림

| 상태 | 표시와 동작 |
|---|---|
| 최초 수신 전 | ‘iPhone에서 날씨챙겨를 열어 주세요’, 기온·체크·생활값을 샘플로 대신하지 않음 |
| 연결 끊김, 유효한 캐시 있음 | 마지막 자료와 실제 기준 시각 유지, ‘iPhone 연결 시 갱신’ |
| 자료가 3시간 초과 | 기존 워치 정책과 맞춰 ‘오래된 자료’, 기온을 마지막 기록으로 구분, 추천·미래 예보·실행형 안내는 숨김 |
| 브리핑 유효기간만 만료 | 수치가 신선해도 해당 안내·준비물은 숨김. 다음 유효한 구간이 있으면 그 구간 적용 |
| 개별 값 결측 | ‘자료 없음’, 0·좋음·맑음으로 추정하지 않음 |
| 지역 삭제 / 데이터 삭제 | 전달받은 삭제 상태에 따라 앱·위젯 캐시와 해당 체크 제거. 오프라인에서는 즉시 삭제 전달을 보장할 수 없고 재연결 시 우선 반영 |

3시간은 기존 앱의 제품 정책을 재사용하는 제안이며 기상 자료의 일반적인 유효기간을 뜻하지 않는다. 미래 5분을 초과한 비정상 기준 시각도 기존 워치와 같이 무효 처리한다.

- v1은 iPhone 위치/지역 설정을 사용하므로 워치 독립 위치 권한을 요구하지 않는다.
- 기존 iPhone 알림의 Apple Watch 표시는 사용자의 시스템 알림 설정을 따른다. 워치에서 같은 정기 알림을 별도로 중복 예약하지 않는다.
- 워치 자체 APNs와 별도 알림 권한 요청은 후속 범위다. 설치만으로 푸시 표시가 보장된다고 안내하지 않는다.
- 정밀 좌표·API 비밀키·개인 식별자를 컴플리케이션에 담지 않는다. 비활성/잠금 시 민감 정보 가림은 실기기에서 검토한다.

## 7. 스마트 스택·컴플리케이션

- 스마트 스택 사각은 아래 세 줄로 고정한다. 앱 이름·준비물 문구 대신 날씨 수치를 표시하고, 탭하면 현재 화면으로 이동한다.
  1. 지역 `구로동`은 좌측 상단, 날씨 기준 시각 `10:48 기준`은 우측 상단에 배치한다. 중간점은 표시하지 않는다. 현재 시계나 수신 시각을 쓰지 않는다.
  2. `기존 날씨 아이콘 + 13.5° + 체감 10°` — 기온을 가장 크게 표시한다.
  3. `최저 5° / 최고 17°` — 해당 날짜의 최저·최고 기온.
- 긴 지역명은 수치 행을 밀지 않게 윗줄에서 우선 축약하고 전체 이름은 앱에서 확인한다. 미연결·오래된 자료에서는 세 줄의 정상 날씨 대신 상태 안내를 표시하며 결측값은 `—`로 표시한다. 위젯에서 준비물 체크는 제공하지 않는다.
- 원형: 날씨 아이콘과 현재 기온. 공간 부족 시 소수점을 반올림해 표시하되 본문 원값은 유지한다.
- 사각 컴플리케이션도 스마트 스택과 같은 지역/기준시각·기온/체감·최저/최고의 세 줄을 사용한다. 오래된 자료는 ‘날씨 다시 확인’으로 표시한다.
- full-color·tinted·accented 등 시스템이 적용하는 표시 형태에서 의미와 대비를 확인한다. 브랜드 카드 배경을 모든 페이스에서 강제하지 않는다.
- 캐시와 같은 revision을 사용하고, 유효기간/오래됨 경계에 대응하는 타임라인 항목을 계획한다. 실제 갱신은 시스템 예산에 따르므로 항상 새 데이터라고 표현하지 않는다.

[Apple 사각 위젯 규격](https://developer.apple.com/documentation/widgetkit/widgetfamily/accessoryrectangular)은 스마트 스택과 워치 페이스 컴플리케이션에 쓰인다. [원형 규격](https://developer.apple.com/documentation/widgetkit/widgetfamily/accessorycircular)은 원형 컴플리케이션에 사용한다.

## 10. SUITE 적용 가능 여부 확인 및 수정 시안

결론: 기존 SUITE를 watchOS 앱과 앱이 그리는 스마트 스택/컴플리케이션 텍스트에 번들 폰트로 적용할 수 있다. 실제 워치 화면의 크기·표시 모드 검증은 제품 타깃 구현 후 별도로 수행한다.

- [Apple 공식 문서](https://developer.apple.com/documentation/swiftui/applying-custom-fonts-to-text)는 watchOS를 포함한 타깃에 폰트 파일을 넣고 `UIAppFonts`로 등록해 사용할 수 있다고 명시한다. SwiftUI의 `Font.custom("SUITE-Regular", size: 14, relativeTo: .body)` 형태로 큰 글자 설정을 지원한다. 기존 iOS 위젯의 `fixedSize` 구현을 그대로 복사해 글자 크기를 고정하지 않는다.
- 현재 저장소의 `SUITE-Regular.ttf`, `SUITE-SemiBold.ttf`, `SUITE-ExtraBold.ttf`는 Version 2.040이며 PostScript 이름도 각각 `SUITE-Regular`, `SUITE-SemiBold`, `SUITE-ExtraBold`다. 기존 iOS 위젯의 폰트 등록·호출도 확인했다.
- 위 세 파일은 각각 한글 완성형 11,172자를 포함한다. 샘플의 한글·영문·숫자·도 기호·중간점·퍼센트·세제곱 기호를 확인했다. 그리스 문자 `μ`는 폰트에 없어 `μg/m³` 표시에서 시스템 폰트 대체가 필요하다. 모든 언어를 SUITE 하나로 지원한다고 가정하지 않는다.
- 로컬 macOS CoreText에서 세 원본 TTF의 등록과 PostScript 이름 일치, 샘플 문자 표시, `μ`의 시스템 폰트 대체를 확인했다. watchOS 26.4 SDK의 watchOS 10.0 simulator 대상에서 SwiftUI `Font.custom(..., relativeTo:)` 샘플의 타입 검사도 통과했다. 이것은 watchOS 실기기 렌더 검증이 아니다.
- 앱과 WidgetKit 확장 각각의 타깃에 폰트 리소스와 등록을 넣는다. Flutter의 pubspec 선언만으로 별도 네이티브 watchOS 번들에 포함되지 않는다. 앱·위젯 각각 실제 PostScript 이름과 표시를 검증한다.
- [SUITE 공식 라이선스](https://github.com/sun-typeface/SUITE/blob/main/LICENSE)는 SIL OFL 1.1이다. 제품에는 원본 TTF와 저작권·라이선스 고지를 함께 포함한다.
- 대화 시안에는 실제 로컬 SUITE에서 표시 문자만 추린 WOFF2를 삽입했다. 미리보기 전용 파생 파일은 이름을 WeatherCare Preview로 바꾸고 원 라이선스를 함께 포함했으며, 제품용 원본 폰트는 변경하지 않았다. 시스템 시계 글꼴은 유지했다.

검증 자료: [폰트·날씨 아이콘 원본 및 해시](design/apple-watch-20261103/font-assets-verification.json), [CoreText 등록·문자 대체 확인](design/apple-watch-20261103/coretext-font-verification.json).

## 11. 최신 Android 상세 화면 반영

확인 기준: 2026-11-03 `origin/master`의 `9ba5ff0`을 fast-forward pull했다. 참조는 Android 워치 앱 `WatchActivity.kt`의 공통 상세 UI와 `WatchSnapshot.kt`의 항목 설명, `wear_weather_details.dart`의 전달 필드, `store/screenshots/source-wear-20261103/prep-detail.png` 및 `life-detail.png`다. 두 상세 캡처는 로컬 Android 에뮬레이터에 시험 자료를 표시한 결과이며 실제 워치 연동 증거로 취급하지 않는다.

### 준비물 상세

- 상단 준비물 이름은 하늘색, 추천 이유는 밝은 본문으로 중앙 정렬한다.
- Android 우산 캡처와 같은 ‘오후 비에 대비해 우산을 챙겨요.’ 예시를 사용한다. ‘챙겨요’만 별도 값처럼 크게 강조하지 않는다.
- 설명 아래에 `서울 구로구 구로동`, 그 아래에 `10:48 기준`을 별도 줄로 표시한다. 이 시각은 기존 iOS 시안의 예시 스냅샷과 맞춘 값이며 Android 원본 캡처의 12:00을 실제 최신 자료로 옮긴 값이 아니다.
- 데이터는 준비물 label, `details.preparationReasons[type]`, 스냅샷 region, 날씨 기준시각을 사용한다. 현재 Android와 같이 준비물 상세용 수치가 없는 항목은 수치 영역을 생성하지 않는다.
- 하단 전체 폭 ‘목록으로’ 버튼으로 준비물 목록에 복귀한다. 목록 체크 상태와 원래 페이지를 보존한다. watchOS 시스템 뒤로 가기도 같은 복귀를 수행하도록 구현한다.

### 기상·생활 상세

- 항목명은 하늘색, 값·단위는 크게 밝은 색, 설명은 보통 크기로 중앙 정렬한다.
- 습도 예시는 기존 iOS 시안과 같은 `48.9%`를 유지하고 설명은 Android 문구 ‘현재 상대습도예요. 낮으면 보습 준비물을 챙겨요.’를 사용한다. Android 캡처의 시험값 `72%`를 기존 iOS 목록 값 대신 주입하지 않는다.
- 설명 아래에 지역명과 `metrics[].basis`를 각각 표시한다. 습도·기온 등의 관측 시각, 자외선·대기질·가시거리·적설의 개별 시각, 대기정체의 예측 시각을 구분한다. 같은 화면에 있다고 모든 항목의 기준시각을 현재 날씨 시각으로 통일하지 않는다.
- 원본 `metrics` 계약에 description이 없으면 기존 Android `METRIC_DESCRIPTIONS`와 같은 10종 설명을 iOS에도 둔다. 유효한 전달 description이 있으면 우선한다. 화면용 글자색·줄바꿈·단위만 iOS에서 조정하고 기상 수치와 의미는 바꾸지 않는다.
- 대기질의 PM10/PM2.5는 줄을 나눌 수 있다. 결측은 ‘자료 없음’, 제공 기간 외는 ‘기간 외’, 기준시각 미상은 ‘기준 시각 없음’으로 구분한다.
- ‘목록으로’ 버튼은 기상·생활의 원래 목록 구간으로 복귀한다.

### Apple Watch 적용과 검토 범위

## 12. 실제 watchOS 구현과 시뮬레이터 연결

`weather_care_app/ios/WeatherCareWatch`에 SwiftUI 앱, `WeatherCareWatchWidgets`에 WidgetKit 확장, `WatchShared`에 스냅샷·캐시·아이콘을 추가했다. 기존 날씨 PNG와 원본 SUITE Regular/ExtraBold를 앱과 위젯에 번들 등록하고 OFL 고지도 포함했다. WidgetKit의 이미지 아카이브 제한을 확인해 위젯용 날씨 PNG만 같은 원본에서 64px로 축소한 별도 자산을 사용한다. Xcode 프로젝트의 Runner에 워치 동반 앱을 포함했으며 서버 변경 없이 기존 Flutter 날씨 발행 경로를 재사용한다.

- 화면 순서와 좌측 상단 제목은 날씨챙겨 → 준비물 → 타임라인 → 기상·생활이다. 실제 watchOS 시스템 시계를 유지한다.
- 준비물 본문은 상세 진입, 우측 44×48pt 체크는 상태 변경이다. ‘오늘의 준비물’을 중앙 정렬하고 완료 개수는 표시하지 않는다. 체크는 지역·한국 날짜·종류별로 저장한다.
- 타임라인 상단의 ‘시간별 예보 · 강수확률’, 생활 목록의 ‘항목을 눌러 내용 확인’을 적용했다. 준비물/생활 상세에 설명·지역·기준시각·전체 폭 ‘목록으로’를 적용했고 생활 상세에만 큰 값을 표시한다.
- 스마트 스택/사각 컴플리케이션은 지역 좌측·기준시각 우측, 기존 아이콘+기온+체감, 최저/최고의 세 줄이다. 원형 컴플리케이션도 제공한다. 위젯은 워치 앱 그룹 캐시를 읽고 현재 화면 딥링크로 진입한다.
- iPhone은 최신 전체 상태를 application context와 도달 가능한 세션 메시지로 전달한다. 워치 새로고침은 Flutter의 기존 재조회 경로를 호출한다. 3시간 초과·미래 5분 초과 자료와 만료된 준비물, 삭제·이전 revision을 처리한다.

실행 환경은 iPhone 16 Pro/iOS 18.6과 Apple Watch Series 10 42mm/watchOS 11.5의 전용 페어다. 기존 사용자 시뮬레이터와 분리했으며, 사용자 요청 후에는 데스크톱/창 전환 없이 simctl과 XCTest로 조작했다. 권한을 부여하지 않고 앱의 실제 지역 선택 UI에서 서울특별시 구로구 구로1동을 선택했다. 시험 날씨를 주입하지 않았다.

실제 서버 날씨 `16.5°`, 체감 `13.8°`, 최저 `5°`/최고 `17°`를 워치에서 확인했다. 워치 새로고침 후 iPhone 송신 캐시와 워치 앱 그룹 수신 캐시의 revision `1793679982924`, 지역·기온·기준시각 `오후 1:26`이 일치했다. 선크림 체크, 상세 진입/목록 복귀, 체크 유지, 타임라인, 습도 `48.5%`와 개별 기준시각을 확인했다. 이 값은 촬영 시점의 자료다.

검증: Flutter 동반 앱/워치/WidgetKit 시뮬레이터 빌드 성공, Flutter 회귀 검사 101개·Swift 스냅샷 검사 5개 통과, 수정 Dart 파일 정적 분석 통과. 워치 앱 그룹 등록과 공유 캐시 저장을 확인했다. 스마트 스택 추가 화면에서 실제 자료의 세 줄 렌더를 확인하고 전용 워치 스택에 추가했다. 컴플리케이션의 실제 페이스 배치, 큰 글자·VoiceOver·잠금·백그라운드 전송과 실제 기기 provisioning은 후속 검증 대상이다. 앱스토어 배포·커밋·푸시는 하지 않았다.
