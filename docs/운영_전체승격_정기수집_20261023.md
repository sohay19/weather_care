# 테스트 기능 전체 운영 반영 및 심화 자료 정기 수집

2026-10-23 16:59:48 KST에 실제 테스트 배포본 전체를 운영에 반영했다. 운영·테스트의 실행 소스는 동일하며, 심화 날씨 API·백그라운드 위치 갱신·구버전 호환·낙뢰 알림을 포함한다. 운영에서 `locationMeasuredAt`이 포함된 앱 등록이 거부되던 문제도 해소했다. 사용자·인증·위치·알림 설정 및 이력은 기존 환경별 DB를 유지한다.

- 운영: `/opt/weather-care/releases/20261023-full-production/weather_care_server`
- 테스트: `/opt/weather-care/releases/20261023-full-test/weather_care_server`
- 공용 날씨 DB: `/var/lib/weather-care/weather-care-weather.sqlite`
- 운영·테스트 사용자 DB: 기존 `weather-care-users-production.sqlite` / `weather-care-users-test.sqlite`

승격 기준은 당시 실제 실행 중이던 테스트 릴리스 `20261023-shared-db-test` 전체다. 저장소의 추가 미배포 준비물 근거 변경 등은 이번 승격에 포함하지 않았다. 두 릴리스에는 동일한 정기 수집 보완을 적용했고 실행 소스 171개 파일의 해시 일치를 확인했다.

`ops/mini-pc/grid-collection.production.json`을 `/etc/weather-care/grid-collection.json`에 설치하고 공통 환경의 `GRID_COLLECTION_CONFIG_PATH`로 연결했다. 이 파일은 관측소 코드·영역만 포함한다. 날짜를 10월 23일로 고정하는 임시 스크립트는 사용하지 않는다. 이안류는 기존에 설정된 해수욕장이 없어 활성화하지 않았다. 제공처가 주지 않은 값과 결측은 생성하지 않는다.

API 호출은 기존 사용량 장부·중복 슬롯 검사를 유지한다. 매시 대량 수집에는 요청 간 300ms 간격을 두고, HRFCO 지점 이력은 하루 최대 1,200회 한도를 유지한다. 이력 보완은 10개 실패 또는 한도 소진 시 중지하고 서비스 실패로 남긴다. 전국 최신 자료는 별도의 매시 작업으로 계속 갱신된다. 같은 작업이 아직 실행 중이면 Node 스케줄러가 겹친 실행을 건너뛴다.

최초 실행에서 조위 관측 49곳·부이 26곳·K-water 하천 244조합·댐/보 59곳의 새 시간대 자료를 저장했다. 조위 `DT_0009`, `DT_0019`, `DT_0030`, `DT_0034`, `DT_0038`, `DT_0055`, `DT_0058`, `DT_0901`은 제공처 오류 코드 `40`으로 저장하지 않았다. 정규 06분 실행에서도 같은 오류를 확인했으며 결측을 보간하지 않고 다음 실행에서 재요청한다. 하천 이력 서비스는 당일 이미 확보한 935곳을 정상 재사용했다.

## 보존·검증 및 복구

배포 전 설정·서비스·양쪽 실행 소스와 사용자 DB·압축 공용 DB를 `/var/backups/weather-care/promote-20261023`에 보존했다. 사용자 백업의 `quick_check`, 공용 백업의 전체 gzip CRC를 통과했다. 서비스 정지 후 최신 사용자 스냅샷은 그 아래 `final-users/`에 별도로 저장했다.

유지보수 상태에서 새 API를 시작하고 양쪽 사용자 DB의 모든 기존 행을 전후 대조해 동일함을 확인한 뒤 요청을 재개했다. DB 경로·스키마·기존 관측값을 교체하지 않았다. 임시 등록 검증은 FCM 토큰 없이 별도 설치로 실행하고 삭제했다. 수동 푸시는 발송하지 않았다.

타입 검사, 저장소 Node 295개·Worker 466개, 실제 승격 소스 대상 Node 239개 테스트를 통과했다. 실제 승격 소스 검사에서는 별도 번들로 운영 중인 스토어/키갱신 도구 및 테스트 서버에 아직 없는 준비물 근거 기능을 제외했다. 공개 API·양쪽 앱 등록 24개, 심화 7종 각 2지점의 양쪽 공개 조회 28개를 확인했다. 상세 수집 결과·사용자 보존·소스 해시·백업·서비스 상태는 [검증 JSON](운영_전체승격_정기수집_검증_20261023.json)에 기록한다.

복구가 필요하면 수집·알림 서비스와 API를 중지하고 보존한 설정·서비스 및 이전 릴리스 링크를 함께 복구한다. 현재 사용자 DB와 공용 DB는 유지한다. 요청 재개 뒤 생긴 사용자 변경을 잃지 않도록 배포 전 DB를 그대로 덮어쓰지 않는다. 이전 운영 릴리스에는 심화 API와 일부 앱 등록 호환 기능이 없다는 점을 고려한다.

원격 실행 도구·상세 검증은 `/tmp/weather-care-promote-20261023`, 로컬 보존 자료는 Git 제외 `weather_care_server/build/promote-production-20261023`에 있다.
