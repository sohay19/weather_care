# 시험 서버 운영 반영 시 기존 앱 호환성 점검

2026-10-22 한국시간 기준. 실제 운영·시험 릴리스와 DB 마이그레이션 목록을 읽고, 내부 API 응답 및 Git의 과거 앱 코드를 대조했다. 서버 배포나 운영 설정 변경은 수행하지 않았다.

**최신 시험 배포 상태:** 2026-10-22 사용자 요청으로 하위 호환 변경 8개 소스와 0018을 시험 서버에만 반영했다. 구버전 두 버전의 실제 HTTP·날씨·앱 생성 위젯 6개와 공개 응답의 과거 Main 카드 렌더 6개가 모두 통과했다. 운영 릴리스·소스·환경·API/스케줄러/터널 프로세스는 그대로다. [시험 배포 검증 기록](하위호환_시험배포_검증_20261022.json)을 참고한다.

**초기 로컬 보완 상태(배포 전 기록):** 같은 날 사용자 요청에 따라 아래 호환성 문제를 로컬 코드에서 보완하고 테스트했다. 이 단계에서는 운영·시험 서버에 배포하지 않았다. 아래 초기 점검의 실제 서버 상태와 로컬 보완 결과를 구분한다.

**로컬 전체 검증 결과:** 이후 기존 테스트 실패 2건의 원인을 확인해 오래된 테스트 계약을 보완했다. 최종 `npm test`는 Worker 466개·Node 250개, 총 716개 전부 통과했다. 서버 타입 검사도 통과했으며 이 단계에서는 운영·시험 배포를 하지 않았다. 앞선 실패 수치는 보완 전 검증 이력이다. 전체 로컬 코드와 이번에 제한적으로 패치한 시험 릴리스는 범위가 다르다.

## 초기 점검 결론

현재 시험 서버를 그대로 운영에 적용하면 일부 구버전 앱의 표시와 알림 동작에 문제가 생길 수 있다. 서버 코드에 하위 호환 처리를 보완하고 운영 DB·주소·인증 설정을 유지하는 배포가 필요하다. 기본 API가 HTTP 200이라는 사실만으로 구버전 화면 호환성을 보장할 수 없다.

## 확인한 영향

1. **기존 미래 예보 표시 누락**
   - 같은 서울 격자 요청의 `/api/v1/weather/main`, `/today`에 운영은 `nextForecast`를 반환하지만 시험은 반환하지 않는다.
   - Git의 `13ee2af`와 `72fbd9e` 앱 모델은 이를 읽으며, `72fbd9e`의 Main 미래 예상 날씨 카드는 해당 값으로 기온·체감·습도·바람·자외선 등을 표시한다. 값이 없으면 null로 파싱되므로 이 경로에서 즉시 파싱 예외가 발생하는 구조는 아니지만 표시가 결측 상태로 바뀐다. 앱에서 만든 위젯 스냅샷도 이 값에 의존한다.
   - 이 계약을 사용하는 배포 앱을 위해 서버의 `nextForecast` 필드를 유지하는 것이 필요하다. 모든 설치 앱의 실제 빌드와 위 두 커밋의 일치 여부는 확인하지 않았다.

2. **낙뢰 알림이 기존 사용자에게도 활성화될 수 있음**
   - `0016_lightning_alerts.sql`은 `lightning_enabled`를 `NOT NULL DEFAULT 1`로 추가한다.
   - 시험 서버의 스케줄러에는 10분 간격 낙뢰 수집·전송 작업이 추가되어 있다. 기존 설치의 전체 알림이 켜져 있고 유효한 FCM 토큰·연령 확인·인근 관측 등 조건이 맞으면 새 알림 대상이 될 수 있다.
   - `72fbd9e` 앱은 `LIGHTNING` 주제를 알지 못해 unknown으로 분류하며, 해당 버전에는 낙뢰 전용 끄기 설정이 없다. 기존 전체 알림 설정은 서버가 계속 따른다.
   - 운영 반영 전에 기존 앱 대상의 새 알림 활성화 정책과 구버전의 알림 이동 동작을 확인해야 한다.

3. **시험 설정·DB를 함께 복사할 때의 접속 및 사용자 데이터 문제**
   - 시험 코드는 `TEST_ACCESS_KEY`가 있으면 키 없는 요청을 HTTP 403으로 거부한다. 운영에는 이 변수를 아예 설정하지 않아야 한다. 빈 문자열을 지정하면 현재 검증 코드에서 서버 기동이 실패한다.
   - 시험 DB는 운영 사용자 설치·인증·설정·이력을 보존하기 위한 교체본이 아니다. 운영 주소와 기존 운영 DB·인증·FCM 환경은 유지하고, 운영 DB 백업 후 미적용 0015~0017을 적용해야 한다.
   - 코드가 새 스키마에 의존하므로 마이그레이션 없이 코드만 바꾸면 DB 조회 오류가 발생할 수 있다. Node 시작 시 자동 마이그레이션이 있으므로 백업·적용·기동 순서까지 배포에 포함해야 한다.

4. **위젯의 새 준비물 종류**
   - 일반 Today/Weekly 추천은 `recommendationCatalog`로 기존 15종과 새 18종 경로를 구분한다.
   - `/widget`은 요청과 무관하게 새 18종 경로를 사용하도록 변경되었으며, `schemaVersion`은 양쪽 모두 3이다. 구버전 네이티브 위젯의 새 종류 표시까지 호환된다고 단정할 수 없으므로 별도 확인이나 구버전용 변환이 필요하다.

## 점검 범위와 배포 전 조치

- 운영과 시험에서 Main·Today·Weekly·Widget 총 8개 요청이 모두 HTTP 200이었다. Widget 버전 확인 2개 요청도 성공했다. 서울 표본의 기존 필드 누락을 재귀 비교했으며 `nextForecast`와 일부 브리핑 예보 시각 필드가 없음을 확인했다. 브리핑 시각 필드는 장면에 따라 선택적일 수 있어 별도 장애로 확정하지 않았다.
- 사용자 설치 등록·설정 변경 요청, 실제 푸시, 구버전 APK/IPA 실행, 전체 지역·계절·예외 상황 검증은 하지 않았다. Weekly 표본의 형태 일치도 전체 상태에 대한 보장은 아니다.
- 우선 `nextForecast` 응답 보존, 구버전 대상 낙뢰 알림 정책, 위젯 준비물 호환을 정리한다. 이어 운영 DB 복사본에 마이그레이션과 신서버를 적용하고 실제 배포 앱으로 날씨·설정 저장·위젯·알림 이동을 검증한 뒤 전환한다.
- 서버 재시작·선수집 중 잠깐 응답이 지연되거나 실패할 가능성도 있으므로 기존 서비스의 기동 조건을 반영한 전환과 복구 경로가 필요하다.
- 10월 22일 로컬의 준비물 판단 근거 변경은 현재 시험 릴리스에도 아직 배포되지 않았다. 현재 시험 서버 승격과 로컬 최신 코드 배포는 서로 다른 범위다.

## 로컬 하위 호환 보완 결과

- Main·Today에 `nextForecast`를 복원했다. 가장 가까운 미래 시각을 고르고 한국 날짜별 초미세먼지 예보 등급을 연결한다. 미래 슬롯이 없으면 운영의 기존 계약대로 현재 예보를 반환한다. 현재 실황을 미래 관측으로 바꾸지 않는다. 서버 생성 위젯도 이 호환 필드를 우선 사용한다.
- `/widget`의 카탈로그 누락·미지원 값은 기존 `PREPARATION_15`로 처리한다. `PREPARATION_18`을 명시한 요청만 새 정책을 사용한다. 현재 앱은 위젯 갱신 URL에 이 값을 추가한다. 위젯 `schemaVersion=3`과 기존 응답 이름을 유지한다. 구버전 사용자는 앱을 다시 빌드할 필요가 없다.
- `0018_lightning_client_support.sql`에 `lightning_supported`를 기본 0으로 추가했다. 기존 `lightning_enabled` 선호값·설치·FCM 토큰·인증정보·발송 이력을 보존한다. 인증된 낙뢰 설정 저장 요청이 실제 `lightningEnabled` 필드를 보내면 지원 표시를 기록한다. 두 설정 저장 경로에 모두 적용했다.
- 낙뢰 전용 작업은 지원 표시·개별 알림·전체 알림을 모두 확인한다. 기본값이 켜져 있다는 이유만으로 구버전에 새 알림을 보내지 않는다. 지원 확인 이후의 부분 설정 변경은 지원 표시를 지우지 않으며, 전송 직전에도 조건을 다시 확인한다. 새 앱은 설정 동기화 후 전용 알림 대상이 된다. 기존 낙뢰 지원 여부를 추측하지 않으므로 0018 적용 전에 쓰던 새 시험 앱도 한 번 설정을 동기화해야 한다.
- 빈 `TEST_ACCESS_KEY`는 미설정처럼 처리하도록 수정했다. 실제 키가 있으면 누락·잘못된 키는 계속 403이다. 운영에는 시험 접근 키와 시험 DB를 복사하지 않는 배포 조건을 유지한다.

## 향후 배포에 필요한 조건

이번 보완의 운영 DB 목표는 **0018**이다. 운영 사용자 DB·주소·인증·FCM 설정을 보존하고 백업 후 미적용 **0015~0018**을 적용해야 한다. 시험 DB도 기존 설치를 보존하면서 0018을 적용한다. 새 릴리스의 의존성을 잠금 파일 기준으로 설치하고 기동·선수집·복구 절차를 확인한다. 구버전 호환 자체를 위해 기존 사용자에게 앱 업데이트를 요구하지 않는다. 운영·시험 배포, 실제 푸시, 앱 빌드·설치, 커밋·push는 이번 작업에 포함하지 않았다.

## 기존 테스트 실패 2건 원인 확인·해소

- **자외선:** 전국 캐시 통합 테스트가 생활기상지수 예보 2만 저장하고 Today 현재값도 2일 것으로 기대했다. 10월 15일 확정된 현재 자외선 계약은 가까운 유효 관측소의 실측을 사용하고, 실측이 없거나 30분을 초과하면 예보로 대신 채우지 않는 것이다. 이 동작은 유지했다. 합성 관측소·관측 캐시를 추가하고 유효 실측 1.7, 실제 0, 관측 누락, 31분 전 관측을 각각 검사하도록 수정했다. 모든 경우에서 시간별 자외선 예보 2가 별도로 유지되는지와 외부 요청·설치 등록 없이 기존 환경·특보·강수·도로 정보가 제공되는지도 확인한다.
- **오존:** 사용자 지정 공통 수치 표시 규칙이 적용된 뒤에도 테스트는 이전 문자열 `0.102ppm`을 기대했다. 10월 15일 수치 표기 지침과 `9fcbc14`의 변경 내용을 대조해 표시값 `0.1ppm`이 의도된 결과임을 확인했다. 원자료와 내부 판단 정밀도는 유지했다. 0.102·0.149·0.151의 표시 및 나쁨/매우 나쁨 등급, 원본 수치 불변, 행동/체감 주의/공식 근거 역할을 검사한다. 농도·등급에 따라 달라지는 행동 문구는 승인된 카탈로그 문구 중 하나인지 검사하도록 보완했다. 공통 포매터에도 0.102→0.1을 명시했다.
- 수정은 테스트 3파일과 이 기록에 한정했다. 테스트를 통과시키기 위해 현재 실측 결측 정책·예보 계약·원자료·수치 표기 런타임을 바꾸지 않았다.
- 재현: 수정 전 각각 실패를 다시 확인했다. 수정 후 관련 Node 13개, Worker 25개와 서버 타입 검사를 통과했다. 이어 실제 `npm test` 명령의 종료 코드 0과 Worker 57파일/466개·Node 25파일/250개 전체 통과를 확인했다. 최종 실패 0개다.
- Git 제외 로그: 서버 `.baseline-failures-20261022-{node-before,worker-before,node-after,worker-after,typecheck,all}.log`. 운영·시험 서버 접속/배포, 실제 제공처 요청·푸시, DB 변경, 앱 실행·빌드·설치, 커밋·push는 수행하지 않았다.
