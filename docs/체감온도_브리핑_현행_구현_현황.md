# 체감온도 브리핑 현행 구현 현황

- 기준일: 2026-09-22
- 대상 화면: Flutter 앱 `Main > 지금 날씨`의 기온·체감온도와 안내 문구
- 문서 목적: 현재 실제 동작, 판단 기준, 반복 문구 원인, 기존 기준 문서와의 불일치, 아직 적용하지 않은 검토안을 구분해 기록한다.
- 변경 상태: 이 문서는 현황 확인용이다. 체감온도 계산식, 문구, 경계값, 테스트 및 서버 응답은 변경하지 않았다.

## 1. 요약

현재 화면의 `체감 상 조금 덥게 느껴질 수 있어요`는 다음 순서로 만들어진다.

1. 서버가 기상청 초단기실황의 기온·습도·풍속으로 현재 체감온도를 계산한다.
2. 앱은 서버에서 받은 현재 기온과 체감온도를 각각 소수점 첫째 자리로 표시한다.
3. 앱은 체감온도 절대값이 `20℃ 이상 28℃ 미만`이면 모두 `조금 더움`으로 분류한다.
4. 앱은 실제 기온과 체감온도의 차이가 `0.05℃ 미만`일 때만 `비슷함`으로 판단한다.
5. 앱은 하늘 상태, 실제 기온과의 차이, 체감온도 등급을 한 개의 고정 문장으로 조합한다.

따라서 현재 기온 `25.0℃`, 체감온도 `25.1℃`는 다음과 같이 처리된다.

| 판단 항목 | 현재 결과 |
| --- | --- |
| 체감온도 절대값 | `25.1℃` → `20℃ 이상 28℃ 미만` → `조금 더움` |
| 실제 기온과의 차이 | `+0.1℃` → `0.05℃ 이상` → `실제 기온보다 0.1℃ 높지만` |
| 하늘 상태 | `맑음` → `맑은 하늘이 이어지는 날씨예요.` |
| 최종 문구 | `맑은 하늘이 이어지는 날씨예요. 실제 기온보다 0.1℃ 높지만, 체감 상 조금 덥게 느껴질 수 있어요.` |

이 결과는 `25.1℃가 보편적으로 덥다고 검증됐기 때문`이 아니라, 현행 앱의 넓은 고정 구간과 비교 임계값 때문에 발생한다.

## 2. 현재 데이터 흐름

### 2.1 앱 요청

앱은 `GET /api/v1/weather/main?nx={nx}&ny={ny}`를 호출하고 응답의 `current`를 `TodayWeatherResponse.current`로 읽는다.

- 앱 요청: [`weather_care_app/lib/services/weather_service.dart`](../weather_care_app/lib/services/weather_service.dart)
- 앱 모델: [`weather_care_app/lib/models/weather.dart`](../weather_care_app/lib/models/weather.dart)
- Main 표시: [`weather_care_app/lib/features/home/tabs/main_tab.dart`](../weather_care_app/lib/features/home/tabs/main_tab.dart)

### 2.2 현재 기온과 체감온도 원본

최신 서버 코드는 선택 격자의 기상청 초단기실황을 현재 날씨에 연결한다.

| 항목 | 현재 원본 |
| --- | --- |
| 기온 | 기상청 초단기실황 `T1H` |
| 상대습도 | 기상청 초단기실황 `REH` |
| 풍속 | 기상청 초단기실황 `WSD` |
| 하늘 상태 | 기상청 단기예보 `SKY` |
| 데이터 역할 | 초단기실황이 유효하면 `OBSERVATION` |
| 체감온도 출처 표기 | `APP_KMA_METHOD_FROM_OBSERVATION` |
| 계산식 버전 | `KMA_APPARENT_TEMPERATURE_2026.1` |

초단기실황이 없거나 관측시각이 허용 범위를 벗어나면 최신 서버 코드는 현재 기온·체감온도·습도·풍속을 비운다. 단기예보 기온을 현재 실황인 것처럼 대신 표시하지 않는다.

- [`weather_care_server/src/providers/weather/kmaUltraShortObservationProvider.ts`](../weather_care_server/src/providers/weather/kmaUltraShortObservationProvider.ts)

### 2.3 현재 체감온도 산식

서버는 기상청 방식에 맞춰 계절별 산식을 구분한다.

- 5~9월: 기온과 상대습도로 Stull 습구온도를 구한 뒤 여름철 체감온도 산식을 적용한다.
- 10~익년 4월: 기온이 `10℃ 이하`이고 풍속이 `1.3m/s 이상`일 때 풍속냉각 산식을 적용한다.
- 해당 산식 조건을 만족하지 않는 경우 계산 함수는 실제 기온을 소수점 첫째 자리로 반환할 수 있다.
- 필요한 입력값이 없으면 현재 관측 또는 예보를 만드는 상위 함수에서 체감온도를 결측 처리할 수 있다.

기상청도 여름철과 겨울철 체감온도를 다른 산식으로 제공한다. [기상청 체감온도 설명](https://data.kma.go.kr/climate/windChill/selectWindChillChart.do)

## 3. Main 안내 문구의 현재 판정

Main의 안내 문구는 서버의 `brief`를 그대로 표시하지 않는다. 앱의 `_weatherSummaryMessage()`가 다음 세 값으로 현장에서 다시 만든다.

- `sky`
- `temperature`
- `apparentTemperature`

### 3.1 체감온도 절대값 구간

현재 `_apparentTemperatureLabel()`의 분류는 다음과 같다.

| 조건 | 내부 등급 | 화면 문장 표현 |
| --- | --- | --- |
| `38℃ 이상` | 위험한 더위 | 위험할 만큼 매우 덥게 |
| `35℃ 이상 38℃ 미만` | 더위 경계 | 매우 덥게 |
| `33℃ 이상 35℃ 미만` | 더위 주의 | 더위가 강하게 |
| `28℃ 이상 33℃ 미만` | 더움 | 꽤 덥게 |
| `20℃ 이상 28℃ 미만` | 조금 더움 | 조금 덥게 |
| `10℃ 이상 20℃ 미만` | 선선한 편 | 선선하게 |
| `0℃ 이상 10℃ 미만` | 쌀쌀한 편 | 쌀쌀하게 |
| `0℃ 미만` | 추운 날씨 | 춥게 |

현재는 `무난함` 또는 더위·추위 판단을 생략하는 중립 구간이 없다.

### 3.2 실제 기온과 체감온도의 차이

현재 `_apparentTemperatureComparison()`은 두 값을 먼저 소수점 첫째 자리로 반올림한 후 차이를 계산한다.

| 조건 | 현재 문구 |
| --- | --- |
| 차이의 절댓값 `< 0.05℃` | `실제 기온과 비슷하지만` |
| 체감온도가 실제 기온보다 높음 | `실제 기온보다 {차이}℃ 높지만` |
| 체감온도가 실제 기온보다 낮음 | `실제 기온보다 {차이}℃ 낮지만` |

입력값이 이미 소수점 첫째 자리로 반올림됐기 때문에, 실질적으로는 표시값이 정확히 같을 때만 `비슷함`이 선택된다. 표시값이 `0.1℃`만 달라도 높거나 낮다는 문구가 붙는다.

### 3.3 하늘 상태 문구

| 하늘 상태 문자열 | 현재 문구 |
| --- | --- |
| `비` 포함 | 비가 내리는 날씨예요. |
| `눈` 포함 | 눈이 내리는 날씨예요. |
| `흐림` 또는 `구름` 포함 | 구름이 많은 날씨예요. |
| `맑음` 포함 | 맑은 하늘이 이어지는 날씨예요. |
| 그 외 또는 결측 | 하늘 상태 자료가 없어 날씨를 확인하기 어려워요. |

### 3.4 최종 문장 형식

체감온도가 있으면 다음 고정 형식을 사용한다.

```text
{하늘 상태 문장} {실제 기온과의 비교}, 체감 상 {감각 표현} 느껴질 수 있어요.
```

체감온도가 없으면 다음 형식을 사용한다.

```text
{하늘 상태 문장} 체감 정보는 계산조건이 맞을 때 표시해요.
```

## 4. 같은 문구가 반복되는 원인

현재 반복은 데이터 갱신 실패가 아니라 문구 선택 구조에서 발생할 수 있다.

1. 체감온도 구간이 넓다. `20℃ 이상 28℃ 미만`의 8℃ 범위가 모두 `조금 덥게`다.
2. 하늘 상태는 비·눈·구름·맑음의 네 가지 고정 문장만 사용한다.
3. 현재 문구에는 습도 수준, 풍속 수준, 시간대, 일사, 활동량, 의복량이 직접 들어가지 않는다.
4. 같은 상태에서 선택할 대체 문장 목록이나 시간대별 문장 선택 규칙이 없다.
5. 서버에 여러 감각 문구를 가진 `sensationMessageCatalog`가 있지만, 이 카탈로그는 Main의 현재 날씨 문장과 연결돼 있지 않다. 현재는 일부 생활 문구의 자외선·미세먼지·오존·고온다습 표현에 사용된다.

따라서 하늘 상태와 체감온도 구간이 유지되면 최종 문장도 계속 동일하게 보인다.

## 6. 기존 기준 문서의 현재 상태

### 6.1 현행 구현을 설명하는 문서

[`docs/체감온도_표현_기준.md`](./체감온도_표현_기준.md)는 현재 코드와 같은 구간을 기록한다.

- `20~27.9℃`: 조금 더움
- `28~32.9℃`: 더움
- `33/35/38℃`: 더위 주의·경계·위험 단계
- 예시로 `24.2℃`를 `체감 상 조금 덥게`라고 표현한다.

이 문서는 한국형 PT와 기상청 체감온도가 다른 지수임을 인정하면서도 `20/28℃`를 임시 경계로 적용한다고 설명한다.

### 6.2 현행 구현과 충돌하는 원칙 문서

[`docs/수치_기준_근거자료_선정_항목.md`](./수치_기준_근거자료_선정_항목.md)는 다음 원칙을 명시한다.

- 한국형 PT와 기상청 체감온도는 산식과 값의 의미가 다르다.
- 한국형 PT의 `20/28/36/43℃`를 현재 앱의 기상청 체감온도에 그대로 대입하지 않는다.
- PT 입력이 부족하면 기상청 체감온도에 PT 경계를 대신 적용하지 않는다.
- `airTemperature`, `kmaApparentTemperature`, `koreanPerceivedTemperature`, `officialWeatherAdvisory`를 역할별로 분리한다.
- 한국인 야외 한랭 응답 근거를 채택하기 전까지 한랭 감각의 고정 수치 경계를 확정하지 않는다.

현재 코드는 기상청 방식으로 계산한 `apparentTemperature` 하나에 PT에서 가져온 `20/28℃` 경계와 임시 한랭 경계를 적용하므로, 위 원칙과 일치하지 않는다.

## 7. 확인된 연구 결과와 현재 적용의 차이

### 7.1 한국형 PT 고온 연구

한국인 대상 PT 연구는 `20/28/36/43℃` 경계를 제시했다. 다만 서울 거주 젊은 남성 19명을 대상으로 한 고온·고습 환경실험이고, PT는 복사환경·활동량·의복 등을 포함하는 인체 열수지 지수다. 현재 앱의 기상청 체감온도와 같은 값이 아니다. [Kang et al. (2022)](https://link.springer.com/article/10.1007/s00484-022-02261-x)

### 7.2 한국인 실외 더위·추위 인식

서울·대구 성인 남성 각 200명의 설문에서 실외를 덥다고 느끼기 시작하는 기온은 서울 평균 `29℃`, 대구 평균 `30℃`였다. 춥다고 느끼는 실외 기온은 평균 약 `7℃`, 중위값 `5℃`였다. 이는 현재 코드의 `20℃부터 조금 더움`과 큰 차이가 있다. [서울·대구 거주자 연구](https://kjcls.or.kr/_common/do.php?a=full&aidx=13101&b=32&bidx=991)

### 7.3 한국인 야외 현장 응답

창원·대구 892명 야외 조사에서는 기온 `27.2~29.5℃`에서 대체로 덥게, `33.6~34.3℃`에서 덥게~매우 덥게 느꼈다. `17.2~23.9℃`에서는 조금 선선함부터 따뜻함까지, `4.6~6.5℃`에서는 조금 선선함부터 추움까지 응답이 분산됐다. 이 결과는 기온만으로 모든 사람의 감각을 좁은 한 단계로 고정하기 어렵다는 점도 보여준다. [Korean Human Thermal Sensation and Comfort Model](https://sheridan.geog.kent.edu/icb2014/ICB20Cleveland.pdf)

### 7.4 중립·쾌적 범위 참고자료

서울 사무실 근무자 213명 연구의 SET* 중립값은 `25.3℃`, 쾌적 범위는 `23.8~26.8℃`였다. 실내·SET* 결과이므로 야외 기상청 체감온도에 직접 적용할 수 없지만, `25.1℃`를 보편적으로 조금 덥다고 단정할 근거로 사용하기도 어렵다. [여름철 사무실 내 한국인의 온열감 평가](https://kiss.kstudy.com/DetailOa/Ar?key=53387402)

### 7.5 한국어 표현의 의미

한국인 988명 조사에서 `따뜻하다`는 주로 쾌적한 표현으로, `약간 덥다`는 어느 정도 불쾌한 상태로 인식됐다. 따라서 `조금 덥다`는 중립 문구로 사용하기 어렵다. [한국어 온열감 표현 연구](https://pubmed.ncbi.nlm.nih.gov/20084522/)

## 8. 검토 중인 구간안 — 아직 미적용

다음 표는 대화에서 정리한 최신 검토안이며 코드·테스트·기존 기준 문서에 적용되지 않았다. 연구 결과를 참고한 제품용 잠정 구간이지, 기상청이 발표한 공식 감각 등급은 아니다.

### 8.1 체감온도 감각 구간 검토안

앱이 소수점 첫째 자리까지 표시하므로 범위 끝을 `.5`, 다음 범위 시작을 `.6`으로 연결한다.

| 체감온도 | 검토 중인 표현 |
| --- | --- |
| `6.5℃ 이하` | 춥게 |
| `6.6~17.5℃` | 쌀쌀하게 |
| `17.6~23.5℃` | 선선하게 |
| `23.6~26.5℃` | 더위·추위 판단 생략 |
| `26.6~29.5℃` | 조금 덥게 |
| `29.6~33.5℃` | 덥게 |
| `33.6℃ 이상` | 매우 덥게 |

기상청 위험 경계 `33/35/38℃`는 위 감각 표현과 별도로 유지하는 방향으로 검토한다. 실제 발효 특보와 한 시점 값 기반 내부 행동 신호도 서로 구분해야 한다.

### 8.2 실제 기온과 체감온도 차이 검토안

이 구간은 사람 대상 연구에서 검증된 감각 경계가 아니라, 소수점 차이를 과장하지 않기 위한 UI 문구 기준안이다.

| 차이의 절댓값 | 검토 중인 표현 |
| --- | --- |
| `0.0~0.5℃` | 기온과 체감 차이가 거의 없어요 |
| `0.6~1.5℃` | 기온보다 조금 높게/낮게 느껴질 수 있어요 |
| `1.6~3.5℃` | 기온보다 높게/낮게 느껴질 수 있어요 |
| `3.6℃ 이상` | 기온보다 훨씬 높게/낮게 느껴질 수 있어요 |

이 안을 적용하면 현재 기온 `25.0℃`, 체감온도 `25.1℃`는 중립 구간이면서 차이도 `0.5℃ 이하`이므로 다음처럼 표현한다.

```text
맑은 날씨예요. 기온과 체감 차이는 거의 없어요.
```

## 9. 변경 전에 확정해야 할 항목

현재는 다음 사항이 결정되지 않았으므로 구현하지 않은 상태다.

1. `6.5/6.6`, `17.5/17.6`, `23.5/23.6`, `26.5/26.6`, `29.5/29.6`, `33.5/33.6℃` 경계를 최종 채택할지
2. `선선함`과 `쌀쌀함`을 계절에 따라 다르게 표현할지
3. `33/35/38℃` 위험 행동 문구를 감각 문장과 분리해 어디에 표시할지
4. 경계 부근에서 값이 오르내릴 때 문구가 반복 변경되지 않도록 진입·해제 경계를 다르게 둘지
5. 같은 상태의 문구 다양화를 데이터 변화에 따라 할지, 날짜·시간대별 고정 변형으로 할지
6. Main과 Detail의 중복 판정을 공통 함수로 통합할지
7. 기존 기준 문서 두 개의 충돌을 어떤 기준으로 정리할지

## 10. 향후 변경 시 영향 범위

구간을 최종 확정해 적용할 경우 최소한 다음 항목을 함께 변경하고 검증해야 한다.

- Main 문구 판정과 문장 조합
- Detail 체감온도 수준 판정
- Main·Detail 공통 회귀 테스트
- `체감온도_표현_기준.md`
- `수치_기준_근거자료_선정_항목.md`의 현행/목표 상태 구분
- 경계값 바로 아래·위와 `25.0/25.1℃` 사례 테스트
- 기상청 위험 경계 `33/35/38℃`와 공식 특보 표시의 분리 여부

서버의 체감온도 숫자 산식 자체를 유지하고 앱의 표현 구간만 바꾸는 경우 서버 API 계약 변경은 필요하지 않다. 반대로 감각 판정을 서버에서 단일화하려면 응답 모델과 앱 표시 책임을 별도로 재설계해야 한다.
