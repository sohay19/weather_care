# 날씨챙겨 워치 앱·위젯 기획서

작성일: 2026-11-02 / 버전: 0.8 / 상태: 개발 전 검토 시안

## 1. 제품 방향

**손목에서 오늘 날씨와 챙길 물건을 3초 안에 확인한다.** 휴대전화 앱의 모든 상세 지표를 축소해 옮기지 않고, ‘챙겨요 → 현재 날씨 → 타임라인 → 기상/생활’를 먼저 보여준다. 3초는 사용성 검증 목표이며 측정 완료 수치가 아니다.

기존 날씨챙겨의 차분한 파란색·준비물 아이콘·브리핑 문구를 이어 쓴다. 워치에서는 검은 배경과 큰 수치, 짧은 문장을 사용한다. 광고는 첫 버전에 넣지 않는 안을 제안한다. 화면의 온도·시간·예보·특보는 모두 합성 예시이며 실제 연결 워치의 현재 날씨가 아니다.

이번 작업은 기기 속성 읽기, 기획, 웹 기반 시안 작성까지다. 워치 앱·위젯을 설치하거나 실제 Wear 서비스의 동작을 검증한 단계는 아니다. OS 버전과 렌더러 충족만으로 OEM별 위젯 배치를 확정하지 않는다.

### ‘위젯’의 구분

- **Wear 위젯:** 워치의 빠른 정보 화면에 놓는 소형·대형 카드. 최신 Wear OS의 컨테이너 크기·모양에 맞춘다.
- **타일:** 이전 Wear OS에서 빠르게 확인하는 전체 화면. 최신 위젯 미지원 환경을 위한 별도 호환 표현이다.
- **컴플리케이션:** 사용자가 선택한 워치페이스의 작은 정보 칸. 날씨챙겨는 데이터 제공자이며 실제 폰트·모양·크기는 워치페이스가 정한다. 시안의 워치페이스는 배치 예시이고 자체 워치페이스 개발 범위는 아니다.
- **휴대전화 홈 위젯:** 이미 있는 Android/iOS 위젯은 유지한다. 이번 기획의 새 위젯은 워치용이다.

## 4. 정보 구조와 주요 흐름

진입점은 앱 목록, 위젯, 컴플리케이션, 휴대전화에서 브리지된 알림이다. 모든 진입점은 마지막으로 본 지역과 같은 자료 시각을 사용한다.

1. **최초 실행:** ‘휴대전화와 연결’ 안내 → 폰 앱 상태 확인 → 지역·설정·스냅샷 수신 → 챙겨요. 폰 미설치/서명 불일치/연결 끊김을 하나의 오류로 뭉개지 않고 적절한 안내로 구분한다.
2. **외출 직전:** 챙겨요 목록 → 챙긴 품목의 우측 체크박스 선택. 소형 위젯은 날씨만, 대형 위젯은 준비물 아이콘까지 확인한다.
3. **앱 탐색:** 챙겨요 → 현재 날씨 → 타임라인 → 기상/생활 순서. 기상/생활의 2열 목록을 세로 스크롤하고 항목을 누르면 상세 데이터를 확인한다. 왼쪽 가장자리에서 오른쪽으로 밀면 이전 화면/종료를 따른다.
4. **기상 알림:** 기존 휴대전화 알림이 워치로 전달됨 → 탭 → 대상 구역과 사건 ID에 해당하는 안내. 휴대전화에서 보지 않은 경고를 워치가 임의로 새로 만들지 않는다.
5. **연결 끊김:** 캐시가 유효하면 마지막 자료와 시각 표시 → 유효기간이 지나면 오래된 자료 표시 → 재연결/새 자료 수신 후 앱·위젯·컴플리케이션을 함께 갱신한다.

## 5. 워치 앱 화면 명세

| 화면 | 내용 | 조작 / 빈 상태 |
| --- | --- | --- |
| 챙겨요 | 우선순위 높은 준비물과 짧은 이유, 맨 오른쪽 체크박스 | 품목 영역 탭은 이유·해당 시간. 체크 영역 탭은 챙김/해제만 변경. 빈/체크 상태를 명확히 구분 |
| 현재 날씨 | 지역·상태·기온·체감·최저/최고, 아이콘/기온 세로 중앙, 작아진 어제 비교 영역, 기준 시각 | 기존 오후 비/우산 행동 박스를 어제 같은 지역·시각의 기온·체감온도 비교로 대체 |
| 타임라인 | 다음 3시간의 날짜/시각·상태·기온·강수확률 | 기존 다음 시간의 내부 데이터 형식은 그대로. 자정 ‘내일’, 결측과 0% 구분 유지 |
| 기상/생활 | Today처럼 여러 지표를 2열 카드로 세로 나열 | 체감온도·습도·자외선·바람·대기질·대기정체·가시거리·꽃가루·강수량·적설량. 탭 시 상세 |
| 준비물 상세 | 품목명, 추천 이유, 적용 시간, 지역 | 일반 권고와 공식 특보를 구분. 길면 스크롤, 한 화면에 억지로 축소하지 않음 |
| 연결/갱신 상태 | 폰 연결, 자료 시각, 현재 지역 모드, 다시 확인 | 재시도 연타 제한. 서버 오류를 ‘비 없음’이나 ‘안전’으로 표시하지 않음 |

시안은 화면별 핵심 구간을 보여준다. 실제 앱은 스크롤 가능한 목록과 원형 가장자리 안전 여백을 적용하며, 모든 정보를 고정 한 화면에 넣지 않는다. 시안의 보조 화면 선택기는 검토용 도구이며 제품 메뉴가 아니다.

### 체크·비교·지표 상세의 추가 규칙

- 챙김 체크는 품목 설명 영역과 조작을 분리한다. 체크해도 추천 목록에서 즉시 지우지 않고 빈/채운 체크박스로 상태를 남긴다. 시안에서는 우산을 체크한 경우와 빈 상태를 모두 보여준다.
- 어제 비교는 같은 지역·같은 시각 기준으로 기온 차이를 위에 표시하고 그 아래에는 날씨 상태 대신 체감 차이를 표시한다. 예: ‘어제보다2° 낮아요 / 체감 상 어제보다3° 낮아요’. 기온·체감의 어제 비교는 각각 자료 유무를 확인한다. 기존48dp 브리핑 영역은 약35dp 비교 영역으로 줄이고 표시용 영역으로 사용한다. 자료/시간/지역을 맞출 수 없으면 비교 자료 없음으로 표시한다.
- 기상/생활은2열 목록을 끝까지 세로 스크롤한다. 지표 카드는 값·단위·등급을 요약하고, 누르면 값·기준 시각·해석/자료 기준을 확인한다. Today처럼 자료 없음·실제0·예측 지수·관측 수치를 구분한다. 별도의 건조도 수치 카드를 추가하지 않는다.
- 웹 시안의 목록 아래로 버튼은 스크롤 구간을 비교하는 검토 도구다. 실제 워치 앱에 페이지 버튼을 넣는다는 의미가 아니다.

챙겨요와 기상/생활 하단의 개수/아래로 문구는 시안에서 직접 넣은 안내다. 위치 범위(1~2 / 3개 등)를 없애고 모든 구간에서 ‘총 n개 · 아래로’로 통일한다. n은 현재 목록의 전체 개수이며 챙긴 수나 보이는 수가 아니다.

## 6. 워치 위젯·타일 명세

### 공식 SDK 규격 기준 재설계

0.6까지의 소형/대형 시안은 전체 원형 화면에 요소를 흩어 놓아 실제 위젯 카드 경계를 벗어났다. 이를 폐기하고 Google Maven의 **wear-tooling-preview:1.0.0-alpha21** 소스의 WidgetPreviewParams.kt·WearWidgetPreview.kt와 wear-core의 WearWidgetParams.kt를 직접 확인했다. widthDp/heightDp는 콘텐츠 크기이며, 표시용 외곽 프리뷰 크기는 양쪽 호스트 패딩을 더한 값이다.

대표 시안은 작은 화면용 기본 Squircle 규격이다. 소형 콘텐츠166×60dp/외곽182×76dp, 대형 콘텐츠166×96dp/외곽182×112dp이며 각각 호스트 여백은가로/세로8dp다. **실제 연결 기기를 측정한 값은 아니며** 공식 표준 프리뷰의 값이다. SM-L340의 정확한 호스트 크기는 재연결 후 확인해야 한다. OEM이 다른 크기·모양을 전달하면 그 값을 사용한다.

| 표준 프로필 | 콘텐츠 W×H(dp) | 호스트 여백 가로/세로(dp) | 외곽 프리뷰 W×H(dp) |
| --- | --- | --- | --- |
| squircle-small-1 | 166×60 | 8/8 | 182×76 |
| squircle-small-2 | 200×60 | 8/8 | 216×76 |
| squircle-large-1 | 166×96 | 8/8 | 182×112 |
| squircle-large-2 | 200×108 | 8/8 | 216×124 |
| round-small-1 | 182×54 | 13/8 | 208×70 |
| round-small-2 | 200×60 | 15/8 | 230×76 |
| round-large-1 | 150×120 | 29/16 | 208×152 |
| round-large-2 | 160×136 | 35/16 | 230×168 |
| rectangular-small-1 | 192×60 | 16/12 | 224×84 |
| rectangular-large-1 | 168×112 | 32/16 | 232×144 |

10개 규격에 맞춰 콘텐츠 너비·높이 기준으로 정규화했다. 모든 텍스트·박스·준비물과 최저/최고의 실제 SVG 경계를 검사했다. 이는 **SDK 소스의 공식 수치에 따른 웹 시안 경계 검사**이며 Android Studio Native Preview 실행 또는 실기기 설치 검사가 아니다. sourceUrl과 소스 JAR SHA-256, 프로필 값은 widget-specs.json에 보존한다.

### 소형: 카드 안에 현재 날씨

위치/기준시각 → 기온+날씨아이콘 · 한 줄 체감 → 최저·최고 순이다. 준비물은 넣지 않는다. 기본 바탕은 검정이며 정보박스는 기존 전체 바탕색#253747이다. 기온은 왼쪽, 날씨아이콘은 다음에 놓고 체감온도 사이에 중간점을 넣는다. 세 요소를 하나의 배경박스에 넣고 기온·아이콘의 세로 중앙을 맞춘다. 체감 라벨은 작게 유지한다. 좁은 높이에서는 수치를 축소해 전체를 강제로 넣는 대신 콘텐츠 높이에 맞는 콤팩트 타이포그래피를 사용한다. 시안의 기온은 기본 소형22.4sp, 날씨14.67dp(기존22dp의2/3), 체감 라벨9.5sp/수치17sp다. 더 낮은 Round 소형54dp에서는 기온17.6sp/날씨13.33dp(기존20dp의2/3)로 적응한다. 글자 확대·TalkBack의 Native 검증은 후속이다.

최저·최고는 **콘텐츠 안쪽 중앙 하단**이다. 대표166×60dp 콘텐츠에서 중앙x83, 기준선y57이며 호스트 바깥이나 원형 화면 맨 아래에는 그리지 않는다. 이 좌표는 문서의 대표 예시이고 실제 구현은 콘텐츠 너비/높이에서 계산한다. 카드 전체 탭은 현재 날씨로 이동한다.

### 대형: 같은 카드 안에 준비물 추가

위치/기준시각 → 기온+날씨아이콘 · 한 줄 체감 → 원형 배경의 준비물 아이콘3개 → 최저·최고 순이다. 날씨 행은 소형과 같이 기온+작은 날씨아이콘 · 체감을 한 배경박스에 넣는다. 검정 바탕과#253747 정보/준비물 배경은 소형과 같다. 준비물이3개 미만이면 있는 것만 표시한다. 대표166×96dp 콘텐츠에서 최저·최고 중앙x83/기준선y93이며 카드 안에 포함한다. 원형 화면 좌표y187은 사용하지 않는다.

### 크기와 모양의 표현

PDF4페이지와 웹의 소형·대형은 **위젯 카드 자체**를 같은 배율로 보여준다. 두 카드를 원형 전체 화면처럼 표현하지 않는다. 검정 카드 외곽은 호스트 포함 영역이며 안쪽 콘텐츠에만 정보를 배치한다. 둥근 정도는 대표 Squircle26dp와 Round/Rectangular 각 규격을 따른다. 실제 앱에서는 배경을 WearWidgetDocument의 background로 주고 root를 fillMaxSize로 채우며 WearWidgetParams에 적응한다. 검정 캔버스 안에 큰 가짜 카드 외곽을 별도로 강제하지 않는다.

### 이전 버전용 타일

타일은 전체 화면 방식이다. 제목 아래 지역·기준시각, 같은 행의 왼쪽 날씨44dp/오른쪽 기온44sp, 한 줄 브리핑, 하단 최저·최고를 유지한다. 주요 묶음은0.5보다8dp 위로 조정한0.6 배치를 유지한다. 전체 탭은 워치 앱의 현재 날씨를 연다. 카드형 소형·대형의 경계 규칙을 전체 화면 타일과 혼동하지 않는다.

### 플랫폼 계획

신규 앱은 단일 Wear 위젯 서비스와 공식 타일 호환부터 검증한다. 부족하면 TileService/WidgetService를 나눠 하나의 논리 항목으로 묶는다. SDK/렌더러·OEM 부분 높이 지원을 확인하고, 실제 표시 크기는 요청의 WearWidgetParams를 사용한다. 공식 소스 규격 확인과 실제 기기 지원 여부는 구분한다. 첫 지원 OS안과 alpha SDK 도입 위험은 기존 기획을 유지한다.

## 7. 컴플리케이션

| 제공자 | 기본 표시 | 탭 동작 / 자료 만료 |
| --- | --- | --- |
| 왼쪽 현재 기온 | 11° | 현재 날씨 열기 / 오래되면 -- 또는 NO_DATA |
| 오른쪽 날씨 아이콘 | 비·맑음 등 상태 아이콘 | 현재 날씨 열기 / 미수신은 NO_DATA |

기온은 SHORT_TEXT, 날씨 상태는 지원되는 이미지형 슬롯에 제공한다. 왼쪽 기온/오른쪽 날씨 아이콘 배치는 검토용 워치페이스 예시이며, 사용자 워치페이스의 슬롯·자료형 지원에 따라 실제 배치가 달라진다. 준비물 컴플리케이션은 이번 구성에서 제외한다. 자체 원형 게이지는 기온을 임의의 위험 점수처럼 오해하게 만들 수 있어 첫 버전에서 제외한다.

## 8. 데이터·위치·갱신 설계

첫 버전은 **휴대전화 연동형**으로 제안한다. 폰의 현재 위치 모드·선택 지역·기존 브리핑/준비물 정책을 원본으로 유지하고, 워치에서 상시GPS를 돌리지 않는다. 휴대전화의 백그라운드 위치 갱신이 실제 새 스냅샷을 만들었을 때 워치에 변경을 동기화한다. 현재 위치가 바뀌어도 저장 구역을 자동 추가하지 않는다.

재사용 후보는 HomeWidgetSnapshot의 지역, 현재/체감/최저최고, shortMessage, preparations, briefingTimeline, generatedAt/receivedAt, validUntil/nextBriefingBoundary/dataFreshUntil이다. 다음3시간 예보는 현재 스냅샷의 next 한 건만으로 부족하므로 Today 응답에서 최소 hourly 배열을 별도 정규화한다. 기상/생활 2열 목록은 Today의 current·생활 지수 자료에서 값·단위·등급·기준 시각·출처/설명을 정규화한다. 기상 경고의 사건 ID·유효기간·중요도는 별도로 보존한다. 이미 있는 것으로 가정하지 않는다.

제안 흐름: 기존 날씨 API/폰 캐시 → 폰 WearSyncAdapter → Data Layer → 워치 로컬 저장소 → 앱·위젯·타일·컴플리케이션. Data Layer는 동기화 수단이며 워치의 영구 저장소로 대신 쓰지 않는다. 폰과 워치는 같은 패키지명·서명이어야 하며, 기존 Flutter 모바일 모듈은 유지하고 Kotlin/Compose for Wear OS 별도 모듈을 둔다. 폰과 워치에 무관한 별도 서명 Debug 패키지를 설치한 상태로 연동 성공을 기대하지 않는다.

권장 새 계약 WearSnapshotV1: schemaVersion, revision, locationKey, locationMode, regionLabel, generatedAt, receivedAt, validUntil, dataFreshUntil, current, yesterdayComparison, briefing, preparations, nextHours, metrics, alerts. 기존 위젯 계약을 강제로 바꾸지 않고 adapter로 변환한다. 최신 revision만 적용하며 다른 지역의 늦은 응답을 버린다. 체크리스트는 첫 버전에 포함한다. 챙김 상태는 추천/알림 ON/OFF와 분리하며, 제안 저장 키는 지역+현지 날짜+품목이다. 같은 날 새 자료를 받아도 체크를 유지하고 다음 날은 초기화하는 안이다. 첫 버전은 워치 로컬에 저장하며 폰으로의 상태 동기화는 별도 검토한다.

| 발생 조건 | 동작 |
| --- | --- |
| 앱 진입 | 유효 캐시 즉시 표시, 오래됐으면 폰에 갱신 요청 |
| 폰 날씨/위치/설정 변경 | 변경된 revision 동기화, 중복 내용이면 전송 생략 |
| 브리핑 경계 도달 | 이미 받은 timeline에서 유효한 다음 구간 선택, 필요 시 갱신 요청 |
| 정기 백그라운드 | 30분 목표의 보조 갱신을 제안하되 OS·연결·절전에 따른 지연 허용 |
| 수동 다시 확인 | 폰에 요청, 응답 전 기존 유효 캐시 보존; 60초 중복 요청 제한 제안 |
| 폰 미연결 | 유효 캐시만 표시, 만료된 추천을 현재 권고처럼 사용하지 않음 |

‘30분’은 제품 목표이며 정확한 실행 보장이 아니다. forecast generatedAt, 수신시각, 다음 요청 예정시각을 혼동하지 않는다. 특보·현재비·블랙아이스 등 짧은 유효 정보는 해당 validUntil 만료 즉시 최신 위험처럼 표현하지 않는다. 통신 실패를 경고 해제 사건으로 만들지 않는다.

직접 서버 통신·독립 위치는 후속 단계다. 워치 전용 설치 인증, 조회 권한, 독립 토큰 만료/폐기, 기기별 알림 중복 방지와 개인정보 동의를 설계한 뒤 진행한다. 휴대전화의 기존 설치 비밀키를 워치에 단순 복사하지 않는다.

어제 비교는 현 스냅샷에 없으므로 폰 응답의 과거 비교 자료를 확인한 뒤 재사용하거나 별도 정규화한다. 화면 문구를 위해 같은 위치의 어제 자료가 있다고 임의 가정하지 않는다. 기준 시각은 자료의 시각이며 워치 현재 시각이나 화면을 연 시각과 구분한다.

## 9. 기존 알림·설정과의 관계

- 알림 사용여부 / 챙겨요 전체 / Today 전체 / 기상·생활 전체 / 개별 선택값과 공통 알림 시각은 기존 서버·폰 정책을 그대로 따른다.
- 알림 OFF와 앱에서 날씨를 조회하는 것은 다르다. 세 그룹의 OFF는 알림 발송 제어이며 앱·위젯 정보를 모두 숨기는 설정으로 사용하지 않는다.
- 첫 버전은 기존 폰 알림 브리지를 이용해 한 사건이 폰·워치에서 별도 두 번 진동하지 않도록 한다. 독립 워치 FCM은 우선 도입하지 않는다. 페어링/방해금지/착용 상태에 따른 실제 라우팅은 실기기에서 확인한다.
- 워치 전용 지역 선택이 생기면 ‘폰 지역 따라가기’가 기본이다. 추후 다른 지역 보기와 폰 구역 추가/알림 구독을 구분한다.
- 첫 실행은 연동 안내를 제공하고 위치·알림·백그라운드 권한을 한꺼번에 요구하지 않는다. 연동형은 워치 위치 권한 없이 폰의 지역 스냅샷부터 제공한다.

## 10. 디자인 기준

기존 앱 dark palette의 #9DBDD8, #253747, #1D2731과 SUITE를 기준으로 한다. 워치 바깥 배경은 #000000, 주요 글자는 #EDF2F6, 보조 글자는 #AAB7C3, 주의는 #E6B879이다. 값·경고는 아이콘과 문구로도 식별한다. 준비물 이미지는 저장소의 기존 자산을 재사용한다.

날씨 아이콘은 임의 구름/빗금 도형을 제거하고 앱 위젯의 동일한 컬러 아이콘 계열로 통일한다. 시안은 docs/icon-previews/weather-color의 기존PNG를 그대로 내장하며, WidgetIconRenderer의 맑음·구름·비 도형/색상과 tools/generate_icon_previews.py의 생성 기준을 대조했다. Android와 웹 래스터라이저의 픽셀 경계 차이는 있을 수 있지만 새 아이콘을 별도로 디자인하지 않는다.

기존 어두운 준비물 이미지는 워치의 검은 표면에서도 읽히도록 밝은 단색으로 표현했다. 건조 상황의 립밤은 이번 시안용 벡터 대체 도형이며, 실제 구현 시 기존 준비물 아이콘 체계와 맞춘다.

워치 앱208dp 검토 기준: 기본 본문14sp, 보조12sp, 지역14sp, 주요 기온44~48sp. 터치 영역48×48dp 이상, 표준 컴포넌트의 회전 입력·TalkBack·시스템 글자 크기 반영을 전제로 한다. 기존 모바일의 글자 배율 고정 정책을 워치에 그대로 복사하지 않는다. 큰 글자에서는 정보 수를 줄이거나 스크롤하며 축소로 회피하지 않는다. 원 가장자리에는 중요한 문구/동작을 배치하지 않는다.

시안의 고정 원형 프레임은 비교를 위한 표현이다. 시스템 바·OEM 위젯 외곽·실제 폰트 메트릭을 대체하지 않는다. 상시표시(AOD)는 첫 버전 앱의 지속 실행을 제공하지 않고 워치페이스/컴플리케이션의 시스템 동작을 따른다.

## 11. 개발 순서·완료 기준

1. **플랫폼 검증:** 연결 워치에 최소 Kotlin 앱·위젯 제공자를 별도 QA로 설치해 선택기, 위젯2종, 타일 호환, 컴플리케이션 슬롯을 확인한다. 현 단계에서는 설치하지 않는다.
2. **정규화·동기화:** WearSnapshotV1, 캐시, revision/지역 순서 보호, 같은 서명으로 Data Layer 양방향 요청을 검증한다.
3. **앱과 빠른 화면:** 현재/준비물/시간별/안내 및 오류 상태, 접근성, 위젯과 컴플리케이션을 구현한다.
4. **실기기 검증:** 폰을 열지 않은 위치 이동·재연결·절전·재부팅·타임존 변경·구 폰 버전과의 조합을 확인한다.
5. **배포 준비:** 새 모듈의 Wear 품질·선택기 미리보기·스토어 등록과 지원 OS를 검토한다. 시안 승인 후 일정 산정한다.

## 12. 시안 파일과 검토 방법

동일 폴더 design/watch-20261102/index.html에서 화면·예시 상황을 바꾸고 준비물 상세/되돌아가기를 눌러 흐름을 살펴볼 수 있다. overview.png는 챙겨요→현재 날씨→타임라인→기상/생활 순서와 체크/상세 예시6화면, widgets.png는 소형·대형·기존 타일·컴플리케이션 비교다. PDF에는 핵심 기획과 수정 시안, 공식 SDK10규격 표와 검증 범위를 넣었다. 모두 합성 데이터이며 실제 구현·설치 화면이 아니다.
