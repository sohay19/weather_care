# 워치 앱·위젯 구현 및 실기기 검증

검사일: 2026-11-02 / 기준 시안: 0.8 / 기기: Samsung SM-L340, Android17/API37, 원형438×438px, density340dpi

## 구현 범위

`weather_care_wear` 네이티브 프로젝트를 추가했다. 챙겨요의 개별 체크·설명, 현재 날씨의 어제 기온/체감 비교, 타임라인, 10개 기상/생활 지표의 2열 목록·상세를 구현했다. 세로 스크롤·회전 입력과 가장자리 뒤로 이동을 지원한다. 같은 날 다른 구역에 다녀와도 각 구역의 체크를 보존한다.

소형·대형은 공식 Glance Wear/Remote Compose 서비스를 사용한다. 기온+기존의2/3 크기 날씨아이콘 · 체감을 하나의 배경박스에 배치했다. 대형만 준비물 원형 아이콘3개를 추가하고, 최저/최고는 각 카드 안쪽 중앙 하단에 놓았다. 폰 위젯의 원본 날씨 렌더러·준비물 자산과 SUITE 폰트를 재사용한다. 이전 OS용 전체 화면 타일 및 기온/날씨 컴플리케이션 서비스도 등록했다.

폰의 기존 위젯 자료 저장/백그라운드 위치 갱신 경로에 Data Layer 발행을 추가했다. 워치는 독립 캐시를 읽고 앱·위젯·타일·컴플리케이션 갱신을 요청한다. 지역 선택과 알림 설정을 변경하거나 저장 구역을 추가하지 않는다. 서버 수정·배포는 없다. 폰 프로젝트가 새 `weather_care_wear/bridge`를 참조하므로 두 프로젝트를 함께 보존해야 한다.

- 실제 위젯 카드를 누르면 현재 날씨 화면으로 진입.

## 시험 자료와 실제 연동의 구분

화면 검사는 `시험 3구역`/`시험 중구`,11°/체감9° 등의 **androidTest 전용 합성 payload**로 수행했다. 테스트용 주입 receiver나 API를 일반 앱에 공개하지 않았다. 이것은 실제 이동이나 기상 서버에서 실시간으로 관측을 받은 검사와 다르다. 검사 종료 시 이전 저장 자료를 복원했으며 최종 상태는 날씨 없는 연결 대기다. 검사 APK는 제거하고 일반 워치 앱과 두 위젯은 남겼다.

현재 리모트랩 워치의 Data Layer 연결 노드는 **0개**다. 따라서 실제 폰→워치 전송, 폰 앱 미진입 상태의 실제 백그라운드 위치 이동, 재페어링·24시간 배터리, 이전 OS의 타일 표시, 워치페이스 슬롯 선택/표시, 큰 글자 전체 조합은 미검증이다. 코드 경로 구현과 해당 실환경 검증을 구분한다.

사용자가 지정한 RDB 실행 파일의 두 번째 실행은 `RDB is already running. Please close it and try again.`으로 차단됐다. 이 결과는 기본 실행 방식에서 두 인스턴스를 띄울 수 없음을 의미한다. 폰과 워치를 각각 ADB에 붙이는 것과 실제 페어링은 별개이며, 다른 장소의 임의 리모트랩 기기를 ADB만으로 페어링한 것으로 간주할 수 없다. 워치와 실제로 페어링된 폰에 새 폰 APK를 설치한 뒤 실제 연동 검사가 필요하다.

시험 중 APK를 교체할 때 삼성 시스템 UI의 런처 아이콘 갱신 경로에서 ArrayIndexOutOfBoundsException1건을 기록했다. 앱 코드 스택의 예외는 아니며 시스템이 복구된 뒤 최종 두 실기기 검사는 통과했다. 최종 통과 로그와 중간 실패 로그는 구분한다.

## 후속 요청: 사용자 직접 UI 둘러보기

사용자가 연결 대기 화면을 제보한 뒤 ‘그냥 UI만 봐도 된다’고 지정했다. 폰 페어링 없는 리모트랩에서도 직접 조작하도록 androidTest 전용 WatchPreviewTest 도구로 ‘UI 시험 자료’를 넣었다. 일반 앱 코드는 바꾸지 않았다. 준비물3개·시간별3개·생활지표10개·어제 비교 예시를 표시하며, 기준시각은 이 UI 미리보기에서는 워치 표시 시각과 맞춘다.

도구 실행은1개 통과이며 실제 네 화면 이동/표시 및 소형·대형 위젯의 적용을 확인했다. 증거는 `output/watch-ui-preview-20261102/`다. 이번 후속 요청에서는 사용자가 볼 수 있도록 시험 자료를 원복하지 않고 남기며 챙겨요 화면으로 열어 뒀다. 앞 절의 연결 대기 원복은 이전 자동 검사 종료 시점의 기록이다. 현재 자료는 실제 관측이 아니고 준비물 유효기간은 약1시간이다. 일반 앱에는 공개된 자료 주입 API나 자동 시험 자료 전환을 추가하지 않았다.

## 후속 요청: 실제 시계페이스 적용

SM-L340의 ‘아날로그 밸런스’에서 꾸미기→컴플리케이션→다른 앱→날씨챙겨를 사용했다. 왼쪽에는 날씨챙겨 기온, 오른쪽에는 날씨챙겨 날씨를 지정했다. 아래 걸음 수 칸은 기존 설정을 유지했다. 새 워치페이스 앱을 만들거나 설치한 것이 아니라 기존 페이스에 구현된 두 데이터 제공자를 적용했다.

실제 시계 화면에서 왼쪽11°와 오른쪽 비 아이콘을 원본 PNG 및 접근성 설명으로 확인했다. 두 정보 칸을 각각 눌렀을 때 날씨챙겨 현재날씨의 ‘UI 시험 자료’ 화면이 열리는 것을 확인하고 실제 시계 화면으로 돌아왔다. 대기/홈 복귀 중 캡처에는 정보가 비어 보인 경우가 있었고 시계 배경을 한 번 터치해 깨우면 두 정보가 표시됐다. 이 관찰을 모든 페이스/AOD 조합의 검증으로 확대하지 않는다.

이로써 앞 절에서 미검증으로 적은 워치페이스 슬롯 지정/표시는 이 페이스의 두 칸에 대해 확인됐다. 다른 페이스·슬롯 자료형·큰 글자/AOD 전체 조합 및 실제 폰 날씨 연동은 여전히 별도 검증 범위다. 결과는 `output/watch-face-20261102/applied.png/.xml`, `temperature-tap.png/.xml`, `weather-tap.png/.xml`이다. 표시 값은 사용자가 지정한 UI 시험 자료이며 실제 관측을 의미하지 않는다.

## 최종 변경: 기존 독립 타일 제공

사용자 요청으로 소형·대형 WeatherWidgetService는 Manifest에서 비활성화하고 기존 전체 화면 WeatherTileService를 기본 제공하도록 전환했다. 추가 목록에는 날씨챙겨1개가 표시되며 SM-L340에 실제로 추가했을 때 시스템 이름은 날씨챙겨, Tile, 4 of 4였다. 이름을 사용자가 수동 입력하지 않았고 Tools 묶음은 생성되지 않았다.

최종 Debug/AndroidTest 빌드와 설치에 성공했다. WatchPreviewTest1개 통과 후 시험 APK를 제거했으며 UI 시험 자료가 표시되는 타일의 기온/날씨아이콘/브리핑/최저·최고와 탭의 현재날씨 진입을 확인했다. 타일은 기기에 남기고 해당 화면을 열어 두었다. 이는 실관측이 아니며 실제 폰 페어링/날씨 동기화는 미검증이다. 증거 output/watch-legacy-applied-20261102/applied.png, applied.xml, tap.xml. 최종 빌드 로그 weather_care_wear/build-legacy-final.log.

## 실제 서버 연결: SM-F971N ↔ SM-L340_KR2

별도 서버 연결 기능을 시험·운영에 배포하고, 실기기 폰 ‘날씨챙겨 수정본’(com.codesoha.weathercare.preview)과 리모트랩 워치의 실제 연결·해제·재연결을 확인했다. 기존 Play 앱은 서명 차이 때문에 삭제/덮어쓰기 없이 보존했다. 현재는 시험 자료가 아닌 실제 서울 구로구 날씨를 표시한다.

폰·워치 Activity를 닫은 상태에서도 실제 날씨 조회 Worker→서버 게시 Worker→삼성 전체 화면 타일의 수신이 완료됐다. 버전13→15, 양쪽 버전15/같은 발행시각/기온14.5°/체감10.7°/오후4:13 기준/Today10지표 일치를 확인했다. background-workers.log에는 실제 조회/게시 Worker SUCCESS가 남아 있다. 30분 주기 등록은 확인했고 자연 주기·Doze 장기 동작·물리 이동은 검증하지 않았다. 서버 연결 해제 시 양쪽 접근/워치 캐시가 제거되고 새 코드 재연결 후 실자료가 돌아왔다.

원본 증거 output/watch-phone-link-20261102/background-chain-before.json, background-chain-after.json, background-workers.log, watch-live-tile.xml, real-linked-tile.png. 서버 백업·배포 결과는 weather_care_server/build/wear-cloud-deploy-20261102/{test,production,contract}-report.json. 서버 구버전/연결/API30개와 typecheck, Flutter31개/분석, 워치9개/빌드·Lint0오류를 확인했다. 기본 타일명은 날씨챙겨이며 해당 타일을 기기에 남겼다. 스토어·커밋·푸시는 수행하지 않았다.
