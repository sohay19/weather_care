# 날씨챙겨 앱 탭 구성 현황

- 기준일: 2026-10-21
- 기준: `weather_care_app/lib` 현재 구현 코드
- 하단 내비게이션 표시 순서: **Today → Advanced → Main → Week → Setting**
- 앱 최초 진입 탭: **Main** (`selectedIndex = 2`)

> 이 문서는 기획 메모가 아니라 현재 구현 상태를 기준으로 관리한다.
>
> 표기: **완료**는 코드와 회귀 테스트까지 반영된 항목, **부분 완료**는 UI만 있고 저장·운영 연동이 남은 항목이다.

## 1. 공통 화면 구조

### 탭 및 상태 유지

- 5개 탭은 `HomeScreen`의 `IndexedStack`으로 구성된다.
- 탭을 이동해도 각 탭의 위젯 상태는 유지된다.
  - 예: Main에서 체크한 준비물, Main에서 선택한 타임라인 지표, Setting에서 바꾼 토글 상태
- 하단 내비게이션 높이는 74px이며 모든 탭 라벨을 항상 표시한다.
- 선택 전후 아이콘 색상은 동일하게 유지하고 아이콘 모양과 배경 표시로 선택 상태를 구분한다.
- Main의 준비물 정보 버튼을 누르면 Today 탭의 상세 자료로 이동한다.
  - 선택한 준비물과 관련된 근거를 우선 배치하고 해당 카드를 펼친다.

### 날씨 데이터 조회 상태

날씨 데이터는 다음 순서로 조회한다.

1. 저장된 최근 GPS가 유효하면 새 GPS 측정을 기다리지 않고 사용한다.
2. 운영 서버의 경량 Main API와 Today/Weekly API를 병렬 호출한다.
   - Main 핵심 날씨가 먼저 도착하면 상단 날씨 카드를 즉시 표시한다.
   - Check List·Main 타임라인·Today 상세·Week는 자료가 도착할 때마다 이어서 갱신한다.
3. 연결 오류나 선택 지역의 중앙 수집 자료 미준비가 계속되면 안내 팝업을 표시한다.
   - 동작: `운영 서버 다시 시도`
   - `Check List`와 Main `타임라인`은 운영 서버가 준비한 자료가 필요하다고 안내한다.
4. 앱은 기상청 API를 직접 호출하거나 고정 날씨로 대체하지 않는다.

| 조회 상태 | Main | Today | Advanced | Week | Setting |
| --- | --- | --- | --- | --- | --- |
| 운영 서버 연결 | 전체 기능 | 전체 기능 | 수집된 자료 표시 | 전체 기능 | 접근 가능 |
| 서버 자료 준비 중·조회 실패 | 상태 안내 | 상태 안내 | 조회 실패 안내 | 상태 안내 | 항상 접근 가능 |

### 공통 새로고침

- 모든 탭 헤더에서 새로고침 버튼을 제거했다.
- Main, Today, Advanced, Week, Setting과 날씨 미지원 상태 화면은 모두 아래로 당겨서 새로고침할 수 있다.
- 새로고침 때도 운영 서버를 먼저 조회하며 실패하면 동일한 선택 팝업을 표시한다.

### 공통 날씨 아이콘 규칙

날씨 상태 아이콘은 Main 현재 날씨, Today 현재/시간별 날씨, Week 날짜별 날씨에 같은 규칙으로 적용한다. **우산 아이콘은 날씨 상태가 아니라 준비물·알림 항목에서만 사용한다.**

- 해+구름, 겹친 구름, 구름+비/눈처럼 여러 요소를 조합한 아이콘은 상태별 독립 위젯으로 캡슐화한다.
- 조합 위젯은 부모 영역이 더 커도 지정한 정사각 크기를 유지해 구름과 강수 요소가 서로 떨어지지 않도록 한다.

| 서버 상태 | 아이콘 표현 | 구분 원칙 |
| --- | --- | --- |
| 맑음 | 해 | 구름 없음 |
| 구름 많음 | 해 + 구름 | 해가 일부 보이는 다소 흐린 상태 |
| 흐림 | 겹친 구름 | 하늘을 구름이 덮은 상태 |
| 빗방울·이슬비·가랑비·약한 비 | 구름 + 빗방울 1개 | 약한 강수 형태 |
| 비 | 구름 + 빗방울 2개 | 일반적인 비 |
| 소나기 | 구름 + 빗방울 3개 | 비와 별도 형태로 구분 |
| 눈날림 | 윤곽 구름 + 작은 눈송이 | 약한 눈날림 |
| 눈 | 구름 + 눈송이 | 일반적인 눈 |
| 빗방울/눈날림 | 윤곽 구름 + 작은 빗방울 + 작은 눈송이 | 약한 혼합 강수 |
| 비/눈 | 채운 구름 + 빗방울 + 눈송이 | 일반 혼합 강수 |
| 알 수 없음 | 물음표 | 미정의 상태를 맑음으로 오인하지 않음 |

## 2. Main 탭

### 목적

현재 예보 구역의 대표 실황과 오늘의 핵심 생활 정보를 한 화면에서 빠르게 확인하는 탭이다.

### 화면 구성 순서

1. **페이지 헤더**
   - 날짜와 요일
   - `{지역명} 날씨` 오른쪽의 열림 버튼에서 현재 위치, 저장한 구역, `구역 추가`를 선택한다.
   - 추가한 구역이 없으면 현재 위치와 `구역 추가`만 표시한다. 구역을 고르면 해당 격자의 날씨를 다시 조회한다.
   - `예보 기준 구역 지도를 확인할 수 있어요` 옆의 작은 정보 버튼으로 지도를 연다. 버튼은 배경 없이 primary 색상을 쓴다.
   - 별도 앞 아이콘과 새로고침 버튼 없음
2. **Check List 챙김카드**
   - 실제 준비물 체크 카드를 상단 날씨 카드 바로 위에 배치
   - 한국시간 현재부터 오늘 자정까지 필요한 준비물을 최대 3개, 한 줄로 표시한다. 비·눈 대비 우산을 가장 먼저 배치하고, 나머지는 항목별 최고 단계 대표 물품을 강도가 높은 순으로 하나씩 배치한 뒤 남는 칸을 추가 물품으로 채운다. 한 항목만 있으면 같은 항목에서 최대 3개, 두 항목이면 2개와 1개, 세 항목 이상이면 우선순위가 높은 세 항목에서 하나씩 표시한다. 좁은 화면·큰 글씨에서도 카드가 다음 줄로 내려가지 않는다.
   - 저녁에 필요한 준비물도 아침부터 표시하고 `n시부터`에 실제 필요 시작 시각을 사용한다. 비·눈은 예보 시각이 아닌 강수 구간의 시작을 사용한다. 종료 시각은 포함하지 않으며, 서버의 시간대별 준비물 목록·`preparationPeriods`로 앱 재조회 없이 종료된 물품을 제거하고 다음 순위 물품을 표시한다. 일몰이 제공되면 자외선 대비도 일몰에 종료한다.
   - 카드 높이는 가장 긴 내용에 맞춰 통일하고 챙김 버튼은 모두 하단의 같은 높이에 맞춘다. 시작 시각은 12px 글꼴과 사용자 글씨 배율을 유지하며 축소하지 않고 필요한 경우 두 줄로 표시한다.
   - 위치 제목·지도 안내의 버튼 여백을 줄이고, 지도 안내와 Check List 사이 간격은 좁은 화면 12px·일반 화면 16px로 표시한다.
   - 추천된 우산·양산·겉옷·마스크·물·선크림·폭설 대비 항목만 표시
   - 카드 탭으로 `챙길게요`와 `챙겼어요`를 전환하고 한국시간 날짜별 기기 저장을 유지
   - 정보 버튼을 누르면 Today 하단의 관련 생활 근거로 이동
   - 서버는 준비물마다 추천을 발생시킨 실제 시간 자료·수치·출처와 적용한 판단 기준을 `evidence`로 함께 보낸다. 브리핑·시간대별 체크리스트는 `preparationEvidence`에 물품별 근거를 포함한다. 근거를 만들 자료가 없으면 해당 준비물을 생성하지 않는다.
   - 정보 버튼은 선택한 준비물의 근거 카드를 Today에서 즉시 펼쳐 표시한다. 현재 브리핑 구간의 물품별 근거를 하루 전체 추천의 근거보다 우선하고, 일반 추천 설명을 근거의 대체 문구로 사용하지 않는다. 공식 원자료와 앱 계산/판단 기준의 역할을 구분한다.
   - 추천이 없으면 특별히 챙길 준비물이 없다는 빈 상태를 표시
3. **상단 날씨 카드**
   - 서버가 만든 이유 우선·조건부 행동 요약을 말줄임 없이 표시한다. 눈/비/대기질/자외선·더위/겉옷/바람/기본 안내의 기존 7개 장면 우선순위를 따른다.
   - 현재 시각에 유효한 시간대는 `지금`, 미래 시간대는 시각으로 표시한다. 다음 날 예보에는 `내일 오전 9시`처럼 상대 날짜를 붙이고 끝난 시간대는 선택하지 않는다.
   - 미래 시각이 시작되거나 현재 시간대가 끝나면 `briefExpiresAt`으로 해당 요약을 만료시킨다. 앱은 지난 행동 대신 새로고침 안내를 표시한다. 서버 원문 기온·관측·예보 시각은 바꾸지 않는다.
   - 자외선 근거 문장도 자료 조회일과 예보일이 다르면 날짜를 붙인다. 자세한 계약은 [Main 시간별 행동 안내](Main_시간별_행동_안내.md)를 참고한다.
   - 하늘 상태에 따른 배경 톤
   - 초단기실황 관측 시각·현재 기온과 현재 체감온도를 한 줄에 표시. 좁은 화면에서는 한 줄 전체를 비율에 맞춰 축소하고 줄바꿈하지 않음
   - 체감온도 아래에 `{하늘 상태} 체감 상 {감각} 느껴질 수 있어요.` 형식의 안내와 하늘 상태 아이콘 표시. 바로 위 지표에 있는 체감온도 숫자와 계산 근거는 반복하지 않음
   - 체감 안내는 13pt 글자로 표시하고 작은 화면에서도 말줄임 없이 자연스럽게 줄바꿈
   - 숫자는 기상청 계절별 체감온도 산식, 표현은 한국인 PT 감각 경계와 기상청 `33/35/38℃` 위험값을 함께 사용
   - `어제와 비교` 영역에서 선택 격자의 다음 시간 단기예보와 같은 시각의 어제 초단기실황 기온·체감온도 차이를 단위와 함께 표시. 각 비교 문장은 한 줄로 표시하고 작은 `어제 N℃` 글씨는 Spacer 뒤 행 오른쪽 끝에 정렬
   - 오늘 예보시각과 어제 실황시각을 같이 표시하며, 비교값을 상단 현재 초단기실황으로 대체하지 않음
   - 어제와 오늘의 하늘 상태가 모두 있으면 `어제 맑음 · 오늘 구름 많음`처럼 함께 표시
   - 비교할 어제 실황을 받지 못했거나 운영 서버 미연결이면 비교 자료를 받을 수 있을 때 표시된다고 안내
   - 자외선·대기질·가시거리·습도·바람·일출·일몰의 현재 요약 지표는 표시하지 않음. 시간별 자외선·습도·바람은 아래 선택형 타임라인에서 확인

### 선택형 타임라인

   - 날씨·강수·강설·자외선·바람·습도 ChoiceChip을 가로 한 줄로 배치하고, 선택한 항목의 당일 00~23시 24칸을 카드 안에서 가로 스크롤로 표시. 자료가 없는 시각은 결측으로 표시
   - 날씨 아이콘 아래에 기온을 표시하고 `(체감 19°C)`는 다음 줄의 보조 문구로 표시
   - 강수확률은 작은 물방울의 넓은 아래쪽 안에 표시하고, 강수량은 항목명 없이 보조 글씨로 수치만 아래에 표시
   - 강설은 별도 항목에서 눈 예보 여부와 해당 1시간의 예상 신적설을 표시하며 `미만`·`범위`·`이상` 의미를 보존. 다른 색의 `현재 적설량` 관측선을 함께 표시하고 두 cm 선은 같은 왼쪽 축, 기존 강설확률은 오른쪽 % 축을 사용한다. Main·Week의 관측 당일에 같은 관측소의 시간별 마지막 실제 관측을 표시하며 미래·결측을 채우지 않는다. 수치끼리와 인접한 두 선분의 겹침을 피한다. 기존 총 적설 정기 수집을 시간별로 보관하므로 추가 외부 호출은 없으며 적용 직후에는 이력이 적을 수 있다.
   - 자외선 수치를 해 아이콘 중앙에 크게 표시하고 아래에 `낮음`·`보통` 등 단계를 보조 글씨로 표시. 지수가 강할수록 아이콘·글자색을 붉게 표시
   - 바람은 기존 아이콘 아래에 `약한 바람` 같은 상태를 값 글씨로 표시하고, 풍향·풍속은 한 줄의 보조 글씨로 표시
   - 습도는 물컵 안의 물 높이와 내부 수치로 표시. 50% 초과는 채워진 아래쪽에 밝은 글씨, 50% 이하는 빈 위쪽에 어두운 글씨로 표시하고, 컵 아래에 `쾌적`·`습한 편` 같은 상태를 값 글씨로 표시
   - 다음 날 날씨 시각은 표시하지 않는다. 강수·강설은 구간 시작 시각의 칸에 배치하며, 다음 날 00시 예보가 오늘 23~24시 구간이면 오늘 23시 칸에 표시
   - 안내 버튼을 누르면 정시·강수 구간과 자료 제공 범위 설명을 팝업으로 표시. 자외선지수 0은 실제 값으로, 결측은 `—`로 구분

### 레이아웃 규칙

- Check List 아래에서 선택형 타임라인을 표시한다.
- 기온·체감온도 그래프가 함께 있는 시각에는 실제 점의 높이를 비교해 높은 선의 수치는 두 선 위로, 낮은 선의 수치는 두 선 아래로 배치한다. 기온의 날씨 아이콘과 수치는 같은 쪽에 묶어 두며, 양옆 연속 선분과도 겹치지 않게 간격을 둔다. 두 값이 같으면 기온 아이콘·수치는 위, 체감 수치는 아래에 표시한다. 글자 크기에 맞춰 그래프 상하 여백을 확보해 아이콘 잘림과 시간 눈금 겹침도 방지한다. 결측 시에는 존재하는 값만 표시하며 같은 그래프를 사용하는 Week에도 적용한다.
- `CustomScrollView`, `SliverPadding`, `SliverList`로 상단 카드·Check List를 자연 높이로 배치한다.
- 콘텐츠가 화면 높이를 넘으면 Main 전체를 아래 방향으로 스크롤할 수 있으며, 최상단에서는 당겨서 새로고침할 수 있다.
- 화면 너비가 380px 미만이면 compact 레이아웃을 사용한다.
  - 카드 간격과 내부 여백 축소
  - 일부 글자와 아이콘 크기 축소
- 상단 날씨 카드와 Check List에 고정 높이 비율을 배정하지 않는다.

### 데이터 및 동작

- `TodayWeatherResponse`의 `region`, `brief`, `current`, `recommendations`, `timeline`, `hourly`를 사용한다.
- 첫 진입은 경량 Main 응답의 `brief`, `current`만으로 상단 카드를 먼저 표시하고, 전체 Today 응답이 오기 전까지 Check List 자리에 진행 상태를 표시한다.
- 상단 `TodayWeatherResponse.current`의 기온·습도·풍속은 선택 격자의 기상청 초단기실황을 사용하고, 체감온도도 같은 실황값으로 계산한다. 관측 시각과 `OBSERVATION` 역할을 표시한다. 하늘 상태는 단기예보, 자외선·대기질·시정은 각 별도 자료를 병합한다.
- 초단기실황이 없거나 현재보다 5분 넘게 미래이거나 2시간을 초과해 오래되면 단기예보 기온으로 대체하지 않고 현재 기온·체감온도·습도·풍속을 결측으로 표시한다.
- `comparison/yesterday`는 선택 격자의 현재 시각 이후 가장 가까운 단기예보와 그 예보시각에서 24시간 전의 초단기실황을 반환한다. 이 응답은 Main 상단 날씨 카드 안의 `어제와 비교` 영역에서 사용한다.

- `environmentalSources`로 자외선·대기질의 실시간 조회/캐시/stale/미지원 상태를 구분하며, 환경 Provider 실패는 단기예보 응답 전체를 실패시키지 않는다.

- 강수 장면과 행동 판단은 Today 상세 자료의 강조 기준과 같은 강수확률 40%부터 적용한다.
- 날씨 상태 문자열로 Main의 mood를 결정한다.
- Setting에서 확인한 GPS 위치의 기상청 격자 또는 저장된 수동 지역 격자로 조회한다. 위치 확인 실패나 수동 지역 미선택 시 수원 등 다른 지역으로 대체하지 않는다.

## 3. Today 탭

### 목적

현재 날씨 수치와 지표별 상세 설명을 확인하는 탭이다.

### 화면 구성 순서

1. **페이지 헤더**
   - `TODAY`
   - `오늘 하루`
   - `현재 날씨를 자세히 확인해요`
2. **현재 상세 날씨 카드**
   - 별도의 기온·날씨 설명·날씨 아이콘·체감온도 행은 표시하지 않음
   - 체감온도·습도·자외선·바람·대기질·대기정체·가시거리·꽃가루·강수량·적설량·일출/일몰 순서로 지표를 카드에 표시
   - 꽃가루는 제공 기간에 참나무·소나무·잡초류의 공식 단계를 종별로 표시하고, 제공 기간 밖은 `제공 기간 밖`으로 구분한다. 대기정체는 공식 예측 단계를 미세먼지 등급과 별도로 표시한다.
   - 각 지표의 정보 버튼을 누르면 상단 강조 영역에 표시값·수준·자료 출처와 관측 정보를, 구분선 아래에 표현 기준·해석·한계를 설명함. 체감온도·대기질·강수량·적설량은 수치 경계를, 꽃가루·대기정체는 원자료의 단계 사용 기준을, 일출/일몰은 시각 표시 기준을 안내. 자료 로딩 중에도 표현 기준은 확인할 수 있음
   - 미세먼지는 측정소 이름과 관측 시각만 밝히며 사용자 위치 직접 측정 여부를 반복 안내하지 않음
   - 현재 대기질은 제공된 PM2.5·PM10·오존 관측값의 등급 중 가장 나쁜 등급을 표시하며, 상세에 각 관측값과 공식 통합대기환경지수가 아니라는 점을 밝힘
   - 체감온도는 감각 표현과 ℃ 값을 함께 표시. 강수량은 선택 격자의 지난 1시간 기상청 관측 `RN1` 값을 mm와 함께 `강수 없음`·`적은 비`·`보통 비`·`많은 비`·`폭우` 등으로 표시한다. 눈·비눈 또는 강수 형태가 불명확하면 비 대신 강수로 표현한다. 비의 양 표현은 3·15·30mm 경계를 사용하며 특보 단계가 아니다. 강수 예보값이나 별도 레이더 현재 비 판단으로 관측값을 대신 채우지 않는다.
   - 비의 양 구간은 [기상청 예보용어해설](https://www.weather.go.kr/w/resources/pdf/forecast_terms_list_20250611.pdf)의 시간당 강수량 경계를 참고한다. `폭우`는 앱의 쉬운 표현이며 공식 특보 명칭이 아니다.
   - 적설량은 가까운 기상청 관측소의 현재 총 적설 깊이를 cm와 함께 `쌓인 눈 없음`·`조금 쌓임`·`제법 쌓임`·`많이 쌓임`·`폭설`로 표시한다. 양수 값의 경계는 1·5·20cm로 앱 표시용이며 `폭설`은 대설 특보를 뜻하지 않는다. 상세에 관측소·거리·실제 관측 시각을 밝히고 예상 신적설과 구분한다.
   - 일출과 줄바꿈된 일몰 시각은 동일한 글꼴·크기·굵기로 표시한다.
   - 결측값은 `자료 없음`으로 유지하고 실제 0과 구분하며, PM2.5와 PM10은 서로 대체하지 않음

### 데이터 및 동작

- `TodayWeatherResponse.current`와 `livingIndices`를 사용하며 서버가 중앙 수집한 자료만 표시한다.
- Today는 준비물 체크 상태를 변경하지 않는다. 실제 챙김 여부 확인은 Main의 Check List가 담당한다.
- 전체 화면은 세로 스크롤이며 당겨서 새로고침할 수 있다.

### 현재 한계 및 확인 포인트

- [x] 현재 상세 날씨 카드를 Today 최상단으로 이동
- [x] 별도 상단 행을 제거하고 체감온도를 지표 첫 항목으로 표시하며 펼침형 상세 설명 유지
- [x] 선택형 타임라인을 Main으로 이동하고 현재 상세 날씨 카드 유지

## 4. Today 하단 상세 자료

### 목적

오늘의 생활행동과 그 판단 근거·자료를 Today 하단에서 확인한다.

### 화면 구성 순서

1. **상세 자료 상자**
   - 서버 `lifestyleMessages`의 생활항목 하나를 카드 하나로 구성하고 전체 항목을 표시
    - 각 항목은 기본적으로 닫혀 있다. `유효` 기간 아래의 `체크할 일`은 배경색으로 구분해 항상 표시하고, 열면 `판단 근거`, `계산 근거`, `사용한 자료`, `자료 상태`를 역할별로 표시
   - `판단 근거`의 앱 내부 출처는 제품명 대신 `앱 자체 분석`으로 표시
   - 공식 자료에 제공자와 유효기간이 있으면 사람이 읽는 한국시간 메타정보로 함께 표시
   - 선택·알림과 연결된 근거는 먼저 배치하고 첫 일치 항목을 강조. 그 외 순서는 서버 응답 순서를 유지
   - 요청한 근거가 최신 자료에 없으면 `선택한 항목의 근거가 현재 자료에 없어요` 또는 `이 알림과 연결된 근거가 현재 자료에 없어요`로 구분. 다른 항목을 대신 강조하거나 위험이 해소됐다고 판단하지 않음
   - `itemTitle`로 생활항목과 연결되는 `dataStatusMessages`만 같은 항목 카드에 배치하고, 연결되지 않는 상태를 다른 항목에 임의 배정하지 않음
   - 생활항목이 없으면 체크 항목과 근거가 없다는 빈 상태를 표시하고, 운영 서버 미연결 시 미지원 카드로 교체

### 데이터 및 동작

- `TodayWeatherResponse.lifestyleMessages`, `dataStatusMessages`를 사용한다. 근거 목록은 준비물 추천 목록과 별개다.
- 서버가 한 `LifestyleMessage` 안에 제공한 행동과 근거만 같은 세트로 묶는다. 서로 다른 생활항목이나 제목이 없는 자료 상태를 임의로 결합하지 않는다.
- Main 타임라인과 Today 상세 자료의 생활 판단·공식 근거, 비가 그치는 시간, 빨래 마감, 우산·폭설 알림도 강수 구간을 사용한다. 이미 종료된 강수는 미래 행동 판단에서 제외하며 원본 시간별 예보는 유지한다. 산책은 해당 정시부터의 강수 구간과 기온·바람을 맞춰 비교하고, 대응 자료가 없으면 추천하지 않는다.
- [기상청 시간 안내](https://www.kma.go.kr/w/iframe/dfs.do)의 강수량·강수확률·날씨는 이전 1시간, 기온·바람은 정시 기준이다. 1시간 신적설(SNO)은 [기상청 API허브 요소 정의](https://apihub.kma.go.kr/apiList.do?seqApi=10)를 함께 참고한다.
- 서버 응답의 시간별 숫자 결측·비정상 형식·비유한 값은 0으로 대체하지 않는다. 명시된 `false`와 알 수 없는 눈 예상 상태도 구분한다.
- `forecastAt`/이전 `observedAt`에 시간대가 있으면 한국시간으로 변환해 날짜 경계를 판별한다. 시간대 없는 기상청 날짜·시각은 한국시간으로 읽는다.
- 직접 조회에서도 TMP가 빠졌더라도 다른 시간별 자료가 있는 슬롯은 유지한다. TMN/TMX 전용 슬롯은 제외하며, 기온 결측은 일 최저·최고 계산에서 제외한다.
- 전체 화면은 세로 스크롤이며 당겨서 새로고침할 수 있다.
- Main 준비물의 정보 버튼으로 이동하면 관련 근거를 우선 배치하고 펼친 뒤 자동 스크롤하며 `선택한 항목의 근거`로 강조한다.

### 현재 한계 및 확인 포인트

- [x] 상세 자료를 Detail에서 Today 하단으로 이동하고 비게 된 Detail 탭 제거
- [x] 생활항목별 체크할 일과 근거·자료를 한 세트로 구성
- [x] 공통 자료상태를 특정 생활항목과 분리하고 전체 원문 표시
- [x] 빈 항목·선택 근거 부재·운영 서버 미연결 상태 구분
- [x] Main에서 선택한 준비물을 관련 Today 근거에 연결
- [x] 알림·선택 항목을 첫 카드로 배치하고 자동 스크롤·강조 유지

## 5. Week 탭

### 목적

현재 한국 날짜가 속한 주의 일요일부터 토요일까지 날씨와 대표 준비물을 확인하는 탭이다.

### 화면 구성 순서

1. **페이지 헤더**
   - `WEEK`
   - `이번 주` (하단 탐색 이름 `Week` 유지)
   - 현재 주의 달력 범위와 `일~토`: 예) `9월 6일~9월 12일 · 일~토`
   - 연도가 바뀌는 주는 양쪽 연도를 표시한다.
2. **주간 날씨 요약**
   - 강수·기온·준비물을 세 행으로 배치하고 각 행을 아이콘 + 제목 + 내용 순으로 표시한다.
   - 강수에는 강수일·최고 강수량, 기온에는 최저·최고기온, 준비물에는 필요한 일수·예상 종류를 넣는다.
   - 항목명보다 값을 굵고 진하게 표시한다. 요약 강수량의 관측값에는 `(관측)`을 붙이지 않고, 검증된 날짜별 누적량이 없으면 `자료 없음`으로 표시한다. 준비물은 지난 날짜를 제외하고 집계한다.
   - 준비물 행은 `1일 · 우산, 마스크`처럼 일수와 목록을 가운뎃점으로, 준비물 종류를 쉼표로 구분한다.
3. **소형 네이티브 광고**
   - 주간 날씨 요약과 날짜별 카드 사이에 표시하고, 광고와 날짜 제목 사이에 24px 여백을 둔다.
4. **일~토 날짜별 카드**
   - 현재 주의 일요일부터 토요일까지 7개 슬롯 중 한 장만 표시한다. 처음에는 오늘 카드를 열고, 카드 양옆의 작은 좌우 화살표 또는 카드의 좌우 스와이프로 날짜를 넘긴다. `현재 순서 / 7` 대신 광고 아래·카드 위 중앙에 월·일·요일을 표시한다.
   - 월·일·요일: 예) `9월 10일 (목)`. 카드 내부 상단에는 예보 출처와 오늘·지난 날짜 표시만 둔다.
   - 한국시간 실제 날짜에는 카드 우측 끝에 `오늘`, 지난 날짜에는 같은 위치에 `지난 날짜`를 표시
   - 당일·미래 날짜에는 단기·중기예보 출처 배지를 표시하고 지난 날짜에는 출처 문구를 표시하지 않는다.
   - 날씨 아이콘과 상태
   - 대표 준비물 최대 3개를 읽기 쉬운 크기의 아이콘·글자로 표시한다.
   - 빈 준비물 추천 목록은 문구 없이 두고, 추천 미수신·잘못된 목록만 `준비물 추천 자료 없음`으로 구분한다. 지난 날짜에는 준비물 추천을 표시하지 않는다.
   - 운영 서버 미연결 시 준비물 미지원 안내만 표시하고 남아 있는 추천 배지는 숨긴다.
   - `최저 N℃ · 최고 N℃`를 별도 줄에 표시한다. 한쪽만 없으면 해당 항목만 `자료 없음`으로 표시한다.
   - 시간대별 기온은 `받은 시간대 기준 최저·최고`로 짧게 안내한다.
   - 당일·미래의 강수는 `강수확률 최고 N% · 강수량 Nmm` 형태로 표시한다. 한 값만 있으면 다른 값은 `자료 없음`, 둘 다 없으면 `강수 자료 없음`으로 표시한다. 확률은 받은 시간대 중 최고치이며 하루 전체 확률이 아니다. 지난 날짜에 실제 강수 관측량이 0이거나 없으면 강수 항목을 숨긴다.
   - 당일·미래 날짜의 습도·풍속·신적설·자외선·대기 상태는 테두리·그림자가 있는 선택 칩으로 표시하며, 항목명보다 상태 값을 굵게 표시한다. 누르면 원래 수치 또는 항목별 등급을 팝업으로 보여준다. 주간 대기질 예보에 농도 수치는 없으므로 팝업에서 자료 부재를 밝힌다.
   - 해당 날짜의 시간 자료가 있으면 준비물 아래에 여백과 연한 구분선을 두고, 시계 아이콘이 붙은 선택형 시간별 예보를 표시한다. Today 응답의 시간별 날씨·기온/체감온도·강수·강설·자외선·바람·습도 중 값이 있는 항목과 시간대만 노출한다. 시간별로 표시 가능한 습도·바람·신적설·자외선은 중복되는 일별 칩을 숨기고, 시간값이 없는 항목의 일별 칩과 대기 상태 칩은 유지한다. Today의 48칸 범위 밖에서 Week가 1시간 강수 상세를 제공하면 강수 시간대도 표시한다. 자료가 없는 시간대를 뒤에 채우지 않는다. 지난 날짜는 시간별 예보를 표시하지 않으며, 일별 값이 있는 칩만 유지한다.
   - 강수 카드의 `강수확률`·`강수량`은 보통 굵기로, 값은 굵게 표시하고 전체 글씨를 작게 표시한다.

### 데이터 및 동작

- `WeeklyWeatherResponse.days`에서 현재 주에 속하고 날짜가 유효한 항목만 정확한 요일 슬롯에 연결한다.
- 서버는 단기예보를 우선하고 4~10일 뒤의 빈 날짜는 중기 기온·육상예보로 채운다. 겹친 날짜의 단기예보가 공식 일 최저·최고 없이 일부 시간값만 가진 경우에는 완전한 중기 일 예보를 사용한다.
- 지난 날짜는 기상청 지상·AWS 일통계에서 인근 유효 관측소의 실제 최저·최고기온·일강수량·일 최심신적설을 조회한다. GPS가 있으면 실제 좌표를 우선한다. 지난 날의 준비물은 추천하지 않으며 카드에서는 자료출처 문구를 숨긴다. 현재 지면의 총 적설량과 구분한다.
- 앱에서 `현재 적설`은 기존 눈을 포함해 관측소 지면에 쌓여 있는 눈의 깊이다. Today는 전용 관측 자료를 표시하고, 시간별·주간 눈 예보는 `예상 신적설`, 과거 일관측은 `최심신적설`로 표시한다. 기존 예보·일관측 값으로 현재 적설을 대신 만들지 않는다.
- 지난 날짜에 실제 일관측을 받지 못하면 결측으로 남겨두며 저장된 예보값으로 채우지 않는다. 앱도 관측 출처가 아닌 지난 날짜 항목은 표시하지 않는다.
- 단기와 중기 Provider는 독립적으로 처리한다. 한쪽이 실패해도 다른 쪽 자료를 표시하고, 두 예보가 모두 없으면 해당 미래 날짜를 정상 날씨로 추정하지 않는다.
- 서버는 기존 요일 `date`를 유지하고 `forecastDate: YYYY-MM-DD`를 추가로 제공한다. 직접 기상청 조회도 같은 달력 날짜를 유지한다. 구버전 서버의 요일만으로 달력 날짜를 추정하지 않는다.
- 날짜가 없거나 유효하지 않은 서버 항목은 임의 요일에 끼워 넣지 않는다. 같은 날짜가 중복돼도 하나를 임의 선택하지 않는다.
- 서버의 날짜별 준비물은 해당 날짜의 시간대별 기상청 체감온도로 계산한다. 시간대별 체감값이 없을 때 일 최고기온을 체감온도로 대입하지 않는다.
- 날씨·기온의 결측을 맑음·0으로 보충하지 않는다. 알 수 없는 날씨 문구, 빈 문자열, 비유한 수, 뒤집힌 최저·최고는 유효한 값으로 사용하지 않는다. 실제 0℃·영하기온은 보존한다.
- 지난 날짜는 카드 전체에 투명도나 색상 필터 레이어를 씌우지 않고 카드·글자·아이콘 색을 직접 회색으로 지정해 스크롤 화면의 합성 오류를 피한다.
- 비/눈 집계는 지원하는 기상청 현상명으로만 판별한다. 부분 자료라도 확인된 강수는 포함하지만, 일부 시간대 또는 상태 메타데이터가 빠진 맑음·흐림 자료를 무강수로 확정하지 않는다. `weatherDataComplete`는 받은 첫~마지막 슬롯 사이의 자료 완전성이지 하루 24시간 전체를 보장하는 값이 아니다.
- 서버와 직접 조회가 `weatherDataComplete`, `minTemperatureSource/maxTemperatureSource` (`DAILY`/`HOURLY`)를 전달한다. 서버는 기온만 빠진 시간대도 보존하고, 빠진 PTY·SKY와 공백 숫자를 무강수·맑음·0으로 만들지 않는다. 기존 날짜·요일·기온 응답 형식은 유지한다.
- 날짜별 `precipitationDetail`에 1시간 예보(`HOURLY`)와 연장 예보(`EXTENDED`)를 구분한다. `hours`는 `forecastAt`(구간 종료), `probability`, 원문 `amountText`를 전달한다. Today의 48개 제한 전 전체 자료를 사용하며 기존 API 필드는 유지한다.
- 강수량·강수확률의 1시간 자료는 표기 시각의 이전 1시간에 해당한다. 자정 자료는 전날 23~24시로 배정하고, 날짜·중복·시간 오류가 있으면 합산하지 않는다. [기상청 예보 요소별 시간 안내](https://www.kma.go.kr/w/iframe/dfs.do).
- 받은 첫~마지막 구간만 합산하며, 중간 시간이나 강수량이 빠지면 부분합을 전체 예상량으로 표시하지 않는다. 24시간 미만은 `하루 중 일부 시간`을 명시한다. 확률 자료의 완전성은 강수량과 독립적으로 계산한다.
- 합산은 `미만`의 열린 상한·`이상`의 열린 범위·수치 범위를 유지한다. 예: `1mm 미만 + 1mm 미만 → 2mm 미만`, `5mm + 1mm 미만 → 5mm 이상 6mm 미만`. 음수·오류 문자열·역전 범위·단위 없는 양수 코드를 mm로 읽지 않는다. 모든 날짜 카드에 같은 앱 계산을 적용한다.
- 오전~14시 발표의 글피, 17시 이후 발표의 그글피는 연장 예보로 구분한다. 확인된 시간대의 확률 최고값만 표시하고, 정성 단계인 강수량은 mm 합계를 계산하지 않는다고 안내한다. [기상자료개방포털 단기예보 설명](https://data.kma.go.kr/data/rmt/rmtList.do?code=420&pgmNo=572).
- 날짜 미확인 및 중복 날짜는 요약에서 제외하고 제외 내역을 알린다. 누락 날짜·중복 값 중 하나를 임의로 골라 집계하지 않는다.
- 준비물은 `recommended: true`인 알려진 종류만 중복을 제거해 표시한다. 비활성 추천을 제거한 뒤 최대 3개를 선택한다. 잘못된 종류를 우산으로 대체하지 않으며 일부 추천이 손상돼도 유효한 추천은 유지하고 상태를 안내한다.
- `forecastDate`와 한국시간 오늘 날짜를 비교한다. 한국시간 자정 및 앱 복귀 시 다시 판단하며, 기기 시간대·목록 순서에 의존하지 않는다. 체크리스트와 한국시간 날짜 계산 함수를 공유한다.
- 단기·중기예보, 실제 관측, 저장 예보에 모두 없는 슬롯은 날짜 자체는 유지하되 날씨를 만들지 않는다.
- 서버는 02·05·08·11·14시 발표분의 오늘~글피 최대 4개 날짜와 17·20·23시 발표분의 오늘~그글피 최대 5개 날짜를 모두 보존한다. 기존 4개 절단으로 저녁 발표분의 다섯 번째 날짜가 버려지지 않게 한다.
- 빈 목록에도 일~토 7개 날짜 자리를 표시하지만 0일 요약·맑음·준비물 없음으로 해석하지 않는다.
- 운영 서버 자료를 받지 못하면 날짜별 날씨를 임의로 대체하지 않고 조회 상태 안내를 표시한다.
- 전체 화면은 세로 스크롤이며 당겨서 새로고침할 수 있다.

## 6. Setting 탭

### 목적

알림 종류를 설정하고 데이터 저장·기기 권한 상태 및 데이터 권한 안내를 확인하는 탭이다. 지역 선택은 Main 상단에서 한다.

### 화면 구성 순서

1. **페이지 헤더**
   - `SETTING`
   - `설정`
   - `필요한 알림과 데이터 사용을 설정할 수 있어요.`
   - 설정 아이콘 표시
2. **지역 선택 안내**
   - 설정 최상위의 지역 메뉴는 제거했다. Main 상단에서 현재 위치와 저장한 구역을 전환하고 구역을 추가한다.
   - `위치 권한은 어디에 쓰이나요?`는 데이터 권한 안내에서 연다.
3. **테마**
   - 라이트·다크·시스템 설정에 따름 중 하나를 선택한다.
   - 현재 선택한 테마를 설정 메뉴에 표시하고 기기에 저장한다. 시스템 설정에 따름은 기기 밝기 변경을 반영한다.
4. **알림**
   - 최상위 `알림` 메뉴에서 알림 시간과 받을 날씨·생활 알림을 한 화면에 설정한다.
5. **날씨 알림**
   - 끄면 하위 준비물/주의 알림 스위치가 비활성화된다.
   - 알림 시간 영역도 흐리게 표시되고 입력을 받지 않는다.
6. **알림 시간**
   - 기본값 `07:00`
   - 시간 선택 대화상자로 변경하고 로컬·서버에 저장한다.
   - 준비물 요약에만 적용됨을 명시하고 `설정 시각`으로 표시한다. 실제 서버 확인 시각은 다음 10분 경계로 안내한다(07:35 → 07:40, 23:55 → 다음 날 00:00). 저장값은 그대로 보존하고 도착 시각을 보장하지 않는다.
   - 준비물 요약을 껐으면 켜야 적용된다고 안내한다.
7. **챙겨요 알림**
   - 우산
   - 양산
   - 겉옷
   - 마스크
   - 물
   - 선크림
   - 준비물 요약에 포함할 항목을 선택한다. 우산 스위치는 현재 비 안내에도 함께 적용됨을 명시한다.
   - 현재 서버의 준비물 추천 6종과 일치하므로 연결되지 않은 스위치는 추가하지 않음
   - 우비·장화·장갑·모자는 향후 서버 추천 타입과 판단 기준이 추가될 때 검토
8. **기상·생활 알림**
   - `발효된 공식 정보와 생활 준비 알림을 관리해요`
   - 호우특보 안내: 발효 상태 진입·단계 변경·해제
   - 대설·많은 눈 안내: 발효 특보와 예보 기반 많은 눈 대비 별도 알림
   - 폭염특보 안내: 발효 상태 진입·단계 변경·해제
   - 한파특보 안내: 발효 상태 진입·단계 변경·해제
   - 현재 비 안내: 관측분석·레이더가 일치한 현재 비이며 우산 켜짐·등록된 정밀 위치 필요. 소나기 예보 알림으로 설명하지 않는다.
   - 준비물 요약 알림: 설정 시간에 하루 한 번, 현재부터 한국시간 오늘 자정까지의 예보로 준비물 최대 3개를 같은 항목 배분·우선순위로 요약한다. 저녁 비·눈도 아침부터 시작/종료 시각과 우산을 먼저 안내하며, 안개 등 대표 브리핑이 준비물 내용을 대체하지 않는다. 항목별 알림 설정을 제외한 뒤 물품을 배분한다. 준비물이 없으면 기존 유효 날씨 브리핑 경로를 사용한다.
   - 블랙아이스·도로통제·그 밖의 공식 특보는 개별 스위치 없이 전체 알림 설정을 따른다고 안내한다.
9. **데이터 저장·기기 권한 상태**
   - `데이터 상태`와 `기기 권한 상태`로 구성한다. 기존 데이터 상태의 저장 결과·재시도 기능은 유지한다.
   - 확인 중 / 저장 중 / 기기 저장 실패 / 기기 저장 완료·서버 반영 미확인 / 양쪽 저장 완료를 구분한다.
   - 실패 시 `설정 저장 다시 시도`로 현재 선택된 최신 설정을 재전송한다. 서버 반영 미확인에는 이전 설정으로 알림이 발송될 수 있다고 알린다.
   - 기기 알림 권한 확인 중 / 미요청 / 미허용 / 영구 차단 / 허용 / 조용한 알림만 허용 / 확인 실패를 구분한다.
   - 기기 권한 상태에는 ‘기기 권한 상태를 확인해요’ 안내와 `앱 알림`·`백그라운드 위치 갱신`을 배치한다. 앱 알림이 미요청·미허용·영구 차단일 때만 `권한 다시 확인`을 표시한다. 미요청·미허용은 권한을 요청하고, 영구 차단은 기기 앱 설정을 연다. 허용·조용한 알림 허용·조회 중·조회 실패에는 버튼을 숨기고 해당 상태 안내를 표시한다. 권한 변경은 열린 상세 화면에도 반영한다.
   - 기존 설정 목록의 백그라운드 위치 갱신 박스를 이 화면 안으로 옮긴다. 켜기·끄기, 최초 사용 동의, GPS·전체 알림·서버 사용 조건과 Android 실행 알림 표시 설정을 유지한다. 기능이 켜지고 사용 가능하며 위치 권한이 필요한 상태에서만 재확인 버튼을 표시한다. 정상 이동 감지 중이면 권한 허용 안내를 표시한다. 기능 꺼짐·위치 기능 꺼짐·오류·미지원은 허용으로 표시하지 않는다.
   - 두 항목 아래 구분선 다음에 `기기 앱 설정 열기`를 배치한다. 하단 물음표 도움말은 데이터 저장과 알림·위치 권한의 차이 및 백그라운드 위치 갱신의 동의·동작 조건을 안내한다.
   - 앱 알림·백그라운드 위치 갱신 제목은 14px 굵은 글씨와 배경 없는 18px 아이콘으로 통일하고 하위 설명은 12px로 맞춘다. Android 실행 알림 표시 설정은 왼쪽 여백 8px의 배경 박스로 표시하고 그 아래에 위치 권한 다시 확인 버튼을 배치한다. 박스 제목 11px·설명 10px를 사용하며 사용자 글씨 배율은 유지한다.
   - 앱 전체 알림 스위치와 기기 권한은 별개다. 전체 알림을 껐어도 OS 권한을 허용으로 표시할 수 있으며, 서버 반영 전 또는 이미 처리 중인 알림은 도착할 수 있다고 안내한다.
   - 서버 저장/권한 허용을 실제 수신 성공으로 표시하지 않는다. 개별 알림 종류·소리·집중 모드는 이 상태로 판별하지 않는다.
10. **데이터 권한 안내**
   - 데이터 출처·위치 권한·알림 권한·저장/전송 정보 화면으로 연결한다.
   - 예보·자외선·특보 외에 관측분석/레이더·오존·도로 결빙 가능정보·ITS 통제를 포함한다. 공식 기관 링크를 외부 브라우저로 열고 실패 시 주소 복사를 제공한다.
   - 위치 미확인과 서버 등록 정보 삭제, 앱 알림 끄기와 기기 권한을 구분한다. 기능 설명을 법적 개인정보처리방침으로 표시하지 않는다.

### 데이터 및 동작

- 모든 초기 스위치는 켜짐 상태이고 위치 모드는 GPS, 알림 시간은 07:00이다.
- 전체 알림을 끄면 알림 시간과 모든 하위 스위치는 비활성화되지만 각 하위 값은 보존된다.
- 설정은 Home에 전달되어 로컬 저장과 서버 동기화 큐를 통해 저장된다. 시작 시 저장된 설정과 설치 ID를 복구한다. 서버 저장 지연·실패는 로컬 GPS 확인을 막지 않는다.
- 큐는 요청 순서를 보존하되 최신 변경 결과만 상태로 표시한다. 기기 저장의 실패 반환값도 처리한다. 서버 저장 실패를 숨기지 않고 수동 재시도·다음 시작·다음 변경 때 다시 동기화한다. 날씨 조회나 오류 대화상자가 설정 저장 큐를 막지 않는다.
- 알림 설정 API의 strict 스키마에 맞춰 전체 알림·시간·6종 준비물·6종 기상/날씨 토글의 14필드만 보낸다. 설치 ID는 URL 경로, 위치 모드와 격자는 별도의 설치 등록 API로 전달한다. 이전 앱은 로컬 설정 전체를 보내 HTTP 400을 받을 수 있었으며 이번에 바로잡았다.
- 알림 권한은 실행·새로고침·기기 설정 복귀 시 읽고, 미요청·미허용 상태에서 사용자가 앱 알림의 `권한 다시 확인`을 눌렀을 때 요청한다. GPS 없이 수동 지역이거나 위치가 없어도 권한을 확인할 수 있다. 조회 중 복귀하면 다시 읽어 늦은 이전 결과를 사용하지 않는다.
- 권한 변경 뒤 유효한 지역이 있으면 FCM 설치 등록도 갱신한다. 등록 큐에서 최신 권한을 읽고 허용되지 않았으면 토큰을 null로 전송한다. 등록 요청 성공/토큰 발급/실제 푸시 수신 여부는 이번 상태 카드의 판정 범위가 아니다.
- 권한 의미는 설치된 `firebase_messaging 16.6.0`/플랫폼 인터페이스 `4.10.0`과 [Firebase Flutter 알림 권한 안내](https://firebase.google.com/docs/cloud-messaging/flutter/receive)를 확인했다. 설치 버전은 Android `deniedPermanently`도 반환한다. iOS의 거부는 별도 영구 차단 값이 아니므로 거부 상태에도 앱 설정 버튼을 제공한다.
- GPS는 앱 실행·백그라운드에서 복귀·당겨서 새로고침·명시적 재확인 시 읽는다. 실행·복귀·새로고침에서는 기존 권한만 확인하고, 권한 요청은 확인 버튼이나 GPS 모드 선택 때만 한다. 설정에서 별도 동의한 ‘이동 시 알림 지역 갱신’과 항상 위치 권한·GPS 모드·전체 알림·서버 사용이 켜져 있으면 iOS 큰 위치 변화 감지와 Android 저전력 위치 이벤트로 서버 알림 지역도 갱신한다. 기본은 꺼짐이며 수동 지역·전체 알림 끄기·기능 끄기·서버 삭제 시 감시를 중지한다. 감지 주기는 보장하지 않는다.
- 위치 확인 시간 제한은 8초다. 측정 시각이 2분보다 오래되거나 1분 넘게 미래이면 현재 위치로 사용하지 않는다. 이 값은 앱의 위치 자료 신선도 기준이며 날씨 체감·정확도 기준이 아니다.
- 기기 정밀 위치 권한과 유효한 측정 정확도(0m 초과, 500m 이하)가 함께 확인될 때만 정밀 분석 좌표를 전송한다. 나머지는 대략적 위치로 지역 격자만 사용한다. 이는 500m 기상자료 정확도를 보장하는 값이 아니다.
- 정밀 GPS 좌표는 기기 운영체제의 역지오코딩에도 전달해 Main 지역명을 `서울 강남구 역삼동` 또는 `수원시 팔달구 인계동` 형태로 표시한다. 첫 주소가 시·구까지만 반환돼도 전체 주소 후보와 도로 주소를 계속 확인해 동·읍·면이 포함된 이름을 우선한다. 도 단위 이름은 상세 시·군이 있으면 생략하고 특별시·광역시는 짧게 표시한다. 운영체제가 어떤 후보에도 동·읍·면을 제공하지 않은 경우에만 확인된 시·구를 대체 표시한다.
- 대략적 위치는 동을 판별할 정밀도가 아니므로 역지오코딩하지 않는다. GPS 화면은 기기 주소 변환 결과와 서버가 좌표·행정경계 또는 예보 격자로 확인한 지역명을 함께 사용하며, 확인된 동·읍·면 이름을 시·구보다 우선한다. 기기 조회 실패·지연이 이미 받은 서버 지역명을 `현재 위치`로 덮어쓰지 않는다. 둘 다 지역명을 확인하지 못한 경우에만 `현재 위치`를 표시하고 서버의 `선택 지역` 같은 임시 문구는 제외한다. 역지오코딩 이름은 화면 표시용이며 로컬 저장이나 서버 등록 필드에 추가하지 않는다.
- 좌표는 현재 서버의 지원 범위(위도 30~44, 경도 120~134)에 맞춰 검사한다. 이 사각 범위가 대한민국 행정 경계 검증을 뜻하지는 않는다.
- 위치 모드/저장 지역이 바뀌면 이전 위치·날씨를 비우고 새 지역을 조회한다. 진행 중인 이전 위치/날씨 응답은 새 지역 화면에 적용하지 않는다. 동시 새로고침은 하나로 합친다.
- 위치 확인 실패 시 다른 지역으로 대체하지 않고 날씨를 비워 안내한다. 수동 모드는 유효한 저장 격자(`nx_ny`)가 있어야 조회한다.
- 확인한 위치는 FCM 설치 등록에도 반영한다. 토큰 갱신은 시작 당시 좌표가 아닌 최신 확인 대상을 사용하며 서버 등록 요청은 순서대로 처리한다. 대략적 위치/수동 모드에는 정밀 좌표를 보내지 않는다.
- 위치 확인 실패 시 이전 좌표를 토큰 갱신으로 재전송하지 않지만 서버의 마지막 등록 지역을 삭제하거나 알림을 중단하지는 않는다. 화면에 `알림은 서버에 마지막으로 등록된 지역 기준이에요`를 명시한다. 원시 위치를 새로 로컬 저장하거나 로그에 남기지 않는다.
- 근거: [Geolocator 권한·정확도·설정 API](https://pub.dev/packages/geolocator), [geocoding 패키지](https://pub.dev/packages/geocoding), [Android 대략적/정확한 위치 권한](https://developer.android.com/develop/sensors-and-location/location/permissions/runtime), [Android Geocoder](https://developer.android.com/reference/android/location/Geocoder), [Apple CLGeocoder](https://developer.apple.com/documentation/corelocation/clgeocoder).
- 전국 목록은 기상청 날씨누리의 2026-09-10 공개 목록 3,838행(시·도 16, 시·군·구 257, 하위 지역 3,565)을 앱에 포함한다. 목록 탐색·검색은 오프라인에서도 가능하고 실제 날씨 조회에는 인터넷이 필요하다. 자료 실패·재시도·빈 검색·출처/확인일을 안내한다.
- 기상청 코드가 중복된 하위 지역은 원본 이름·격자까지 포함한 `manualRegionKey`로 구분한다. 앱은 이 키와 기존 `currentRegion: nx_ny`를 로컬 저장한다. 서버 설치 등록에는 `nx/ny` 쿼리로 격자를 보내며 알림 설정 API에는 지역 정보나 키를 보내지 않는다. GPS로 전환해도 마지막 수동 지역은 보존한다.
- 저장된 키가 사라지거나 격자가 변경된 목록에서는 다시 선택하도록 한다. 키가 없는 구버전의 유효한 격자는 계속 사용할 수 있다. 선택한 이름은 기상자료의 반환 격자가 일치할 때만 Main·Today 등의 지역 표시에 적용한다. 다른 격자의 응답을 받은 경우 날씨를 표시하지 않는다. 공식 근거 문장의 원문 지역명을 임의 치환하지 않는다.
- 수동 지역 변경은 날씨 조회와 알림 설치 등록에 같은 격자를 적용하며 정밀 좌표를 보내지 않는다. 서버 등록 실패 시 이전 서버 지역이 남는 기존 한계는 유지된다. 전국 검색 결과는 화면에 보이는 행만 생성해 전체 지역을 한꺼번에 렌더링하지 않는다.
- 원본·갱신 절차·중복 코드 사례는 `weather_care_app/assets/data/README.md`, 갱신 스크립트는 `scripts/update_region_catalog.ps1`에 기록했다. 서버 코드·DB·배포 변경은 없다.
- 전체 스위치/API 필드/발송 경로 대조는 [알림 설정·발송 계약](알림_설정_발송_계약.md)에 정리했다. 화면 이름만 실제 동작에 맞추고 기존 API 필드·설정값·발송 조건은 변경하지 않았다.

### 2026-10-21 만조·간조·조위 통합 및 관측소 선택 이동
- 바다 상단의 별도 만조·간조 행과 독립 관측소 선택 팝업을 제거하고 ‘만조·간조/조위’ 칩·항목으로 통합했다. 조위 선택 관측소 코드로 만조·간조를 조회하며 현재값 박스의 최저·최고 바로 위에 표시한다. 해당 코드에 오늘 자료가 없으면 다른 관측소로 대체하지 않고 결측·실패·기준일을 안내한다.
- 만조·간조의 뜻과 표시 기준은 통합 항목 제목의 설명 버튼에서 확인한다. 오늘 남은 첫 시각을 표시하고 모두 지나면 오늘의 마지막 시각을 표시하는 기준은 유지한다.
- 관측소 선택창 아래 최근접 자동선택 버튼은 높이32·아이콘16·글자12로 줄이고 현재값 박스 위 간격은8로 줄였다. 관측소 목록·검색 결과·자동선택으로 지점을 고르면 조회 완료 후 현재값 박스를 화면 중앙으로 스크롤한다. 최초 기본 선택이나 구역 변경 자체에는 자동 이동하지 않는다.

### 2026-10-21 Advanced 요약 박스·기준 시간·그래프 간격 조정
- 만조·간조는 최저·최고와 동일한 테마 배경과 라벨/수치 글꼴을 사용한다. 한 행의 연결된 배경 박스에 ‘만조 시각 · 간조 시각’으로 표시하며, 위치는 최저·최고 위를 유지한다.
- 통합 관측 패널의 기준 시간은 현재 관측 제목과 같은 행의 오른쪽에 HH:mm으로 표시한다. 관측이 없으면 --:--와 기존 결측 안내를 유지한다. 일반 시각 선택 요약도 관측/예측 제목 오른쪽에 해당 시각을 표시한다.
- 시간대별 범례와 그래프 사이 여백은24로, 통합 그래프 높이는256에서320으로 늘렸다. 일반 시간별 추이 그래프도192에서256으로 늘려 세로축 눈금 간격을 넓혔다. Main/Week 그래프는 변경하지 않았다.
- 하천 수위/유량의 ‘위치가 제공된 관측소 기준으로 선택해요’ 안내를 제거했다. 좌표가 확인된 지점의 최근접 자동선택 및 나머지 수동 선택 동작은 유지한다.
