## 앱 동작

- 챙겨요 알림 박스의 비 위, Today 알림 박스의 가시거리 위, 기상·생활 알림 박스의 첫 행에 각각 ‘전체 알림’ 스위치를 배치했다.
- 기상·생활 맨 아래에 있던 ‘챙겨요·Today 알림’ 공통 스위치는 제거했다.
- 그룹을 끄면 해당 하위 항목의 편집을 비활성화하며 개별 선택값은 보존한다. 다시 켜면 기존 선택값을 사용한다. 최상단 ‘알림 사용여부’는 세 그룹 모두를 제어한다.
- 챙겨요와 Today는 같은 설정 시각을 사용하며 독립적으로 정기 브리핑 내용을 선택한다. 기상·생활 전체 OFF는 현재 비·기상특보·블랙아이스·도로통제·동파·낙뢰를 차단하고 정기 브리핑에는 영향을 주지 않는다.
- 저장 실패 안내는 최상단에 유지하며 알림 사용여부와 시간 박스 사이는 다른 박스와 같은 12px이다. 동파 대비 신규 기본값은 ON이고 기존 명시적 OFF는 유지한다.

## 구버전 호환성

새 carryNotificationEnabled/todayNotificationEnabled/weatherNotificationEnabled는 선택 필드다. 사용자 마이그레이션0008과 기본 마이그레이션0025의 세 열은 NULL을 허용한다. 필드가 없는 기존 설정은 챙겨요·Today에서 기존 dailyWeatherEnabled를, 기상·생활에서 기존 ON 동작을 따른다.

새 앱에서 챙겨요 또는 Today를 바꾸면 기존 dailyWeatherEnabled를 두 선택의 OR로 맞춘다. 구 앱이 기존 dailyWeatherEnabled를 OFF하면 두 정기 그룹을 모두 차단하고, ON하면 저장된 새 그룹 선택을 따른다. 구 앱의 필드 없는 부분 갱신은 새 그룹 OFF와 하위 선택값을 보존한다. 두 설정 API에 동일한 병합 규칙을 적용했다. 전체 notificationEnabled 조건도 유지한다.

동파는 기존 OFF/ON과 신규 명시 OFF를 보존한다. 필드를 생략한 신규 설정만 요청한 기본 ON 정책으로 바뀐다. 구버전 앱도 신규 설정을 만들 때 이 정책을 적용받는다. 기존 사용자 값을 일괄 ON으로 덮어쓰지 않았다.

최초 운영 반영에서 API의 Requires/After인 weather-care-prewarm.service가 정상 날씨 선수집을 수행하면서 배포 도구의120초 제한을 넘었다. 도구는 소스를 이전 상태로 복구하고 스케줄러를 재가동했으며 이미 커밋된 추가 DB 열은 보존했다. 데이터 손실·원복용 DB 덮어쓰기는 없었다. 선수집 완료를 확인하고 systemctl 대기 한도를600초로 조정한 뒤 운영 코드만 재반영했다. 이미 적용된 이관은 재실행하지 않았고 이후 전체 검증과 별도 읽기 전용 최종 점검을 통과했다. 서비스 정의 자체는 변경하지 않았다.
