# 기상청 APIHub 이용계획·호출량 산정서

작성 기준: 2026-09-17
서비스명: 날씨챙겨
운영 한도: 일 20,000회 / 5GB

## 1. 운영 구조

모바일 앱은 기상청·공공데이터포털 API를 직접 호출하지 않고 Cloudflare Workers 서버만 호출한다. 외부 API 요청은 Cron 중앙 수집 작업에서만 실행하며, 수집한 자료는 D1에 저장한다. 앱의 Main·Today·Week·어제 비교 조회는 D1 자료만 읽기 때문에 DAU나 새로고침 횟수가 늘어나도 APIHub 호출량은 늘지 않는다.

- 10분: 전국 500m 레이더 1회, 특보 1회, 활성 좌표 일괄 판독
- 1시간: 공공데이터포털 초단기실황을 활성 5km 격자별 1회 재사용
- 불일치 시만: 레이더와 초단기실황의 강수 판단이 다른 좌표만 APIHub 지점 관측분석으로 재검증
- 15분: 동절기 도로살얼음 12개 노선 파일을 각 1회 받아 모든 좌표를 일괄 판정
- 1시간: ASOS 기온·습도·풍속 전국 자료 3회로 모든 지역의 어제 동시각 비교 생성
- 1일: AWS 일최저·일최고·일강수·일 최심신적설 전국 자료 4회로 모든 지역의 지난 날 주간 카드 생성. `sd_day_max`는 하루 동안 새로 쌓인 눈의 최대 깊이이며 현재 지면 적설이나 일 최심적설이 아니다.

## 4. 20,000회 / 5GB 최대치 산정

아래는 동절기에 불일치 지점 검증 상한을 모두 소진하는 최대치다. GB는 신청 한도와 같은 10진수(1GB=1,000,000,000바이트)로 계산했다.

| API | 계산식 | 최대 호출/일 | 1회 용량 산정 | 최대 용량/일 |
| --- | ---: | ---: | ---: | ---: |
| 500m 레이더 | `144 × 1` | 144 | 13,281,414B | 1,912,523,616B |
| 지점 관측분석 | `144 × 69` | 9,936 | 4,096B | 40,697,856B |
| 특보현황 | `144 × 1` | 144 | 256,000B | 36,864,000B |
| 도로살얼음 12노선 | `96 × 12` | 1,152 | 2,100,000B | 2,419,200,000B |
| ASOS 시간관측 3요소 | `24 × 3` | 72 | 128,000B | 9,216,000B |
| AWS 일관측 4요소 | `1 × 4` | 4 | 512,000B | 2,048,000B |
| 특보구역 보조 매핑 | `1 × 1` | 1 | 1,000,000B | 1,000,000B |
| **합계** |  | **11,453회** |  | **4,421,549,472B (4.422GB)** |

- 호출건수: 한도의 57.3%, 잔여 8,547회
- 호출용량: 한도의 88.4%, 잔여 약 0.578GB
- 비동절기: 10,301회, 약 2.002GB/일
- 실제 지점 관측분석은 불일치 지점만 호출하므로 보통 상기 최대치보다 작다.

서버는 APIHub 일일 예산을 D1 `api_usage_daily`에 예약·누적하며, 18,000회 또는 4.5GB에 도달하기 전에 선택 수집을 중단한다. 이는 APIHub 공식 한도에 대해 호출 10%, 용량 0.5GB의 안전 여유를 둔 값이다.

## 5. 정확도 유지 방법

- 레이더 원본을 좌표별로 반복 다운로드하지 않고 전국 1개 파일에서 모든 위치를 500m 격자로 샘플링한다.
- 강수를 레이더 하나로 단정하지 않고 시간별 초단기실황과 교차 검증한다. 불일치할 때만 고해상도 지점 관측분석을 사용한다.
- ASOS·AWS 전국 자료를 한 번 받은 뒤 각 위치에서 가까운 지점을 서버에서 선택하므로 지역이 늘어나도 원본 호출은 늘지 않는다.
- 단기예보는 발표분이 바뀔 때만, 환경자료는 30분, 중기·주간 부가자료는 6시간 캐시를 적용한다.
- 신규 수집이 실패해도 직전 정상 자료를 즉시 삭제하지 않고, 화면에서 결측 항목을 명시한다.

## 6. 신청서 활용 목적 문구

> 모바일 날씨 앱 '날씨챙겨'의 현재 위치 강수, 기상특보, 도로살얼음, 주간 실제 관측값, 어제 동시각 기온·체감온도 비교 제공에 APIHub 자료를 사용합니다. 앱은 APIHub를 직접 호출하지 않고 Cloudflare Workers의 중앙 수집 결과만 조회합니다. 전국 레이더·특보·ASOS·AWS·도로 자료를 주기당 한 번만 받아 모든 활성 지역에 재사용하며, 레이더와 공공 초단기실황이 불일치하는 지점만 고해상도 관측분석으로 재검증합니다. 20,000회/5GB 일일 한도에서 동절기 최대 11,453회, 4.422GB로 산정했으며, 서버 내부에서 18,000회/4.5GB 소프트 한도를 적용합니다.

## 7. 운영 시 확인 항목

- 도로살얼음 ZIP의 실제 평균·95분위 용량을 APIHub 통계로 확인해 2.1MB 산정값을 교정한다.
- APIHub 포털의 실제 전송량과 D1 `api_usage_daily`의 예산 사용량을 매일 비교한다.
- 용량 4.5GB 도달률이 높아지면 정확도 영향이 적은 순서로 지점 재검증 상한을 축소하고, 도로 자료는 동절기에만 수집한다.
- 제공자의 호출량 집계 기준은 Cloudflare 캐시 여부와 다를 수 있으므로 실제 APIHub 관리 화면을 최종 기준으로 삼는다.
