# Main 시간별 행동 요약 계약

수정일: 2026-09-10. 자외선 수치·체감 기준이나 알림 발송 조건을 변경하지 않는다.

## 확인한 문제

- 기존 요약은 현재 예보와 앞의 시간별 예보를 조건만으로 골랐다. 가까운 정시가 현재보다 과거여도 `오후 2시 외출한다면`처럼 표시했다.
- 시간만 표시해 다음 날 예보가 오늘 이미 지난 시각처럼 보였다. 실제 2026-09-10 18:15 KST 운영 응답은 현재 자외선 0인데 `오전 9시` 양산 행동을 표시했고, 해당 UV 6 예보의 실제 대상은 **9월 11일 오전 9시**였다.
- 앱은 받은 문자열을 화면이 열려 있는 동안 계속 표시하고 요약 표시 기한을 알지 못했다.

## 서버 선택 및 문구

- Today 응답을 만드는 시각을 `buildWeatherBriefResult(..., { now })`에 넘긴다. 과거 `fetchedAt`을 현재 시각으로 사용하지 않는다.
- 기존 조건·장면 우선순위는 유지한다. 같은 조건의 후보는 시간순으로 확인하고 끝난 구간, 잘못된 시각/기한, 현재로부터 24시간 이상 뒤의 후보는 선택하지 않는다.
- 기온·바람·UV 정시 자료는 해당 시각부터 최대 한 시간의 표시 범위를 사용한다. 명시된 `validTo`가 더 이르면 그 시각까지만 사용하고, 없으면 한 시간 뒤를 사용한다. 기한 자체가 잘못됐으면 추측해 연장하지 않는다. 이는 요약 표시 범위이지 관측 사실이나 새 예보 정확도 기준이 아니다.
- PCP/SNO는 이미 확정된 이전 한 시간 강수 구간을 따로 사용한다. 구간이 끝나면 강수 행동에 사용하지 않는다. 기온·풍속의 시각을 앞당기지 않는다.
- 진행 중인 구간: `자외선이 강할 수 있으니, 지금 외출한다면 양산이나 모자를 준비하세요`.
- 미래 구간: `자외선이 강할 수 있으니, 오후 4시 외출한다면 양산이나 모자를 준비하세요`.
- 날짜가 다른 미래 구간: `자외선이 강할 수 있으니, 9월 11일 오전 9시 외출한다면 양산이나 모자를 준비하세요`.
- 유효한 행동 조건이 없으면 기존 기본 문구 `오늘은 외출 전에 시간별 예보를 확인하세요`를 사용한다. 과거 고UV 값을 현재값으로 대체하거나 낮은 UV를 새로 추정하지 않는다.
- 양산/자외선 차단제의 공식 UV 근거도 `fetchedAt`의 한국 날짜와 대상 예보일이 다르면 월·일을 붙인다. `validFrom`, 원시 `forecastAt`, 수치와 기관의 사실 역할은 유지한다.

## API 및 앱 표시 기한

- `brief: string` 유지, `briefExpiresAt?: string` 추가. UTC ISO 시각이며 **해당 시각부터 표시하지 않는 기한**이다.
- 미래 행동 문구는 대상 시작 시각에 만료된다. 시작 후 같은 과거 시각을 계속 표시하지 않고, 새 응답을 받아 `지금` 또는 다음 조건을 선택하게 한다.
- `지금` 문구는 해당 구간의 끝에 만료된다. 기존 정시 `validTo`가 `:59:59`이면 그 경계부터 숨기는 보수적 처리를 한다.
- 기본 문구에는 기한을 넣지 않는다. 구버전 클라이언트는 기존 `brief`를 계속 읽을 수 있다.
- 앱은 기한 경계와 복귀 때 확인하고, 시스템 시계 변경을 놓치지 않도록 최대 1분 간격으로 재확인한다. 백그라운드에서는 표시 타이머를 취소한다. 자동 API 요청·위치 조회·푸시 발송을 추가하지 않는다.
- 만료: `안내 시간이 지났어요. 화면을 아래로 당겨 최신 예보를 확인하세요.`
- 잘못된 기한/시간대 누락: `안내 시간을 확인하기 어려워요. 화면을 아래로 당겨 최신 예보를 확인하세요.`
- 기한이 없는 구버전 서버/직접 기상청 조회 응답은 기존 문구를 유지한다. 한국어 문장을 파싱해 임의로 날짜를 추측하지 않는다. 수동 지역 이름 변경도 기한을 보존한다.

## 범위와 검증

- Main 상단 행동 요약과 자외선 근거 날짜가 범위다. 전체 생활 카드·Today 타임라인·Week의 자체 만료 정책이나 다른 현상의 날짜 표기를 일괄 변경하지 않았다.
- 앱 14개 신규 포함 290 tests, 정적 분석, Android debug 빌드 통과. 만료 전/경계/후, UTC·KST, 잘못된 값, 구버전 호환, 앱 복귀, 시계 변경, 새 응답, dispose, 실제 Main 연결을 확인했다.
- 서버 21개 신규 포함 27 files / 184 tests, TypeScript 검사 통과. 시각 선택, 종료된 고UV/눈/비, 다음 날·연말 날짜, 앞뒤 강수 구간, 누락·잘못된 기한, API 직렬화와 원시 예보 보존을 검증했다.
- 운영 반영 전 dry-run과 기존 배포 버전을 확인했다. 비밀값/운영 변수/DB 스키마/스케줄을 변경하지 않는다. 테스트는 모의 Provider/발송 경로를 사용하고 실제 테스트 푸시를 보내지 않는다.
