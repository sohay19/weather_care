# 강수·강설 그래프 실기기 확인

2026-10-29, 연결된 **SM-S948U / Android 16(API 36) / 1080×2340**에서 확인했다. 기존 확인용 앱 `com.codesoha.weathercare.storecapture`에 최신 제품 소스를 빌드해 적용했다. 일반 앱의 스토어 배포는 수행하지 않았다.

## 확인 결과

- 실제 서버 자료로 Main·Week의 강수/강설 4개 화면을 확인했다. 당시 부산 자료는 주로 0mm·0cm와 0~30% 확률이어서, 양수·급경사·하한 예보는 아래 별도 검사용 자료로 보완했다.
- 같은 제품 `HourlyForecastSection`·`HourlyValueChart`를 실제 기기에서 실행한 8개 조합에서 **수치 58개**의 실제 렌더링 좌표를 검사했다. 수치끼리, 수치와 선분·점, 막대 경계 걸침, 과거 예보/미래 관측 노출 오류는 **0건**이었다.
- 겹치지 않는 확률은 막대 위에 유지하고, 급경사와 충돌하는 확률만 자기 막대 안으로 옮기는 것을 확인했다. 막대 안의 글자 대비도 확인했다.
- 신적설 0cm와 2cm 이상 하한 점이 연결되며, 하한 점 위쪽에 수직 범위선이 없고 수치가 선을 피하는 것을 확인했다. 과거는 실제 관측, 미래는 신적설·확률 예보로 분리됐다.
- 각 조합에서 앞·뒤 구간을 이동해 직접 캡처를 확인했다. 가로 스크롤 경계 밖의 시점은 정상적으로 클리핑되며, 구간을 이동해 해당 수치를 확인했다.
- 최종 검증 실행 PID의 Flutter 예외·RenderFlex·FATAL/ANR 로그는 **0건**이었다. 검증 도구 준비 중의 오류는 최종 제품 실행 오류와 구분했다.

## 최종 설치 상태

검증 후 임시 검사 화면을 **최신 제품 화면으로 교체**했다. 기기에는 실제 서버 자료의 Main 강수 화면을 남겼다. 설치된 APK의 SHA-256이 보관한 최신 제품 확인용 APK와 일치하며, 빌드 후 검사한 제품 소스 110개 파일의 변경은 없다.

일반 `lib/main.dart`의 Android arm64 Debug APK도 다시 빌드해 표준 `build/app/outputs/flutter-apk/app-debug.apk`를 제품 결과로 복구했다. 일반 패키지 `com.codesoha.weathercare`임을 출력 메타데이터로 확인했으며 이 일반 패키지를 기기에 추가 설치하지는 않았다. 검사 전부터 사용하던 확인용 패키지를 갱신한 것이다.

제품 그래프 코드 추가 수정은 필요하지 않았다. 이번 작업은 기존 수정본의 빌드·기기 적용·검증과 증거 정리이며, 서버/스토어 배포·커밋/push는 수행하지 않았다.
