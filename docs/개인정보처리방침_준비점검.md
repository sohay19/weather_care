## 삭제 요청 방식 — 구현

2026-09-11 사용자의 `실제 기능구현하고 다음항목` 요청으로 구현했다. 기능 구현 승인을 실제 이용자의 저장 정보를 시험 삼아 삭제하라는 승인으로 해석하지 않는다.

- 앱 Setting에 `서버 내 나의 데이터 삭제` 진입점을 두고 삭제 대상과 알림 중단 영향을 안내한 뒤 사용자가 다시 확인하면 처리하는 방식. 이 사용자용 명칭은 2026-09-11 사용자 요청으로 확정했다.
- 범위는 해당 설치에 연결된 앱 서버의 등록정보·좌표·FCM 토큰·알림 설정·발송 상태·발송 이력이다. 다른 설치의 정보와 공용 기상자료는 삭제하지 않는다.
- 설치별 256비트 비밀값과 서버의 해시로 삭제 권한을 검증한다. 기존 설치는 변경 전 서버 알림 수신 경로에 전달한 일회용 증명으로 전환한다. 식별자만으로 삭제·소유권 획득을 허용하지 않는다. 확인 불가 시 문의를 안내하며 완료로 표시하지 않는다.
- DB 일괄 트랜잭션으로 대상 설치의 관련 행을 삭제한다. 늦은 저장·발송 이력 기록은 재생성하지 못한다. 앱은 삭제 시도부터 전송 중지 상태를 보안 저장소에 남기고, 완료 후 명시적인 `서버 기능 다시 사용` 확인 전까지 재등록하지 않는다.
- 성공한 작업만 삭제 완료로 안내한다. 앱 삭제나 OS 권한 해제를 서버 정보 삭제로 설명하지 않는다.
- 일반 보유기간은 2026-09-11 사용자 결정으로 1년이다. 마지막 사용이 확인된 뒤 1년 미사용인 설치와 발송 후 1년 된 이력을 정리한다. 기존 설치는 정확한 과거 사용 시각이 없어 적용 시각부터 계산한다. 자세한 경계·처리 주기는 [보유기간 계약](./서버_데이터_보유기간.md)을 따른다.
- 백업·로그 및 Firebase/광고 서비스 쪽 정보 처리는 별도로 정한다. 이 기능 하나로 모든 외부 정보가 즉시 영구 삭제된다고 약속하지 않는다.

삭제 기능의 실제 동작 계약이며 특정 법정 보유기간이나 모든 앱의 계정 삭제 의무를 단정하는 내용이 아니다. 보유·삭제 기준 전체가 확정된 상태는 아니다.
