# 아동 개인정보 보호 설계

2026-09-11 사용자 승인: 만 14세 미만 포함, 아동 Analytics·광고 비활성, 동의가 필요한 개인정보 처리는 법정대리인 동의 확인 후 제공.

**상태: 설계 확정안. 현재 앱에 차단이 적용됐다는 뜻이 아니다.** 보호자 확인 수단이 결정되지 않았으며 아동 대상 출시 조건은 충족되지 않았다. 전체이용가와 개인정보 처리 동의는 별개다.

## 기능별 상태

| 상태 | Analytics | UMP·광고 SDK | 위치·개인화 서버 등록·푸시 | 오프라인 안내 |
| --- | --- | --- | --- | --- |
| 연령 미확인 / 저장 오류 | 시작 안 함 | 시작 안 함 | 시작 안 함 | 가능 |
| 만 14세 이상 | 별도 선택 동의 후 | UMP 및 광고 정책 확인 후 | 기존 기능별 동의·권한 조건 | 가능 |
| 만 14세 미만, 보호자 미확인 | 사용 안 함 | 사용 안 함 | 동의 필요 기능 잠금 | 가능 |
| 만 14세 미만, 보호자 확인 완료 | 사용 안 함 | 사용 안 함 | 서버가 확인한 동의 범위 안에서만 | 가능 |
| 보호자 동의 철회 / 확인 만료 | 사용 안 함 | 사용 안 함 | 즉시 새 처리 차단, 관련 정리 절차 | 가능 |

만 14세 이상을 성인으로 표현하지 않는다. 청소년 광고 정책은 별도 검토한다. 보호자 동의가 아동 광고·분석 수집을 허용하는 스위치가 되지 않는다.

## 연령 확인과 시작 순서

1. 중립적인 연령 확인 UI를 앱 시작 경계에 둔다. 만 14세 이상 선택을 유도하는 보상·문구를 넣지 않는다. 생년월일 등 추가 개인정보 수집을 당연시하지 않으며 최소 확인 방식은 보호자 확인 수단과 함께 확정한다.
2. 확인 전에는 HomeScreen 생성과 Firebase/FCM/Analytics/UMP/위치 요청 및 설치 등록을 시작하지 않는다. 로컬 안내 UI만 먼저 표시한다.
3. 네이티브 초기화도 점검한다. Dart 시작을 늦추는 것만으로 Firebase 자동 초기화나 과거 SDK 동의의 지속 저장을 통제했다고 보지 않는다. Android/iOS 프로세스 시작·이전 버전 업그레이드를 검증한다.
4. 백그라운드 FCM 진입, 알림 딥링크, 앱 재개, 재설치·복원, 저장 실패 경로에도 동일한 차단을 적용한다. 다른 route로 우회해 HomeScreen이 먼저 생성되면 실패다.
5. 정상 이용 이력이 있는 기기를 아동이 쓰게 되는 경우 기존 SDK·서버 등록·발송을 중단하는 전환 절차가 필요하다. 기기 연령 값만 바꾸고 기존 서버 알림을 계속 보내서는 안 된다.

## 보호자 동의 확인 경계

- 보호자에게 수집 목적·항목·기간·거부 효과와 아동의 기능 범위를 설명한다. 아동에게도 이해하기 쉬운 언어로 안내한다.
- ‘보호자입니다’ 체크박스, 아동이 입력한 부모 이메일, UMP 응답, OS 권한, 휴대전화 소유 확인 하나를 법정대리인 관계와 동의가 검증됐다는 증거로 취급하지 않는다.
- 적절한 동의·확인 수단과 법정대리인 관계 확인 방법을 선정한 후 연결한다. 외부 본인확인 서비스도 이것만으로 법정대리인 관계까지 확인한다고 가정하지 않는다.
- 서버가 검증한 요청의 대상 설치·동의 범위·방침 버전·시각·유효 상태를 최소한으로 관리한다. 클라이언트가 보낸 `guardianVerified: true`로 허용하지 않는다.
- 확인 콜백은 서명/요청 연결/재사용 방지/만료를 검증한다. 위조·중복·다른 설치의 증명을 거부한다.
- 동의 철회와 삭제 요청은 보호자의 권한을 다시 확인하고 실행한다. 증명 원본·연락처·감사 기록의 보관기간은 운영자가 확인 방식과 함께 결정한다. 일괄 1년으로 추정하지 않는다.
- 아직 확인 서비스 계약·가입·유료 결제·인증정보 수집을 수행하지 않는다. 실제 연결 전 보호자 확인 상태는 항상 미완료다.

## 별도 본인확인 서비스 미보유: 이메일 회신안 검토

2026-09-11 사용자 확인: 별도 본인확인 서비스 없음. 유료 본인확인 계약이 반드시 필요하다는 뜻은 아니다. 개인정보 보호법 시행령 제17조의2제1항제5호에는 동의 내용을 전자우편으로 보내고 법정대리인의 명시적 동의 회신을 받는 방법이 규정되어 있다. 이메일 주소 입력 또는 OTP 확인만으로 이 절차를 대체하지 않는다.

- 운영 후보: 동의 요청 번호 생성 → 목적·항목·보유기간·거부 효과가 포함된 안내 이메일 → 법정대리인의 동의 회신 → 운영자 확인 → 서버에서 해당 요청의 동의 범위만 승인.
- 기존 메일함을 사용하는 수동 운영은 별도 인증 서비스 계약 없이 검토할 수 있지만, 운영자 확인 시간·메일 보안·증빙 보관 및 삭제 관리가 필요하다. 자동 발송 서비스의 무제한 무료 운영을 보장하지 않는다.
- 법정대리인임을 확인하는 절차와 요청 연결·위조 대응을 설계하되, 가족관계증명서나 주민등록번호 수집을 일률적인 필수 요건으로 추가하지 않는다. 별도 관계 증명 서류 제출이 위 조항의 보편적 의무라고 설명하지 않는다.
- 수동 승인 운영 여부, 증빙 보관기간 및 철회 확인 방식은 미확정. 이메일 수신만으로 자동 승인하는 코드는 구현하지 않는다. 만14세 미만 분석·광고 비활성 방침은 유지한다.

확인 출처: [국민건강보험공단 법령정보의 시행령 제17조의2](https://www.nhis.or.kr/lm/lmxsrv/law/lawFullContent.do?MODE=threeView&SEQ=191&SEQ_HISTORY=598892). 실제 도입 전 현행 조문과 위치정보 등 기능별 추가 요건을 확인한다.

## 서버와 최소 기능 적용

앱 버튼을 숨기는 것만으로 보호하지 않는다. 개인화 등록·설정·좌표 처리·FCM 발송에서도 연령/보호자 권한을 확인한다. 구버전 등록과 인증된 요청의 전환 정책을 정의하며, 전환 완료 전 아동 지원 출시를 선언하지 않는다.

개인정보를 처리하지 않는다고 검증된 오프라인 도움말은 제공할 수 있다. 수동 지역 날씨 조회도 서버가 IP 등을 받으므로 ‘개인정보 수집 없음’으로 단정하지 않는다. 이 경로의 최소 처리와 법적 근거 검토가 끝나기 전에는 온라인 기능을 자동 허용하지 않는다.

## 사용자 문구 초안

- 연령 확인: `날씨챙겨를 이용할 분의 연령대를 알려주세요.`
- 아동 안내: `만 14세 미만은 이용 통계 수집과 광고를 사용하지 않아요.`
- 확인 전: `이 기능을 사용하려면 보호자의 개인정보 동의 확인이 필요해요.`
- 미연결: `보호자 동의 확인 기능을 준비하고 있어요. 아직 이 기능을 사용할 수 없어요.`
- 오류: `보호자 동의를 확인하지 못했어요. 확인될 때까지 이 기능을 시작하지 않아요.`

미연결 문구는 전체 아동 서비스를 제공하는 것처럼 보이는 완료 문구와 함께 사용하지 않는다.

## 구현·검증 순서

1. 보호자 확인 방식·관계 확인·보관 범위 결정.
2. SDK 이전 시작 경계와 최소 로컬 화면, 지속 저장/실패 처리.
3. 서버 증명 검증·기능별 권한·철회·구버전 전환·발송 차단.
4. Android/iOS 실제 네트워크 검증: 최초/재시작/업그레이드/미확인/아동/철회 상태에서 분석·광고·개인화 요청이 시작되지 않는지 확인.
5. 방침에 실제 수집·보관·확인 방법 반영 후 공개 페이지 최종화. AdMob/스토어 아동 설정 검토.
