## 1. 변경하려는 동작

현재 `GET /api/v1/weather/comparison/yesterday`의 **오늘 다음 시간 예보 ↔ 어제 정시 실황** 비교를 **오늘 현재 실황 ↔ 어제 같은 시각 실황** 비교로 바꾼다.

- 같은 선택지역의 `nx/ny` 격자를 양쪽에 사용한다.
- 오늘 기온은 현재 실황 기온, 어제 기온은 같은 시각의 실황 기온이다.
- 오늘·어제 체감온도는 각각의 기온·습도·풍속을 입력으로 기존 체감온도 계산 함수를 동일하게 적용한다.
- 예: **오늘 11:54에 요청 → 오늘 11:50 실황 ↔ 어제 11:50 실황**.
- 오늘 값은 메인 화면의 현재 기온·체감온도와 같은 실황 원천·캐시·계산 경로를 사용한다. 비교 카드만 별도 예보나 다른 관측소 값으로 채우지 않는다.
- 목표는 **앱 배포 없이 서버 수정으로 동작**하게 만드는 것이다.
- 비교 카드의 `오늘 10월 4일 오후 12시 · 어제 10월 3일 오후 12시` 같은 **날짜·시간 줄을 표시하지 않는 방향**이다.

최신 10분 구간이 미발표·결측인 경우의 처리와 이력 저장 방식은 아래 권장안이다. 정상적인 경우의 11:54 → 11:50 계약을 임의로 항상 10분 더 늦추지 않는다.

## 3. 실제 조회로 확인한 내용

APIHub의 다음 실황 API로 확인했다.

```text
https://apihub.kma.go.kr/api/typ01/cgi-bin/url/nph-dfs_odam_grd
tmfc=YYYYMMDDHHmm
vars=T1H 또는 REH 또는 WSD
authKey=기존 KMA_APIHUB_KEY
```

공식 문서: [기상청 API허브 동네예보 격자자료, 2.3 실황](https://apihub.kma.go.kr/apiList.do?seqApi=10&seqApiSub=286)

### 확인 결과

1. 오늘 11:56~11:58에 **어제 12:00과 11:50 기온**을 조회했고 두 응답 모두 유효한 값을 받았다.
2. 이후 확인 시작 시각은 **오늘 12:04**였다. 해당 10분 구간인 **2026-10-04 12:00 ↔ 2026-10-03 12:00**의 T1H·REH·WSD를 모두 확보했다. 오늘 응답은 12:05~12:07, 어제 응답은 12:10~12:11에 확보했다.
3. 각 응답에서 149×253 = 37,697개 격자값을 확인했다. 아래는 예시 격자 **nx=60 / ny=121**의 값이며, 사용자의 현재 GPS 위치를 의미하지 않는다.

| 항목 | 오늘 12:00 | 어제 12:00 |
|---|---:|---:|
| 기온 T1H | 23.8℃ | 20.6℃ |
| 습도 REH | 43.5% | 43.2% |
| 풍속 WSD | 2.6m/s | 3.4m/s |
| 기존 함수로 계산한 체감온도 | 22.2℃ | 17.7℃ |

두 체감온도 모두 기존 함수가 **STEADMAN**을 선택했고, 기온 차이는 **+3.2℃**, 체감온도 차이는 **+4.5℃**다. 저장소의 계산 함수를 그대로 추출해 실제 조회 값으로 실행했다.

어제 기온·습도 최초 요청은 **HTTP 504**였지만 재요청에서 성공했다. 따라서 504를 곧바로 `과거 자료 없음`이나 `24시간 보관 만료`로 판단하지 않는다. 이번 성공은 특정 시각의 실제 가용성 확인이며, 모든 시각·지역의 과거 조회나 정확한 보관 기간을 보장하는 결과는 아니다. 공공데이터포털 `getUltraSrtNcst`의 조회 기간 제한과도 구분한다.

## 4. 서버 구현 권장안

1. **오늘 기준 시각을 선택한다.** 한국시간의 현재 10분 구간을 목표로 하되, 실제로 확보된 현재 실황의 `observedAt`를 비교 기준으로 삼는다. 예보 발효 시각을 사용하지 않는다.
2. **어제 시각을 맞춘다.** 오늘 `observedAt`에서 정확히 24시간 전의 동일 격자 자료를 선택한다. 오늘 11:50과 어제 12:00처럼 시각이 다른 값은 비교하지 않는다.
3. **체감온도를 계산한다.** 양쪽의 같은 시각 T1H·REH·WSD에 기존 계산 함수를 적용한다. 현재 함수는 조건에 따라 KMA/Steadman을 선택하므로, 계절·기온 조건 경계에서도 기존 현재 체감온도 산식과 일치하는지 확인한다. 특정 산식 하나로 강제하는 별도 변경은 이번 요구에 포함하지 않는다.
4. **중앙 수집과 이력을 재사용한다.** 현재 자료는 기존 수집 캐시를 활용하고, 과거 자료도 전국 격자 응답을 공용으로 저장해 지역별 요청마다 반복 다운로드하지 않도록 한다. APIHub 사용량 예산 기록에도 추가 수집을 반영한다.
5. **실황 이력을 보관한다.** `(nx, ny, observed_at)`로 기온·습도·풍속·제공처를 최소 48~72시간 보관하는 방식을 권장한다. 정확한 보존 기간과 테이블/캐시 구성은 다른 컨텍스트의 현재 서버 작업과 맞춰 결정한다. 시작 직후 누락 이력은 승인된 API로 제한적으로 보충할 수 있다.
6. **실패를 구분한다.** 최신 구간이 미발표면 직전의 실제 확보 구간으로 오늘·어제를 함께 맞추는 정책을 권장한다. 허용할 최신성 한도를 명시하고, 짝이 없거나 체감 입력이 불완전하면 허위 값 없이 기존 비교 불가 응답을 사용한다. 504·요청 실패·결측·예산 소진은 서버 진단에서 구분한다.

현재 실황 경로에는 AWS 지점 fallback도 있다. 오늘을 AWS 관측소 값으로 쓰고 어제를 격자 실황으로 쓰는 혼합 비교는 하지 않는다. 이번 요구는 동일 격자 비교이므로, 오늘이 격자 실황인지 확인하고 충족하지 못하면 명시적인 비교 불가 정책을 적용한다.

## 5. 앱 수정 없이 날짜·시간 줄 숨기기

기존 앱의 `_comparisonBasisLabel`은 응답의 날짜·시간 필드로 표시 문구를 조립한다. **해당 필드를 보내지 않으면 날짜·시간 줄을 표시하지 않는다.**

서버 응답에서 다음 표시용 필드를 생략한다.

```text
basis.currentForecastAt
basis.forecastIssuedAt
basis.currentObservedAt
basis.comparisonObservedAt
basis.stationId
basis.distanceKm
```

이번 비교에는 관측소 ID·거리도 표시하지 않는다. `stationId` 또는 `distanceKm`가 있으면 날짜를 생략해도 별도 출처 줄이 남을 수 있다.

- `basis.provider`는 실제 APIHub 격자 실황을 나타내는 값으로 바꾼다. 이전 `KMA_FORECAST_VS_ULTRA_SHORT_OBSERVATION`을 유지하지 않는다.
- `basis.dataRole`은 실황 대 실황 비교를 나타낸다.
- `basis.gridX/gridY`와 기존 숫자 응답 구조는 유지할 수 있다.
- 실제 관측 시각·제공처·계산 정보는 **서버의 내부 이력과 진단에서 반드시 유지**한다. 시각 필드 생략은 화면 표시 목적이지, 시간 검증을 없애는 것이 아니다.
- `targetDate`는 유지 가능하다. 현재 비교 카드에서 직접 표시하지 않는다.
- 빈 문자열·잘못된 날짜·허위 provider로 앱 표시를 속이지 않는다. 필요한 선택 필드를 명시적으로 생략한다.

호환 응답 예시:

```json
{
  "comparisonAvailable": true,
  "current": {
    "temperature": 23.8,
    "apparentTemperature": 22.2
  },
  "comparison": {
    "temperature": 20.6,
    "apparentTemperature": 17.7
  },
  "targetDate": "2026-10-03",
  "basis": {
    "provider": "KMA_APIHUB_GRID_OBSERVATION",
    "dataRole": "OBSERVATION_VS_OBSERVATION",
    "gridX": 60,
    "gridY": 121
  }
}
```

위 응답은 실제 수정 완료 응답이 아니라 구현 목표 예시다.

### 기존 앱에서 예상되는 문구

```text
어제와 비교
같은 지역의 같은 기준시각 자료만 비교해요

기온은 어제보다 3.2℃ 높아요.
오늘 23.8℃ · 어제 20.6℃

체감온도는 어제보다 4.5℃ 높아요.
오늘 22.2℃ · 어제 17.7℃
```

이 응답에서는 `~시 기준, 다음 시간 기온 예보를 어제 실황과 비교해요`와 오늘·어제 날짜·시간 줄이 사라진다. 다만 **`같은 지역의 같은 기준시각 자료만 비교해요`라는 안내는 기존 앱에 하드코딩되어 남는다.** 이 안내까지 원하는 새 문구로 바꾸려면 앱 수정이 필요하다.
