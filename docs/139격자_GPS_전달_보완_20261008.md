# 139격자 GPS 전달 보완 — 2026-10-08

139개 미확정 격자는 실제 GPS를 서버에 보내 정확한 행정구역으로 연결하도록 보완했다. 주간 조회와 개별 재시도의 좌표 누락을 수정했고, GPS가 있는 메인·오늘·주간 조회가 지역명 조회의 지연·실패 때문에 막히지 않게 했다. **2026-10-08 서버 코드·경계는 운영 배포했으며 앱 업데이트는 사용자가 진행한다. 전국 날씨 초기 캐시는 APIHub 당일 예산 부족으로 미완료다.** 최신 운영 상태는 [SGIS 경계 보완 결과의 운영 배포 결과](SGIS_경계_보완_결과_20261008.md)를 따른다. 아래 검증 수치는 실경계·합성 기상 데이터로 확인한 결과다.

## 139개가 남았던 이유

이 숫자는 경계 자료가 없는 격자 수가 아니다. 좌표·확정 이름·코드 없이 격자 번호만 전달할 때, 격자 전체를 하나의 행정구역으로 확정하지 못하는 경우다.

| 분류 | 격자 수 | 보완 |
|---|---:|---|
| 해안 또는 경계의 빈 영역으로 전체 격자 포함 조건을 통과하지 못함 | 70 | 실제 육지 GPS의 경계 포함 판정 |
| 여러 시도 경계가 하나의 격자에 포함됨 | 69 | 실제 GPS로 소속 구역 구분 |
| 합계 | 139 | 정밀 GPS 전달·이름 실패와 날씨 요청 분리 |

육지 내부의 GPS는 이전 경계 구현으로 판정할 수 있었다. 따라서 이번에는 불확정 격자에 대표 동을 추가하는 대신, 판정에 필요한 좌표가 실제 요청에 도달하도록 고쳤다. 기존 286개 전체 격자 상위 참조와 실제 경계 판정 조건은 유지했다.

## 적용 내용

1. `WeatherService.fetchWeeklyWeather()`에 좌표 인자를 추가하고 위도·경도를 전송한다. 최초 날씨 묶음 조회와 서버 재시도 모두 오늘·주간에 같은 좌표를 전달한다.
2. 홈의 주간 개별 재조회에도 현재 정밀 GPS와 기존 날씨 격자를 전달한다. 기존 메인·오늘·위젯의 정밀 GPS 전달 경로와 일치시켰다.
3. 실제 GPS가 있으면 지역명 Future가 끝나기를 기다리지 않고 요청한다. GPS가 없는 지명 조회가 실패해도 서버 날씨 요청을 계속한다. 별도로 수행하는 앱 지역명 표시 처리는 계속 동작한다.
4. 경계가 설치됐지만 좌표·확정 지역명·코드가 없어 지역을 판정하지 못하면 자외선 상태와 로그에 `LOCATION_COORDINATES_REQUIRED`를 기록한다. 기본 날씨 응답을 지역 연결 실패로 차단하지 않는다. 로그에는 좌표 유무만 기록한다.
5. 실제 GPS가 없는 요청에 다른 사용자의 같은 격자 GPS나 대표 동을 재사용하지 않는다. 기존 대략적 위치·위치 권한 제한 정책은 유지한다.

정밀 GPS가 없고 지역명·코드도 없다면 시도 경계의 어느 쪽인지 알아낼 수 없다. 이런 요청까지 정확한 동으로 연결했다고 보고하지 않는다. 해상 위치에 육지의 동을 배정하지 않는다. 대략적 위치만 허용한 사용자는 정밀 좌표 전송 대상에 포함되지 않는다.
