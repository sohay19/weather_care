# 광고 동의 연결

2026-09-11 사용자 승인으로 Google UMP 흐름을 구현했다.

- 앱 첫 화면 표시 후 매 프로세스 시작마다 동의 정보를 갱신한다. 필요한 경우에만 UMP 화면을 표시한다. 모든 한국 사용자에게 항상 팝업이 뜬다는 의미는 아니다.
- `canRequestAds()` 확인 후 Mobile Ads를 프로세스당 한 번 초기화한다. 이 값은 개인화 광고 동의 자체를 뜻하지 않는다.
- 정보 갱신·화면·조회 오류 시 이 앱은 보수적으로 광고 준비를 막고 설정에 재시도를 제공한다. 날씨 시작을 기다리게 하지 않는다.
- UMP가 요구하면 설정에 `광고 개인정보 선택`을 표시한다. 변경 중에는 광고 요청 가능 상태를 내리고, 닫힌 뒤 다시 확인한다. SDK 초기화를 취소하거나 이미 전달된 정보를 삭제하는 기능은 아니다.
- Analytics 선택 동의를 광고 동의로 사용하지 않는다. Analytics의 광고 관련 consent 거부 설정은 그대로 유지한다. UMP 선택이 Firebase 분석 수집을 켜도록 연결하지 않는다.
- 2026-09-14 `Week` 탭의 주간 요약과 날짜 카드 사이에 인라인 적응형 배너 경로를 추가했다. 탭이 활성 상태일 때만 생성하며 UMP의 최신 `canRequestAds`가 false가 되거나 위젯이 제거되면 기존 광고를 폐기한다. 로드 실패는 날씨 기능을 막지 않고 같은 상태에서 무한 재시도하지 않는다.
- 모든 요청은 `nonPersonalizedAds=true`이며 Mobile Ads 초기화 전에 광고 콘텐츠 등급 상한을 `G`로 설정한다. 비개인화 광고도 광고 전송·빈도 제한·집계·부정 사용 방지 처리가 전혀 없다는 뜻은 아니다.
- Debug/Profile은 Google 공식 테스트 배너 ID만 사용한다. Release는 만 14세 이상 확인, 유효한 플랫폼별 광고 단위 ID, `ADMOB_RELEASE_ENABLED=true`가 모두 충족되지 않으면 UMP와 광고 경로를 시작하지 않는다.
- 2026-09-14 Android 에뮬레이터에서 실제 운영 앱 ID로 UMP 갱신을 시도했을 때 앱용 메시지가 없어 `Publisher misconfiguration: no form(s) configured`가 발생했고 광고 요청은 차단됐다. 이를 동의 성공이나 SDK 오류로 오인하지 않는다. 광고 위젯 자체의 개발 검증에는 `ADMOB_TEST_BYPASS_UMP=true`를 명시할 수 있지만 이 우회는 Release에서 무시되며 UMP 종단 검증 증거가 아니다.
- 같은 에뮬레이터에서 우회 플래그를 넣은 x86_64 Debug APK를 기존 앱 데이터 유지 방식으로 설치한 뒤 `Week` 탭에 진입했다. 앱의 배너 로드 요청, Google SDK의 테스트 기기 요청 인식, 배너 로드 완료 로그를 확인했다. 이는 공식 테스트 광고 위젯의 Android 에뮬레이터 렌더링 경로만 검증하며 운영 광고, UMP 동의, Android 실물 또는 iOS 검증을 대신하지 않는다.
- 실제 운영 광고는 아직 송출하지 않는다. 수익화·광고 개인화 또는 만 14세 이상 대상 설정이 완료된 것으로 보지 않는다.

## 운영 연결 전 필요한 작업

1. 운영 앱 ID 연결 완료(2026-09-11 사용자 제공): Android Manifest는 `ca-app-pub-6152243173470406~7636009442`, iOS Info.plist의 GADApplicationIdentifier는 `ca-app-pub-6152243173470406~9535766125`. 앱 ID와 광고 단위 ID를 구분한다.
2. Android/iOS 배너 광고 단위 생성 완료(2026-09-14 사용자 확인 후 실행). 두 단위 이름은 `날씨챙겨 Week 인라인 배너`다.
   - Android `ADMOB_ANDROID_BANNER_ID`: `ca-app-pub-6152243173470406/8661897062`
   - iOS `ADMOB_IOS_BANNER_ID`: `ca-app-pub-6152243173470406/6134971926`
   - ID는 소스에 하드코딩하지 않고 향후 CI/스토어 Release 빌드 환경에 주입한다. 현재는 아래 운영 조건이 남아 있어 `ADMOB_RELEASE_ENABLED`를 켜지 않는다.
3. 앱 시작 전 로컬 연령 확인 경계와 서버의 정책 버전 경계는 2026-09-14 구현했다. 연령 미확인·저장 오류·만 14세 미만에서는 앱 서비스를 제공하지 않고 UMP와 광고 SDK도 시작하지 않는다. 보호자 동의를 통한 예외 이용 경로는 만들지 않는다. 운영 D1 `0009`와 Worker 배포는 완료했고 새 앱 배포는 남아 있다. Flutter 네이티브 플러그인 등록 과정의 Android Analytics 모듈은 수집 비활성·저장 동의 거부 상태로 로드될 수 있다.
4. AdMob의 개인정보 보호 및 메시지에서 대상 앱·지역·메시지·공개 개인정보처리방침 URL을 검토하고 게시한다. 한국 스토어 한정과 비개인화 광고 방침이 외부 서비스의 모든 처리를 없애는 것으로 설명하지 않는다.
5. 테스트 기기에서 첫 동의, 거부, 재실행, 선택 변경, 오프라인, 메시지 오류, Week 탭 진입·이탈을 확인한다. 지역 강제/동의 reset은 테스트 전용이며 운영 코드에는 넣지 않는다.
6. 새 앱 연령정책 배포, 스토어·AdMob 대상 연령 설정, Android 실물과 iOS 검증 및 공개 방침 최종 연결이 끝난 뒤에만 Release 광고 활성화를 검토한다. 네이티브 SDK 자체 전송 부재나 법적 준수 완료를 코드 테스트만으로 주장하지 않는다.
