# 운영 서버 인근 실황·예보 보충 배포 결과

2026-10-09 14:46·14:52 KST HTTP 전수 검사 기준. 운영 릴리스는 `20261009-nearby-observation-v2`이며 API·스케줄러·Cloudflare Tunnel이 모두 정상 실행 중이다. 내부·외부 `/health`는 모두 200으로 확인했다.

## 적용 내용

- 원본 공간 결측 대상의 예보는 공공데이터포털 `getVilageFcst`에서 **요청 격자 그대로** 수집한다. 302개 모두 캐시 확보. 전국 정상 격자의 APIHub 예보는 기존 전국 원본 수집을 유지한다.
- 전국 배열 37,697셀과 실황 원본 72시간 이력은 보존한다. 원본 결측을 정상 값으로 덮어쓰지 않는다.
- 실황은 원래 격자의 정상 값을 우선한다. 해당 격자가 결측이면 실제 요청 GPS에서 가장 가까운 유효 출처를 찾는다. GPS가 없으면 격자 중심으로 거리 계산하고 `distanceBasis=GRID_CENTER`로 구별한다.
- 같은 시각·같은 격자에서 6항목이 정상인 후보를 우선한다. 그 회차에 선택 항목 파일이 없어 후보가 전혀 없으면 기온·습도·풍속이 정상인 인근 값을 제공하며 누락 항목에 품질 플래그를 붙인다. 정상 핵심 실황 전체를 버리지 않는다.
- `sourceLocation`에 출처 `nx`, `ny`, `locationMatch=NEAREST_GRID`, 실제 GPS 기준 `distanceKm`, `distanceBasis=GPS`를 제공한다. 20km 초과는 `DISTANT_GRID_OBSERVATION` 표시를 추가하며 거리만으로 값을 차단하지 않는다.
- 이전 10분 슬롯부터 조회하고 실황 30분 유효조건을 유지한다. 앱 조회에서는 제공처 호출 없이 저장된 캐시를 읽는다. 인근 실황 선택의 추가 APIHub 호출은 **0회**다. AWS 분 단위 실황 대체는 재도입하지 않았다.
- 어제 비교는 오늘 선택한 출처 격자의 정확히 24시간 전 값만 쓴다. 과거 원본이 없으면 비교 불가로 응답한다.
- 공공데이터 응답을 6,000행까지 요청하며 실제 페이지 크기가 줄어들면 전체 행 수와 중복을 검사해 남은 페이지를 읽는다. 격자·발표 회차가 다른 응답을 거절하며 연장 구간 풍속·강수량·적설 정성 코드를 실제 수치로 계산하지 않는다.
- 공공데이터 예보는 회차·격자당 최대 3번, 10분 이상 간격으로 재시도한다. 동시 수집 임대와 하루 9,000회 내부 예약 한도를 적용하고 APIHub 장부와 분리한다. HTTP 상태·수신량·헤더/본문 단계·소요시간을 비밀값 없이 기록한다.
- 선수집 대상으로 지역 참고 목록 2,848개 대신 **실제 육지와 1㎡ 초과 겹치는 4,728개 격자**를 검사한다. 302개 대상이 모두 포함된다. 목록의 원본 SHA256·경계 버전을 검사하고 버전 불일치 시 잘못된 목록으로 대체하지 않는다.

## 남아 있는 자료 제약

14:46 검사에 선택된 14:20 실황은 PTY(강수형태) 파일이 없어 302개 모두 `PRECIPITATION_TYPE_UNAVAILABLE`가 있었다. 14:52 후속 검사에서도 이 선택 항목 결측 표시는 남아 있다. 기온·습도·풍속·풍향·1시간 강수량 원본은 정상이다. 강수형태는 기존 정책에 따라 예보를 참고하므로 화면에 값이 있다는 사실을 **6항목 모두 실황 원본 정상**으로 해석하면 안 된다.

로그에서 14:30 실황 기온 요청은 응답 헤더 대기 중 30,001ms에 시간초과로 끝났다. 후속 동일 회차 요청과 PTY 보충은 첫 24시간 공통 재시도 100MB 상한에 막혔다. 이는 전체 APIHub 4.5GB 내부 한도 소진과 다른 제한이다. 당시 재시도 장부는 약 99.55MB였으며 1MB 예약 여유가 없었다. 회차가 바뀐 첫 호출은 별도 필수 호출 예산을 사용한다. 상한·장부를 초기화하거나 우회하지 않았다. 헤더 대기 로그만으로 기상청 처리 지연과 서버의 외부 연결 지연을 최종 분리했다고 단정하지 않는다.

외부 표본 검사에서 대기질 제공처 자료는 일부 미확보 상태였다. 14:46 어제 비교 표본 4곳은 원본이 없어 `comparisonAvailable=false`였으며 예보를 실황 비교에 넣지 않았다. 정규 수집에서 새 회차와 그 어제 원본을 확보한 뒤 14:52 표본 4곳은 모두 `comparisonAvailable=true`로 회복했다. 저장 이력의 이전 누락 회차까지 모두 채운 것은 아니므로 이번 배포가 모든 제공처의 원본 결측까지 없앴다는 의미는 아니다.

경계 자료는 현재 설치된 SGIS 2025년 2분기 원본과 기존 2026 행정개편 연결을 사용한다. 신청 중인 2026 공식 경계 새 자료로 바꾼 배포는 아니다.

## 호출 예산

기존 계산 스크립트를 현재 수집 계획으로 다시 실행했다. 파일 용량은 기존 실측·설계 표본이며 10% 재시도는 예상 가정이다. 실제 용량 증가·장애가 나면 내부 상한이 호출을 차단하므로 아래 숫자는 무중단·무결측 보장이 아니다.

| APIHub | 필수 호출 | 예상 재시도 | 합계 | 필수 용량 | 재시도 용량 | 합계 용량 |
|---|---:|---:|---:|---:|---:|---:|
| 비겨울 | 4,208 | 421 | 4,629 | 2.715GB | 0.272GB | 2.987GB |
| 겨울 | 4,333 | 434 | 4,767 | 3.771GB | 0.377GB | 4.148GB |

APIHub 운영 내부 상한은 하루 18,000회·4.5GB, 일반 재시도 하위 상한은 400MB다. 첫 24시간만 100MB다. 전국 예보의 05·17시 마지막 연장일 VEC 요청 제외도 유지된다. 실황 보충으로 이 합계는 늘어나지 않는다.

공공데이터포털 예보는 302격자×8회차×최신·일별 보완 최대 2호출 = **4,832회/일**, 재시도 20% 예상 **967회**, 총 **5,799회/일**을 보수적으로 잡는다. 정상 02시 최신·보완 요청은 내부 중복 제거로 더 줄어든다. 다중 페이지·자료 미발표에 따른 추가 회차는 실제 예약에 포함되며 9,000회 내부 상한을 지킨다. 이 기능의 호출은 에어코리아·자외선·APIHub 호출과 제공 서비스가 다르다. 이번 정상 선수집 표본으로 계산한 4,832회 수신량은 약 0.564GB이며 예시 추정치다. 수동 진단·다른 프로그램의 같은 계정 호출은 이 서버 장부에 자동 합산되지 않는다.

## 다음 경계 교체 및 앱 반영

새 공식 경계로 바꿀 때 `tools/build_land_forecast_grids.py --boundaries <원본ZIP> --audit <경계감사JSON> --output <육지격자JSON>`을 실행하고 동일 경계 버전의 자료를 `src/node/importLandForecastGrids.ts`로 함께 가져온다. 버전 불일치는 수집 로그 `NATIONWIDE_LAND_GRIDS_NOT_READY`로 확인한다. 지역명 참고 목록을 육지 수집 대상으로 사용하지 않는다.

앱 배포는 사용자 작업이다. 현재 앱의 인근 실황 안내는 미리보기 단계이며 서버 출처 메타데이터를 실제 CurrentWeather 모델·메인·Today 안내에 연결해야 한다. 표시 문구는 `인근 실황 · 약 ○km`로 하고 시각은 요약 행에서 제외한다. 어제 비교 요청에도 Main/Today와 같은 `latitude`, `longitude`를 보내야 GPS 기준 출처가 동일하다. GPS 없이 격자만 보내면 격자 중심 기준 출처를 선택한다.

운영 DB 온라인 백업(약 731MB, quick_check=ok)과 이전 릴리스를 보존했다. 배포 실패 시 이전 링크로 돌아가는 절차를 사용했으며 커밋은 만들지 않았다.
