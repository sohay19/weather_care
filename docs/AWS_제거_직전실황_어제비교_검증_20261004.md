## 적용한 동작

- AWS 분 관측 대체 제공처·호출·예약·현재 표시 경로를 제거했다. 기존 AWS 현재 캐시도 현재 값·어제 비교·강수 지점 검증에 채택하지 않는다. AWS **독립 일 관측**은 주간 과거 자료 원천으로 유지하며 한도 합계에 포함한다.
- 한국시간 현재를 10분으로 내림한 뒤 10분을 뺀 회차가 상한이다. 11:50~11:59→11:40,12:00~12:09→11:50. 이미 저장된 더 최신 회차도 이 상한을 넘으면 쓰지 않는다. 실패 시 같은 격자의 더 이전 정상 실황만 30분 유효범위 안에서 사용한다. 20분을 넘으면 지연 표시한다.
- 메인과 어제 비교는 동일한 원본 선택 함수와 기존 체감온도 산식을 쓴다. 어제는 선택된 현재 관측시각의 정확히24시간 전, 같은 nx/ny만 채택한다. 예보·다른 관측소·다른 분으로 채우지 않는다.
- 비교 응답은 기존 current/comparison 숫자 구조와 targetDate를 유지하고 provider=KMA_APIHUB_GRID_OBSERVATION,dataRole=OBSERVATION_VS_OBSERVATION을 반환한다. 표시용 날짜·시각·관측소·거리 필드는 생략한다. 앱 코드는 수정하지 않았다. 기존 일반 안내 문구는 남는다.
- 전국 실황 원본 배열을 회차당 한 번 저장한다. 149×253개 셀과 공식 결측값을 보존하며 개별 GPS는 해당 셀을 읽는다. 새 SQLite migration0012_grid_observation_history.sql, 72시간 보존·원자 저장·정리·임대·중복 방지·실패 진단을 추가했다. 신규 핵심3변수 캐시를 정규6변수로 보충할 때 기존 파일을 재다운로드하지 않는다.
- 어제 원본은 중앙 수집만 보충한다. 비교 API는 외부 호출0회다. 초기에는 어제3변수×144회차의 추가 비용이 필요하다. 24시간 이력이 정상적으로 쌓이면 추가 정규 조회0회, 결손 구간 보충·실패 재시도는 별도다. APIHub 예약 검사는 한 SQL로 원자 처리했다.
- 요청별 타임아웃은30초를 유지한다. T1H를 먼저 확인하고 정상 파일을 재사용한다. 필수 입력이 없는 비교·짝이 없는 비교는 비교 불가로 반환하며 실패 이유는 내부 로그로 구분한다.
- 프리워밍은 정상 전국 원본의 공식 결측을 무한히 보충하려고 서버 시작을 막지 않고 observationSourceMissingGrids로 보고한다. 다른 원본의 준비 확인은 유지한다.

## 검증 및 운영 반영

TypeScript와 관련 테스트, Node 실제 SQLite 마이그레이션/원자성/이력/전수 셀/중복/예산/프리워밍을 검증했다. 상세 최종 테스트 수는 HANDOFF에 기록한다. 실제 오늘·어제 원본의 SQLite 왕복과 Hono 비교 API 재현도 확인했다. 운영은 읽기 전용 DB 검사와 공급자 원본 조회만 수행했다.

운영 반영 시 새0012마이그레이션을 포함한 서버 소스를 함께 배포해야 한다. Node runtime은시작 시 마이그레이션을 적용한다. 앱 수정은 없다. 원본 실패·예산부족이면현재30분 유효규칙/비교불가 정책이 작동한다. 대표 격자 밖의전체앱 응답은 별도의 전국 기본예보·환경·지역 해석 전환이 남아 있다.
