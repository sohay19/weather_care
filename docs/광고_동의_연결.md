# 광고 동의 연결

2026-09-11 사용자 승인으로 Google UMP 흐름을 구현했다.

- 앱 첫 화면 표시 후 매 프로세스 시작마다 동의 정보를 갱신한다. 필요한 경우에만 UMP 화면을 표시한다. 모든 한국 사용자에게 항상 팝업이 뜬다는 의미는 아니다.
- `canRequestAds()` 확인 후 Mobile Ads를 프로세스당 한 번 초기화한다. 이 값은 개인화 광고 동의 자체를 뜻하지 않는다.
- 정보 갱신·화면·조회 오류 시 이 앱은 보수적으로 광고 준비를 막고 설정에 재시도를 제공한다. 날씨 시작을 기다리게 하지 않는다.
- UMP가 요구하면 설정에 `광고 개인정보 선택`을 표시한다. 변경 중에는 광고 요청 가능 상태를 내리고, 닫힌 뒤 다시 확인한다. SDK 초기화를 취소하거나 이미 전달된 정보를 삭제하는 기능은 아니다.
- Analytics 선택 동의를 광고 동의로 사용하지 않는다. Analytics의 광고 관련 consent 거부 설정은 그대로 유지한다. UMP 선택이 Firebase 분석 수집을 켜도록 연결하지 않는다.
- 실제 광고 표시 코드는 아직 없다. 이후 모든 광고 로드 경로는 이 컨트롤러의 최신 `canRequestAds` 및 busy/error 상태를 확인하고, 선택 변경 시 기존 광고를 폐기해야 한다. 수익화·광고 개인화 동작 완료로 보지 않는다.

## 운영 연결 전 필요한 작업

1. Android Manifest의 샘플 AdMob 앱 ID를 실제 등록한 Android 앱 ID로 교체한다. iOS Info.plist에는 실제 iOS 앱의 GADApplicationIdentifier가 필요하다. 임의 ID를 만들지 않는다.
2. AdMob의 개인정보 보호 및 메시지에서 대상 앱·지역·메시지·공개 개인정보처리방침 URL을 검토하고 게시한다. 대상 연령 및 아동 관련 설정은 운영자가 별도 확정해야 한다.
3. 테스트 기기에서 첫 동의, 거부, 재실행, 선택 변경, 오프라인, 메시지 오류를 확인한다. 지역 강제/동의 reset은 테스트 전용이며 운영 코드에는 넣지 않는다.
4. 이 작업은 앱 코드와 가짜 의존성을 이용한 테스트까지다. 운영 콘솔 변경, 실기 UMP 화면, iOS 빌드, 실제 광고 발송은 수행하지 않았다. 네이티브 SDK 자체 전송까지 없다고 보장하지 않는다.

근거: [Google UMP Flutter 안내](https://developers.google.com/admob/flutter/privacy), [Mobile Ads 설정](https://developers.google.com/admob/flutter/quick-start).
