# 전국 GPS 전환 구현·검증

2026-10-04 구현·검증 기록이다. **2026-10-08 전국 수집 서버·DB·SGIS 경계 운영 배포 후 10/9 필수 공통 캐시 197/197과 여행지 조회 HTTP 200을 확인했다.** 최신 상태와 제공처 결측·풍향 일부 미제공 제한은 [운영 전국 캐시 확보](운영_전국캐시_확보_20261009.md)를 따른다. 아래 ‘미배포’ 표기는 당시 작업 이력이다. 기존 미커밋 수정은 보존했고 커밋·푸시는 하지 않았다. 이전 문서의 ‘전환 미완료’와 과거 예산 표는 작업 이력이며, 수집 정책은 이 문서와 최신 예산 JSON을 따른다.

## GPS 지역명을 쓰는 방법

앱은 이미 GPS의 위·경도와 한국어 지역명을 서버에 보낸다. 추가 지도 인증키 없이 그 지역명을 기상청 행정구역 코드에 연결한다.

| 자료 단위 | 요청 위치 연결 | 수집·캐시 단위 |
|---|---|---|
| 기온·습도·바람·강수 실황, 기본 예보 | 실제 GPS의 `nx,ny` | 전국 149×253 원본 |
| 자외선 | GPS 지역명 → 공식 행정구역 코드 | 전국 모든 지역·모든 페이지 |
| 중기예보·대기질 예보 | 확인된 지역명·코드 → 제공처 예보구역 | 제공처 전국 지원 구역 |
| 시정·과거 일 관측·현재 대기질 | 실제 GPS에서 관측소 선택 | 전국 관측소 원본 |
| 강수 분석·레이더 | 실제 GPS를 전국 원본에 대입 | 전국 분석·레이더 원본 |
| 특보·도로살얼음·도로통제 | 실제 GPS로 제공처 구역·도로 연결 | 전국 구역·도로 원본 |
| 일출·일몰·체감온도·추천 | 실제 GPS·확보한 기상값으로 계산 | 계산값, 별도 제공처 호출 없음 |

예를 들어 시흥시 은행동은 행정코드 `4139054000`, 예보 격자 `57,124`이다. 자외선은 은행동 코드로 찾고 기온·예보는 해당 GPS 격자에서 읽는다. 지역명을 써서 모든 기상값을 동 중심의 한 격자로 바꾸는 방식은 쓰지 않는다.

전체 동 이름을 먼저 찾는다. 법정동과 행정동 이름 차이 등으로 동 연결이 되지 않으면 확인 가능한 상위 시·군·구를 사용한다. 같은 이름의 고성·광주 등은 해당 이름의 후보 안에서 GPS로 구분한다. 이름이 없는 GPS를 가까운 다른 동에 임의로 배정하지 않는다. 확인할 이름·코드가 없으면 행정구역 자료는 미확인 상태를 반환한다.

앱 목록에는 `2815555000`이 용유동·운서2동에 중복되어 있었다. 두 동의 개별 코드 연결을 확정하지 않고 검증된 상위 영종구를 사용한다. 운서1동 `2815554000`은 개별 연결된다. 전국 UV 응답에 있는 13개 상위 시 코드를 추가해 수원시·성남시 등 시 단위 이름도 연결했다. 확정된 코드 목록 3,849개는 이번 실제 UV 응답에 모두 존재했다. 원본 UV 3,851지역은 필터링 없이 저장한다.

확인된 GPS 지역명·코드는 동일 좌표의 알림에도 재사용한다. 원시 GPS를 키에 노출하지 않고 좌표 해시를 사용하며, 동일 정보는 매 요청마다 쓰지 않는다. 앱 활동 없는 알림을 위해 지역 정보는 최대 365일 유지하고 정리한다. 이 보존 기간은 날씨 값의 유효기간과 다르다.

## 구현한 수집·조회

- 대표 1,633격자 순회로 기본 예보·환경·주간 자료를 만드는 수집 경로를 전국 원본 수집으로 교체했다. 설치가 0개여도 수집한다. 지역별 예보·환경·시정 사본을 새로 만들지 않는다.
- 실황은 앞서 구현한 전국 37,697셀·72시간 원본을 그대로 사용한다. 11:50~11:59는 11:40, 12:00~12:09는 11:50을 사용한다. AWS 분 관측 대체는 없다. 빠른 작업이 먼저 수집한 회차도 실제 첫 HTTP는 필수 호출로 집계하고, 누락된 선택 변수를 다음 작업에서 보충한다.
- 기본 예보는 APIHub 전국 격자 파일을 사용한다. TMP·REH·WSD·VEC·SKY·PTY·POP·PCP·SNO 9변수와 TMN·TMX를 저장한다. 일 최저·최고는 06시·15시 유효시각을 요청하며, 오늘 최저는 02시 발표도 확보한다. 실제 05시 발표의 오늘 06시 TMN은 전 셀이 결측이었고, 02시 발표에는 9,295셀이 유효했다.
- 한 유효시각의 9변수가 같은 발표에서 모두 저장되어야 그 발표를 선택한다. 최신 일부 변수만 도착하면 이전 완성 묶음을 사용한다. 손상된 읽기 블록은 진단 로그를 남기고 이전 완성 원본을 선택한다.
- 37,697셀을 Float64로 보존하고 512셀 단위 gzip 블록으로 저장한다. 조회할 때 해당 GPS 블록만 풀며, 다른 대표 격자로 대체하지 않는다. 공식 결측 `-99`, `-999`도 원본에서 보존한다. 예보 원본은 유효시각이 지난 뒤 2일까지 유지하므로 수집 실패 중에도 아직 미래에 해당하는 이전 발표를 제거하지 않는다.
- 연장 마지막 날은 공식 제공 간격인 3시간 슬롯만 수집한다. 풍속·강수량·신적설의 정성 코드를 m/s·mm·cm로 해석하지 않고 구분해서 보존한다. [기상청 격자자료 명세와 예보기간 변경 참고자료](https://apihub.kma.go.kr/apiList.do?seqApi=10)를 확인했다.
- 자외선은 `areaNo=`로 전국 페이지를 수집한다. 합계·중복 코드·발표시각·페이지 누락을 검증한 뒤 한 번에 게시한다. 빈 값은 0으로 처리하지 않는다. 실제 GPS의 코드와 다른 이전 지역 캐시의 UV는 채택하지 않는다.
- 시정은 ASOS 전국 VS 원본의 유효 관측소 전체에서 실제 GPS와 가장 가까운 곳을 고른다. 기온 자료가 없는 관측소를 제외하던 결합을 제거했다. 30km 안의 관측소가 없으면 더 먼 최근접 관측소도 사용하고 실제 관측시각·거리를 제공한다. 관측 후 3시간 이내 조건은 유지한다. VS 조회가 실패하면 해당 원본을 완료로 표시하지 않고 이전 정상 원본을 유지한다. 시정 수집에 TA·HM·WS를 추가 호출하지 않는다.
- 과거 일 관측은 독립 AWS 일 자료 4지표를 전국 관측소 단위로 저장한다. 일부 지표 실패를 완료 날짜로 표시하지 않고 재수집하며 기존 정상 값을 합친다. 빈 적설 응답을 ‘관측된 0’으로 만들지 않는다. 이 AWS 일 자료는 현재 실황 대체와 별개다.
- 대기질은 전국 17시도 원본을 유지하고 측정소 목록을 24시간 공유한다. 중기예보는 기온 176·육상 10개 지원 구역 원본을 공유한다. 특보·강수·도로 자료도 전국 원본에서 GPS를 연결한다.
- 메인·오늘·주간·위젯·알림은 공통 전국 자료를 읽는다. `COLLECTED_REGION` 존재 여부로 GPS 요청을 먼저 차단하던 경로를 제거했다. 앱 날씨 조회·어제 비교·알림 판정에서 외부 기상 API를 호출하지 않는다.
- 배포 전 기존의 같은 격자 캐시는 전환 중 호환용으로만 읽을 수 있다. 기존 대표 목록·옛 제공처 함수 일부는 호환·테스트용으로 남아 있지만 새 전국 수집에 쓰이지 않는다. `NATIONWIDE_PRECOLLECT_ENABLED`에 따른 시작 프리워밍 선택과 별개로 정규 수집은 전국 원본을 수집한다.

## 겨울에 한도를 넘기지 않는 주기

겨울 분기는 기존 도로살얼음 시즌인 **11월15일~3월15일**을 사용한다.

| 원본 | 비겨울 | 겨울 |
|---|---|---|
| 10분 실황 | 직전 10분 회차, 6변수 | 동일 |
| 가까운 24시간 단기예보 | 매 발표, 3시간 | 동일 |
| 먼 기간 단기예보 | 05·17시 발표, 하루 2회 | 17시 발표, 하루 1회 |
| TMN·TMX | 최신 발표의 06·15시 값과 오늘 02시 보충 | 동일 |
| 전국 강수 분석·레이더 | 30분 | 30분 |
| 도로살얼음 | 시즌 밖 호출 없음 | 12파일, 30분 |
| ASOS 시정 | 시간별 | 동일 |
| 중기예보 | 하루 2회 | 동일 |
| 특보·구역 목록 | 특보 30분·목록 24시간 | 동일 |
| 독립 AWS 일 관측 | 새 완료 날짜, 하루 4요청 | 동일 |

모든 격자는 그대로 유지한다. 용량 절약은 먼 기간 예보와 큰 전국 강수 원본의 갱신 주기로 한다. 겨울 먼 기간의 발표는 최대 하루 간격으로 갱신되며, 가까운 24시간은 계속 3시간 갱신이다. 실패 재확인과 초기 보충은 별도 예산을 사용한다.

## 제공처별 일 합계

정상 수집 주기를 기준으로 한 보수적 예상이다. APIHub 재시도 10%, 다른 제공처 재시도 20%는 계획 가정이며 실측 실패율이 아니다. GB는 10억 바이트다.

| 제공처 | 필수 호출 합계 | 재시도 예상 추가 | 총합 | 한도·전제 |
|---|---:|---:|---:|---|
| APIHub 비겨울 | 4,224회 / 2.721GB | 423회 / 0.272GB | 4,647회 / 2.993GB | 일반 20,000회·5GB, 내부 18,000회·4.5GB |
| APIHub 겨울 | 4,341회 / 3.774GB | 435회 / 0.377GB | 4,776회 / 4.151GB | 동일 |
| 에어코리아 | 425회 | 86회 | 511회 | 운영계정 신청 전제로 문제없음 |
| ITS | 144회 | 29회 | 173회 | 사용자 전제로 한도 문제없음 |
| 기상청 공공데이터포털 UV | 32회 | 7회 | 39회 | 운영계정 전제, APIHub 합계와 별도 |

APIHub 일반회원 한도는 [공식 이용안내](https://apihub.kma.go.kr/apiInfo.do)에서 확인했다. 공공데이터포털 운영계정을 APIHub 기관회원 한도로 해석하지 않는다.

| APIHub 필수 원본 | 비겨울 요청 | 겨울 요청 | 일 예상 용량 |
|---|---:|---:|---:|
| 전국 10분 실황 6변수 | 864 | 864 | 0.295GB |
| 전국 단기예보 9변수·일 최저최고 | 2,815 | 2,356 | 비겨울 0.961GB / 겨울 0.804GB |
| 특보·구역 목록 | 49 | 49 | 0.013GB |
| ASOS 시정 전용 1지표 | 24 | 24 | 0.003GB |
| 독립 AWS 일 관측 4지표 | 4 | 4 | 0.002GB |
| 중기 기온176·육상10 × 하루2회 | 372 | 372 | 0.003GB |
| 전국 강수 분석·레이더 2파일 × 48회 | 96 | 96 | 1.444GB |
| 도로살얼음 12파일 × 48회 | 0 | 576 | 겨울 1.210GB |

전국 예보 요청 수는 실제 운영 함수 `nationwideForecastPlan`을 이틀 준비 후 하루 동안 10분 간격으로 실행하고 `(발표,유효시각,변수)` 중복을 제거해 산출했다. 비겨울 2,815파일·겨울 2,356파일이다. 연장 마지막 날에 존재하지 않는 1시간 슬롯을 합산하지 않는다. 파일당 341,297B는 이번 실제 응답 표본이다. 그 외 용량은 기존 설계 표본·보수적 배정이다.

캐시가 전혀 없는 시작 일자도 하루 중 모든 시작 시각을 비교했다. 예보는 최대 비겨울 3,824·겨울 3,365파일이다. 여기에 어제 실황 3변수×144회차, 과거 일 관측 7일 범위, 이전 중기 186파일, 초기 전국 강수 2파일을 추가했다.

| 빈 캐시 시작 일자 | 필수 요청·예상 용량 | 초기 재시도 최대 배정 포함 용량 |
|---|---:|---:|
| 비겨울 | 5,853회 / 3.256GB | 3.356GB |
| 겨울 | 5,970회 / 4.309GB | 4.409GB |

초기 재시도는 **첫 24시간 100MB**, 이후는 **하루 400MB**를 모든 APIHub 작업이 공유한다. 초기 표에는 재시도 요청 수를 임의로 환산하지 않았다. 작은 오류 응답과 큰 레이더 재시도의 용량 차이가 크며, 전체 요청 수는 별도로 내부 18,000회에서 차단한다.

APIHub 실제 HTTP마다 먼저 최대 응답 크기를 원자적으로 예약하고, 성공·오류 응답을 다 읽으면 실수신량으로 정산한다. 미발표 확인에서 중단된 나머지 변수는 호출 수에 넣지 않는다. 불완전 전송·시간 초과는 예약을 유지한다. 상한보다 큰 응답은 중단하고 이미 받은 초과 바이트도 기록한다. 예약·정산은 실제 호출 시작의 KST 일자를 사용한다. 로그에 상태·수신 바이트·소요 시간을 남기고 인증키·요청 URL 원문은 남기지 않는다. 전국 예보 인증·공급자 한도·호출 제한 오류는 배치를 중단한다.

예상 용량 증가나 실패로 내부 한도에 도달하면 추가 외부 호출을 차단하고 이전 정상 캐시를 유지한다. 모든 격자의 최신 숫자를 무조건 확보할 수 있다는 보장은 아니다. 같은 계정으로 다른 프로그램이나 수동 호출을 하면 실제 제공처 한도에는 합산되지만 서버 장부에는 자동 기록되지 않는다.
