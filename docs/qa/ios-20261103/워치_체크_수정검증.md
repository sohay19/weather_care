# 워치 체크 초기화 수정 및 검증

2026-11-03, iOS 18.6와 watchOS 11.5 전용 시뮬레이터에서 수정본을 설치하고 검증했다. **구로1동 → 대치1동 → 구로1동 전환 후 기존 체크가 유지되며, 구역 삭제는 해당 구역의 체크만 제거한다.**

## 수정 내용

- 날씨 캐시의 `clear`는 이전 날씨를 숨기는 역할만 수행하고 체크 기록을 보존한다. 조회 실패·구역 전환의 일시적인 날씨 초기화도 같은 방식이다.
- 구역 삭제 확인 후에는 해당 구역 체크만, 서버 데이터 삭제 완료 후에는 전체 체크를 지우는 별도 경로를 호출한다. 삭제 취소 시에는 호출하지 않는다.
- iPhone은 삭제 대상별 `checkResetTokens`를 저장하고 이후의 전체 스냅샷에도 포함한다. 중간 전송이 다음 전송과 합쳐져도 삭제 요청이 남는다. 워치는 처음 받은 토큰만 처리하므로 이후 새로 체크한 항목을 반복해서 지우지 않는다.
- 워치의 표시 상태도 저장된 체크를 다시 읽어 임시 날씨 초기화 뒤 기록과 화면이 일치하도록 수정했다.

## 실제 앱 검증

HTML 시안이나 시험 날씨 주입 없이 앱의 수동 지역 선택 UI와 운영 날씨를 사용했다. 창·데스크톱을 전환하지 않고 simctl/XCTest로 조작했다.

| 순서 | 실제 확인 결과 |
|---|---|
| 구로1동 시작 | 선크림 체크 완료 상태 확인. |
| 대치1동 추가·전환 | 구로1동 체크가 저장소에 남고, 대치1동 선크림은 미완료로 표시된다. |
| 대치1동 체크·새로고침 | 두 구역의 체크가 별도 키로 함께 유지된다. |
| 구로1동 복귀 | 기존 선크림 체크 완료 표시 유지. 폰/워치 전체 스냅샷 일치. |
| iPhone 앱 재실행 | 두 구역의 체크 보존. |
| 워치 앱 재실행 | 두 구역의 체크 보존, 구로1동 완료 표시 확인. |
| 대치1동 삭제 | 대치1동 저장/알림 선택과 체크만 제거되고, 구로1동의 체크·날씨는 유지된다. 삭제 토큰이 폰/워치에 동일하게 전달된다. |

실제 삭제 검증 후 저장 구역은 구로1동 하나, 구역 알림은 기존 GPS/구로1동 선택, 선크림 체크는 기존 완료 상태로 복원했다. 운영 서버 전체 데이터 삭제는 실행하지 않았다.

## 자동 검사

- Flutter 관련 4개 파일 회귀: 기본 플랫폼 106개, iOS 기준 106개 모두 통과.
- Swift 모델 검사: 7개 모두 통과. 임시 clear·지역 왕복·지역/한국 날짜별 체크 분리·대상 구역 삭제·병합된 전송·전체 삭제·같은 삭제 토큰 재수신·이전 revision 거부를 포함한다.
- Flutter 검사에서 구역 삭제 취소 시 미호출, 구역별 삭제 대상, 서버 데이터 삭제 완료 시 전체 체크 삭제 호출과 iOS 메서드 채널 계약을 확인했다.
- 관련 Dart 4파일 정적 분석 이슈 없음. iPhone+Watch+WidgetKit 동반 Debug 빌드 성공.
- 전체 데이터 삭제 및 전송 병합은 자동 검사로 검증했다. 실물 Apple Watch·장시간 오프라인/백그라운드는 별도 검증 범위다.
