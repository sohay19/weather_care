# 연장 풍향 요청 제외와 302격자 실황 보충 설계

## 풍향 수정 및 운영 반영

사용자의 05시·17시 풍향 누락 제외 요청에 따라, 정상으로 확인된 일반 구간 풍향은 유지하고 마지막 연장 구간 VEC 요청만 수집 계획에서 제거했다. 현재 전체 예보기간을 수집하는 발표는 비겨울 05·17시, 겨울 17시다.

- 05시 발표: 발표일 기준 3일 뒤 00시 풍향까지 유지, 이후 03·06·09·12·15·18·21·다음 00시 VEC 8개 제외.
- 17시 발표: 발표일 기준 4일 뒤 00시 풍향까지 유지, 이후 같은 8시각 VEC 제외.
- 제외 구간의 TMP·REH·WSD·SKY·PTY·POP·PCP·SNO 및 최저·최고기온은 계속 수집한다.
- 풍향 제외 회차의 다른 예보는 기존 필수 8항목 계약에 따라 제공하며, 없는 풍향을 임의 값이나 이전 발표 풍향으로 채우지 않는다.
- 한 발표당 기본 요청 8개 감소, 일 고유 요청은 비겨울 16개·겨울 8개 감소한다. 해당 VEC의 주기별 반복 재시도도 수집 계획에서 제외된다. 실제 줄어드는 바이트는 빈 응답 자체의 0B와 시간초과 예약 등을 구분해야 한다.

변경 파일은 `weather_care_server/src/providers/weather/kmaNationwideForecastProvider.ts`다. Node 회귀 테스트는 05·17시 비겨울과 겨울의 연장 경계, 정상 VEC 보존, 마지막 8시각 필수 8항목 보존을 검증했다. TypeScript 타입 검사 및 Node 64개·Worker 414개, 총 478개 테스트가 통과했다.

## 실황 해결 방안: 같은 시각 인근 유효 격자 보충

**이미 수집한 전국 10분 실황에서, 요청 격자가 결측일 때 같은 관측시각의 가장 가까운 유효 격자 묶음을 사용하도록 서버에 보충 경로를 추가하는 방법을 추천한다.** 실제 요청 GPS·격자·지역명은 유지하고 값의 출처 격자만 별도 기록한다. 특정 대표 행정격자로 모든 사용자를 묶지 않는다.

현재 원본은 149×253 전체 격자 배열과 72시간 이력으로 저장되어 있다. 따라서 보충 후보를 찾으려는 목적의 추가 API 호출은 없다. 원본 결측 셀은 그대로 보존하고 보충 결과는 별도 캐시에 저장한다.

### 6항목 후보 전수 확인

11:46 KST 검사에서 **11:30 실황 원본**을 다시 대조했다. 유효 원본 격자는 4,444개이고, 기온·습도·풍속뿐 아니라 풍향·강수형태·1시간 강수량까지 모두 유효한 격자도 4,444개다. 이 묶음으로 조사 대상 302격자 전부에 보충 후보가 존재한다.

| 결측 격자 중심과 출처 격자 중심 거리 | 대상 수 |
|---|---:|
| 10km 이내 | 220 |
| 10km 초과~20km 이내 | 60 |
| 20km 초과 | 22 |
| 합계 | 302 |

10km 이내 220개, 15km 이내 260개, 20km 이내 280개다. 가장 먼 경우 약 51.5km다. 이번 계산은 구면 대권거리로 최대 51.42km이며, 앞선 같은 후보의 WGS84 타원체 거리 계산은 51.54km였다. **실제 GPS 기준 거리는 요청 시 다시 계산해야 한다.** 한 시각의 전수 후보 검증이며 미래 모든 회차의 6항목 가용성을 보장하지 않는다.

후보 원본과 거리 목록은 [302격자 실황 6항목 후보 JSON](302격자_실황6항목_보충후보_20261009.json)에 있다. 이 검사에서 보충값을 운영 캐시에 쓰지는 않았다.

### 적용 흐름과 데이터 계약

1. 기존대로 준비된 이전 10분 슬롯의 동일 격자 원본을 우선 선택한다. 기존 실황 유효기간 30분을 유지한다.
2. 원본 셀의 지속 결측을 발견하면 같은 관측시각의 유효 6항목을 가진 인근 격자를 찾는다. 파일 자체가 없는 회차는 셀 결측과 구분한다. 전체 항목이 있는 이전 회차를 선택한다면 그 실제 `observedAt`을 유지하고 30분 범위를 넘기지 않는다.
3. 가능한 경우 동일 섬·육지 연결과 지형 조건을 고려해 후보 순서를 정하고, 후보가 없으면 직선거리 최단 유효 격자를 선택한다. 행정구역명이 같다는 이유만으로 더 먼 출처를 강제하지 않는다. 단순 거리가 최단이라는 사실이 국지 기상 정확도를 보장하지 않는다.
4. 기온·습도·풍속·풍향·강수형태·강수량을 같은 출처 격자·시각에서 가져온다. 없는 항목을 0이나 ‘비 없음’으로 만들지 않고, 서로 다른 시각의 항목을 한 묶음으로 합치지 않는다.
5. 요청 nx·ny/GPS와 원본 nx·ny, 거리, 관측시각을 따로 저장한다. `locationMatch: NEAREST_GRID`, `NEARBY_GRID_OBSERVATION`, 먼 거리에는 `DISTANT_GRID_OBSERVATION` 같은 명시적인 품질 정보를 응답한다. 타입의 `EXACT_GRID`를 재사용하여 출처 일치로 오인시키지 않는다.
6. 전체 대상의 결측 여부는 원본에서 자동 판정한다. 이번 302개를 하드코딩한 제외 목록으로 유지하지 않는다. 최신 경계 변경이나 유효 영역 변경도 다시 판정한다.
7. 보충 캐시는 원본 관측시각을 키 또는 버전으로 삼아 만료·교체하고, 원본 72시간 이력에서 복원 가능하게 한다. 읽기마다 전국 배열을 반복 탐색하지 않도록 관측시각별 유효 후보 목록과 결과를 재사용한다. 후보가 없으면 실패 사유와 실제 자료 나이를 기록하며, 예보를 실황으로 바꾸지 않는다.
8. 어제 동시각 비교는 오늘·어제 두 원본에 공통으로 유효한 출처 격자를 선정하거나 동일 출처로 고정한다. 날짜마다 다른 격자를 독립 선택하면 위치 차이가 날씨 변화로 섞일 수 있으므로 비교 불가 시 사유를 표시한다.

이 설계에서는 AWS 대체 호출을 복원하지 않는다. 시정·대기질 등의 기존 관측소 보충 정책과도 별개다. 원본 격자의 실황 값을 새로 생산하는 것은 아니며 **인근 위치의 실제 실황을 대신 보여주는 기능**이다.

### 정확도·호출 한도·앱 표시

- APIHub·에어코리아·ITS 추가 호출: **각각 0회/일**. 비겨울·겨울 공통. 기존 전국 실황 수집 호출 수와 본문량을 증가시키지 않는다.
- 추가 비용은 서버의 후보 탐색과 별도 보충 캐시 저장이다. 최신 대상 결과만 유지하면 수백 개 묶음 규모이고, 이력은 기존 전국 원본을 재사용할 수 있다.
- 20km가 넘는 22격자는 관측값 차이가 커질 수 있다. 특히 비·눈·안개·돌풍은 가까운 곳에서도 달라져 해당 GPS의 실제 발생을 확정하는 안내에 그대로 사용하지 않아야 한다. 먼 출처는 낮은 공간 신뢰도로 명시하고 알림 판단도 이 정보를 사용해야 한다.
- 서버만 수정해 값을 응답할 수 있지만, 현재 앱의 `CurrentWeather`는 출처 격자·거리·품질 정보를 읽거나 메인 카드에 표시하지 않는다. ‘인근 실황 · 약 ○km’와 자료 시각을 정확히 표시하려면 앱 모델·표시를 함께 반영해야 한다. 이번 작업에서는 앱을 수정하지 않았다.
- 해당 GPS에서 직접 관측한 값이 반드시 필요한 조건은 이번 인근 격자 보충만으로 충족할 수 없다. 그 조건에는 원본 제공 영역 확대 또는 해당 위치의 관측자료가 필요하다.

**현재 상태:** 풍향 요청 제외는 운영 반영 완료. 실황 보충은 302개·6항목의 후보 전수 검증과 설계까지 완료했으며 런타임에 구현하지 않았다.
