## 적용 내용

- 지정시간 요약 제목을 **오늘자 준비물 😊**로 통일했다.
- 사용자가 확정한 추위·자외선·비·더위·미세먼지·눈 안내 문장을 반영했다. 조사 을/를, 시간 양쪽 오전/오후와 `~`, 마침표 및 추위 다음 자외선 문장의 ‘챙겨 입고,’ 연결을 적용했다.
- 같은 사유·시간대의 준비물을 한 문장으로 묶는다. 기존 최대 3개 물품 선택·우선순위·오늘 자정까지의 판단·설치별 설정·알림 이동 목적지는 유지한다.
- 예보가 발송 시점부터 자정까지 끊김 없이 해당 물품을 뒷받침할 때만 아침에는 ‘오늘은 하루 종일’, 이후에는 ‘지금부터 밤까지’를 쓴다. 준비물이 없는 브리핑의 기존 본문과 독립 긴급알림은 유지한다.
- 자외선 문구는 사용자 확정안 ‘자외선이 강하니’를 사용한다. 선크림 추천 기준 UV3 이상은 변경하지 않았다.

## 배포 범위와 검증

실행 소스 **src/notification/notificationBuilder.ts 한 파일**만 각 환경에서 원자 교체했다. 각 서버의 실제 소스와 사용자 마이그레이션 177개 manifest를 기준으로 후보를 만들었으며 나머지 파일은 동일하다.

- 운영: `/opt/weather-care/releases/20261023-full-production/weather_care_server`
- 시험: `/opt/weather-care/releases/20261023-full-test/weather_care_server`
- 운영 API PID708773→719710, 시험 API704480→719616, 운영 스케줄러704661→719777. 모두 active이며 스케줄러의 정상 시작 이벤트를 확인했다.
- 각 환경 실제 소스 기반 후보 전체 TypeScript 검사와 관련 4개 시험 파일 **각 84개, 총 168개**를 통과했다.
- 서버의 Linux 의존성으로 각 후보 구문 검사 및 합성 예보 5종 생성 결과를 확인하고, 설치 후에도 각각 같은 5종을 확인했다. 총 20개 생성 사례이며 검증 과정의 FCM 전송은 0건이다.
- 은행동의 health·Main·PREPARATION_18 Today·주간·위젯을 운영/시험 배포 전후에 조회해 **총 20건 모두 HTTP200**을 확인했다. 기존 최상위 필드/자료형과 주간 upcomingDays·오늘 preparationPeriods를 유지했다.
- 운영/시험 전체 소스 manifest, 사용자/공용 날씨 DB 스키마, 환경 파일·서비스 정의·패키지·잠금 파일·TypeScript 설정 해시가 예상과 일치한다. DB 마이그레이션·사용자 설정 직접 변경·수동 수집·앱 빌드/설치·스토어 배포는 하지 않았다. 스케줄러 재시작 시 기존 정상 시작 절차는 실행된다.

첫 시도는 서버에 개발용 tsc가 없어 파일 교체 전에 중단됐다. 로컬에서 실제 서버 후보의 전체 타입 검사를 완료한 것을 확인하고, Linux에서는 설치된 esbuild 구문 검사와 실제 모듈 실행 검사로 바꿔 재시도했다. 제품 소스 변경이나 원복 없이 완료했다.
