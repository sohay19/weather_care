## 이 PC의 PowerShell에서 직접 실행

APIHub의 인증키를 입력한다. 공공데이터포털 서비스키와 구분한다. 한 번 실행하면 전국 기온 파일1개를 요청하며 APIHub의 실제 공유 한도를 소비한다. 직접 호출은 우리 서버의 api_usage_daily 예약에 기록되지 않는다.

```powershell
$apiHubKey = [System.Net.NetworkCredential]::new(
  '', (Read-Host 'APIHub 인증키' -AsSecureString)
).Password
$tmfc = '202610041120'
$variable = 'T1H'
$outputFile = Join-Path (Get-Location) "실황_${tmfc}_${variable}.txt"

curl.exe --get 'https://apihub.kma.go.kr/api/typ01/cgi-bin/url/nph-dfs_odam_grd' `
  --data-urlencode "authKey=$apiHubKey" `
  --data-urlencode "tmfc=$tmfc" `
  --data-urlencode "vars=$variable" `
  --max-time 30 --output "$outputFile" `
  --write-out 'HTTP %{http_code} / %{time_total}s / %{size_download} bytes\n'

if ($LASTEXITCODE -eq 0) {
  Get-Content -LiteralPath $outputFile -Encoding UTF8 -TotalCount 8
}
```

`$tmfc`는 **한국 시각YYYYMMDDHHmm**이다. 예시는2026년10월4일11:20이며 끝의 분은00·10·20·30·40·50이다. 이 날짜를 다른 날에 사용하면 과거 회차를 요청하는 것이다. 다른 변수는 `$variable`을 바꿔 같은 명령을 다시 실행한다. 첫 키 입력 변수는 같은 PowerShell 창에서 재사용할 수 있다.

| 변수 | 의미 |
|---|---|
| T1H | 기온 |
| REH | 상대습도 |
| WSD | 풍속 |
| VEC | 풍향 |
| PTY | 강수형태 |
| RN1 | 1시간 강수량 |

응답은 전국149×253=37,697격자의 원본이며 단일 위치 JSON이 아니다. 정상 숫자 배열에 결측값이 들어갈 수 있어 숫자가 있는 것과 해당 GPS에 정상 값이 있는 것을 구분한다. HTTP200이어도 본문이 오류면 정상 자료가 아니다.

- `# dfs_file_read error (-1)`: 해당 파일을 읽지 못함. 요청 시각·제공 여부 등을 확인한다. 이 문자열만으로 서버 파일 미발표 원인을 완전히 확정하지 않는다.
- 인증/활용 신청 오류: APIHub 키와 해당 API 활용 권한을 확인한다.
- 호출/용량 초과 문구: APIHub 공유 한도 문제다.
- curl 시간 초과: 30초 내 완료하지 못한 것이며 미발표와 구분한다.

실제 제공 지연을 비교할 때는 같은11:20파일을11:24·11:26 등 실제 그 시각에 요청하고 요청/응답시각을 기록해야 한다. 나중에11:20파일을 받았다고11:24에도준비됐다고추론하지않는다.

## 기준시각이 지난 실황도 실패했는지와 앱11:51 응답

### 이미10분 이상 지난 직전 회차의 실패

운영 로그에서 직전 회차 실패와 그 직후 전국AWS성공을 같은 대상회차 관계로 대조했다. AWS작업의targetObservedAt-10분이 실패 PREVIOUS.targetObservedAt과 일치하고 실패 뒤90초 내 완료한 경우를 연결했다. 10월3일~10월4일12:43까지 **전국1,633개 전체를AWS로보완한작업 중17회**(10월3일5·오늘12)에서 직전 실황 실패 기록이 함께 있었다. 이는 과거회차 요청도 실패한다는 증거이며 파일이 이미 정상 공개되었다는 직접 증거는 아니다.

| 실패 기록시각(KST) | 요청한 직전 실황 | 실패 분류 | 직후 AWS 결과 |
|---|---|---|---|
| 10월3일00:00:37 | 10월2일23:50 | TIMEOUT | 00:00:39 전국1,633격자 확보 |
| 10월3일00:50:39 | 10월3일00:40 | TIMEOUT | 00:50:40 전국1,633격자 확보 |

시각은 요청 시작이 아니라 실패/완료가 기록된 시각이다. 두 경우 모두10분 이상 지난 직전 회차를 요청했지만 응답 시간 초과가 발생했다. 이를 모두 미발표 때문에 실패한 것으로 설명하지 않는다. 요청 시각이 회차 시각을 넘었다는 사실만으로 파일 제공 완료와30초 이내 응답을 보장하지 않는다.

오늘11:50 부근도 확인했다.

- 11:50:14: 11:50회차 기온 실패, UNKNOWN.
- 11:50:16: 직전11:40격자값1,626개+AWS7개를저장.
- 11:52:28: 활성 위치에서11:50회차재시도실패, UNKNOWN·저장0.
- 11:51에11:50을조회하는별도정규작업은이구간로그에없다. 앱요청이직접실황API를조회하는경로도아니다. 정확히11:51실패라고바꿔표현하지않는다. UNKNOWN에서미발표를확정하지않는다.

### 앱 요청의 자료 시각

`/api/v1/weather/main`과`/today`의현재기온·습도·풍속등은해당격자의`COLLECTED_ULTRA_SHORT`캐시를읽고`currentFromUltraShortObservation`으로응답한다. 앱이11:51에요청했다고11:51관측을새로수집하거나자료시각을11:51로변경하지않는다. 현재자료기준은원본`current.observedAt`,응답생성시각은`generatedAt`이다.

| 11:51 요청 때 캐시 상태 | 현재 기온 등의 관측 기준 |
|---|---|
| 11:50격자실황확보 | 11:50 |
| 11:50실패·직전11:40확보 | 11:40 |
| AWS대체확보 | 선택관측소실제분관측시각(예11:48;예시이며이번7개실제시각은이력없어확정못함) |
| 최근수집실패·이전캐시유효 | 이전성공실황시각유지 |
| 캐시없음·30분초과 | 현재기온·체감·습도·풍속등미제공상태 |

20분을넘은관측은SOURCE_DELAYED,30분을넘으면현재실황수치를제외한다. AWS분관측은수집작업의now-2분까지9분전부터의범위를조회하고관측소별최신행을선택하므로11:50작업에서는대상11:39~11:48(양끝포함10분) 중실제사용가능한시각이다. 11:48은가능한종료시각이며확정값이아니다.

오늘11:51시점에는11:50:16에저장한대부분격자의11:40자료가응답대상이다. 7개AWS위치는해당관측소시각이며캐시이력이남지않아각자료의정확한시각·수치까지복원하지않는다. 위치별로다르고동시수집완료여부에도영향받는다.

현재카드와미래카드도구분한다. 앱의‘지금날씨’기온은`current`,‘미래예상날씨’는`nextForecast`다.11:51에는캐시의미래정시슬롯이정상일때12:00예보를선택한다. 현재하늘상태는예보를보충해쓰므로현재카드의모든항목이동일실황시각/출처라는의미는아니다.

코드근거: `api/weather.ts`의currentFromUltraShortObservation·nextForecastSnapshot, `collection/weatherCollectionJob.ts`의collectUltraShortObservations, `kmaAwsMinuteObservationProvider.ts`, 앱`main_tab.dart`. 이조사에서는운영로그읽기와코드확인만했고운영·로컬수집로직을변경하지않았다.
