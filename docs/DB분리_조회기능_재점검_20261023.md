# DB 분리 후 조회 기능 재점검

2026-10-23 17:35:23 KST에 운영·테스트 실제 API 점검을 완료했다. 인증이 포함된 오늘·주간 조회의 잘못된 DB 연결을 수정했고, 지역명 표기 수정도 양쪽 서버에 배포했다. 이번 검사에서 추가 조회 오류는 발견하지 않았다. 제공처 자료가 없는 경우와 미제공 기능은 아래처럼 구분한다.

## 수정과 배포

- 인증 날씨 조회: 사용자 인증·알림 설정을 공용 날씨 DB에서 읽던 두 곳을 환경별 사용자 DB로 수정했다. 수정 전 동일 요청503을 재현했고 수정 후200을 확인했다. 커밋 `247f595`, 태그 `v1.1.0`이며 후속 지역명 변경은 태그에 포함하지 않는다.
- 서버 지역명: 메인·오늘·주간·위젯에서 `구로제3동`을 `구로3동`으로 표시한다. Today의 공식 이름 재조회와 위젯 요청 이름 덮어쓰기도 처리했다. 공식 코드·격자·원본·저장 키는 보존한다. 커밋 `0aaa0df`이며 운영·시험 모두 반영했다.
- 앱 지역명: GPS 기기명/서버명, 직접 선택·검색 결과·주소 결과·위젯에 같은 규칙을 적용했다. 거제1동·홍제1동·제주시의 고유 지명과 기존 저장 키는 보존한다. 커밋 `96035d0`이며 설치 앱에는 새 빌드/업데이트가 필요하다. 이번에는 앱 버전·서명 설정·기기 설치·스토어 등록을 변경하지 않았다.
- 테스트 검색 범위: Worker 검사에 무관한 빌드 백업의 Node 테스트가 포함되던 설정을 `test/**/*.test.ts`로 한정했다. 백업 파일을 삭제하거나 정상 테스트를 제외하지 않았다.

## DB와 수집 상태

- 운영 사용자: `weather-care-users-production.sqlite`, 시험 사용자: `weather-care-users-test.sqlite`, 공용 날씨: `weather-care-weather.sqlite`.
- 실제 API/스케줄러 프로세스의 DB 경로와 필수 테이블을 대조했다. 사용자 DB에 날씨 테이블이 없고 공용 DB에 사용자 인증·설정 테이블이 없음을 확인했다. 두 사용자 DB `quick_check(1)`은 `ok`다. 대용량 공용 DB 전체 무결성 검사는 이번 범위에 포함하지 않았다.
- 운영·시험 API와 운영 스케줄러는 모두active다. 확인 시 최신 격자 관측은17:20KST, 적재는17:30KST이며 단기예보는17시 발표분이다.
- 17:16KST 이후 확인 시점까지 운영 날씨 접근 로그의5xx는0건이다. 실제 로그 원문·개인 식별자·인증키는 점검 문서에 넣지 않았다.
- 각 조회 API뿐 아니라 수집 대상·예약 수집·정기 알림의 사용자/날씨 DB 전달 경로도 코드로 대조했다. 실제 수동 발송 없이 기존 Node 회귀 테스트로 환경별 설정·이력·중복 방지를 검증했다.
