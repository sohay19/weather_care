# 2026-11-03 iOS 시뮬레이터 검증

후속 상태: 워치 체크 초기화는 수정 후 구역 왕복·재실행·대상 구역 삭제 검증을 통과했다. [수정 및 재검증 기록](워치_체크_수정검증.md)을 참고한다. 아래 내용은 수정 전 종합 점검 기록이며, 워치 위젯 버전 불일치는 별도 미해결 항목이다.

금일 변경사항을 점검한 결과, 구역 관리와 날씨 연동은 정상이며 **워치 체크 기록 초기화 문제 1건**을 재현했다. 최신 빌드에서는 **워치 위젯 버전 불일치**도 확인했다. 이번 작업에서는 제품 코드를 수정하지 않았다.

## 환경과 범위

- Flutter 3.47.4, iPhone 16 Pro / iOS 18.6, Apple Watch Series 10 42mm / watchOS 11.5.
- 전용 iPhone `4EBFF416-CCE9-4F79-9C88-2C272BF821A7`, Watch `565FCA1F-E64D-4F95-AE9E-F2AEC188EE0D`.
- 사용자 데스크톱과 기존 iOS 26 시뮬레이터를 조작하지 않고 simctl/XCTest와 화면 캡처로 확인했다.
- 실제 앱 UI로 구로1동·대치1동을 선택하고 운영 날씨를 조회했다. 제품 데이터나 설정 파일에 시험 값을 주입하지 않았다.
- 상세 UI 조작은 1.1.4 동반 빌드에서 수행했다. 작업 중 추가된 `d160245`의 1.2.0 빌드 설정으로 재빌드하고 두 시뮬레이터에 설치·실행했다. 두 빌드의 Dart·Swift 제품 동작 소스는 같다.

## 발견 1: 다른 구역을 선택하면 워치 체크 기록 소실

1. 구로1동 준비물에서 선크림 또는 겉옷을 체크한다.
2. iPhone에서 대치1동으로 전환한다. 구로1동은 저장 목록에 그대로 둔다.
3. iPhone에서 구로1동으로 돌아온다.
4. 워치의 기존 체크가 미완료로 바뀌고 앱 그룹의 `preparation_checks`도 사라진다.

같은 지역에서 새로고침할 때는 체크가 유지됐다. 지역별 체크 보존 구현과 달리, 지역 전환이 전체 체크 삭제로 전달되는 문제다.

원인은 `home_screen.dart`의 `_handleSettingsChanged`에서 위치 변경 시 `_clearHomeWidget()`을 호출하고, `AppDelegate.swift`의 `clear`가 `WatchPhoneBridge.clear()`로 이어지기 때문이다. 워치의 `WatchCache.accept`는 이 삭제 상태를 받으면 전체 `preparation_checks`를 제거한다. 지역 전환용 자료 무효화와 실제 자료 삭제의 의미를 구분하는 수정이 필요하다.

- 전환 전: [체크된 선크림](워치_구역전환전_체크.png)
- 같은 지역 복귀 후: [체크 초기화](워치_구역복귀후_체크초기화.png)
- 구조화 근거: `verification.json`의 `roundtrip-guro`, 원본 접근성 트리 `watch-guro-checks-lost.txt`.

## 발견 2: 최신 워치 위젯 버전 불일치

최신 `d160245` 빌드의 실제 Info.plist를 확인한 결과다.

| 제품 | 버전 | 빌드 |
|---|---|---|
| iPhone 앱·위젯 | 1.2.0 | 26110300 |
| Apple Watch 앱 | 1.2.0 | 26110300 |
| Apple Watch 위젯 확장 | **1.1.4** | **26103000** |

`WeatherCareWatchWidgets`의 Debug·Profile·Release 설정이 이전 값이다. 시뮬레이터 빌드·설치·실행은 성공했다. 배포 전 확장 타깃 버전을 맞춰야 하며, 이번에는 Archive/App Store 검증을 실행하지 않았다.

## 근거와 제한

- 요약·해시·설정 상태: [verification.json](verification.json).
- UI 캡처: [순서 변경](구역_순서변경.png), [OFF 삭제 안내](알림OFF_삭제확인.png), [ON 삭제 안내](알림ON_삭제확인.png), [워치 습도 상세](워치_습도상세.png).
- 전체 로그·원본 접근성 트리·화면은 제외 경로 `weather_care_app/build/ios-qa-20261103`에 보존했다. 최초 검색 자동화는 포커스 뒤 라벨 변경으로 실패해 독립 테스트 제어기만 수정 후 재실행했다. 자동화 제어 재시도와 제품 문제를 구분했다.
- 실 APNs/FCM 수신, 강수·특보·정기 요약의 실제 발송, 실물 iPhone/Watch, 장시간 잠금·백그라운드 전달, 페이스 컴플리케이션, 스마트 스택 재검증, 큰 글자·VoiceOver 전체 동작은 이번 범위에서 확인하지 않았다. 삭제된 구역 알림 재진입·카탈로그 누락·등록 한도는 Flutter 회귀 검사 범위이며 실 푸시로 재현하지 않았다.
- 시험 구역 대치1동을 제거하고 원래 구로1동·GPS/구로1동 알림 선택·선크림 체크 상태로 복원했다. 전용 기기는 켜 두었으며, 제품 소스 수정·커밋·푸시·배포는 하지 않았다.
