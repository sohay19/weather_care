# 시험 서버 최신 기능 배포

2026년 10월 28일 **17:48:40 KST** 시험 서버 배포를 완료했다. 최종 서버 검증은 **17:50:07 KST**다.

## 해결한 문제

IDE의 기본 Debug 실행은 `weather-test-api.codesoha.com`을 사용한다. 시험 서버에는 새 구역별 알림 API와 출퇴근 시간 마이그레이션이 없어 새 앱의 설정 저장이 실패했다. 신규 경로의 일반 텍스트 404 응답을 앱이 `502 INVALID_RESPONSE`로 처리하며 `SettingsSaveState.serverFailed` 안내를 표시했다.

실행 중 앱의 서버 주소와 실패 상태를 VM 객체에서 직접 확인하고 시험 서버를 최신 운영 기능과 맞췄다. 기본 Debug 서버 주소·시험 접근 키·IDE 설정은 바꾸지 않았다.

## 적용 범위

- 설치 경로: `/opt/weather-care/releases/20261023-full-test/weather_care_server`
- 시험 사용자 DB: `/var/lib/weather-care/weather-care-users-test.sqlite`
- 운영 설치본과 다른 **16개** 소스·사용자 마이그레이션 파일만 반영했다. 최종 `src`·`node-migrations/users`의 **182개** 파일 해시가 운영과 일치한다.
- `0003_commute_notification_schedule.sql`: 출근 `07:00~10:00`, 퇴근 `17:00~20:00` 기본값 열 4개 추가.
- `0004_notification_regions.sql`: 구역별 구독·지역 상태·특보 상태 테이블 4개와 트리거 추가.
- 시험 API만 재시작했다. 운영 API·스케줄러의 프로세스와 소스, 운영 사용자 DB 스키마, 공용 날씨 DB 스키마를 보존했다.
- 시험용 알림 스케줄러는 기존 비활성 상태를 유지했다. 시험 접근 키·서비스 정의·환경 파일·패키지·공용 날씨 마이그레이션도 보존했다.

## 백업과 데이터 보존

- 서버 내부 백업: `/var/backups/weather-care/test-latest-20261028T084831Z/users-before.sqlite`
- 백업 디렉터리 0700·DB 파일 0600을 확인했다. 실제 사용자 DB를 다운로드하지 않았다.
- SQLite 온라인 백업 후 `BEGIN IMMEDIATE` 안에서 두 마이그레이션을 적용했다.
- 기존 모든 테이블의 원래 열·행을 해시와 건수로 비교해 일치함을 확인했다. **기존 알림 설정 34건**을 보존하고 기존 사용자에게 구역 구독을 자동 생성하지 않았다.
- 두 마이그레이션이 각각 한 번만 적용됐으며 운영과 시험 사용자 DB의 스키마 해시가 일치한다. `quick_check=ok`, 외래키 오류 0건이다.

## 복구와 제한

배포 도구는 실패 시 변경한 소스를 백업으로 복원하고 시험 API를 재시작하도록 구성했다. 추가한 DB 열·테이블은 보존해 배포 후 사용자 쓰기를 과거 DB 백업으로 덮어쓰지 않는다.

최초 사전 검사에서 시험 서버에 개발 의존성 `tsc`가 없어 중단됐으며 그 시점에는 DB·소스를 수정하지 않았다. 동일한 실제 운영 소스 스냅샷을 로컬에서 타입 검사하고 Linux에서 메모리 DB 검증 후 배포했다. 서버에 개발 의존성을 새로 설치하지 않았다.

과거 스토어 APK/IPA 실행·실제 푸시 도착을 이번 배포에서 확인한 것으로 확대하지 않는다. 앱·스토어 버전은 변경하지 않았다. 실행 도구와 상세 로그는 ignored `weather_care_server/build/test-latest-deploy-20261028`에 보관했다.
