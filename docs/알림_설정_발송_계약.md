# 알림 설정과 실제 발송 계약

2026-09-10 코드·테스트 대조 기준. 새로운 발송 정책이 아니라 현재 구현의 범위를 설명한다.

## 공통 조건

- 전체 `날씨 알림`이 켜지고 서버에 유효한 FCM 토큰이 등록되어야 발송 대상으로 조회된다. OS 권한·네트워크·채널 설정에 따른 실제 도착은 별개다.
- 앱의 알림 설정 API에는 전체 알림·시간·하위 12종의 14필드만 보낸다. 아래 기존 API 필드와 저장값은 이름을 바꾸지 않았다.
- 준비물 요약은 설정 시각을 다음 10분 경계로 올린 시각에 확인한다. 07:35 → 07:40, 23:55 → 다음 날 00:00이다. 저장된 사용자 시각 자체를 변경하지 않는다.
- 공식 특보·현재 비·많은 눈 대비·도로 안내는 준비물 요약 시각과 별개다. 서버는 현재 10분 간격으로 실행하므로 현상이 생긴 바로 그 순간의 도착을 보장하지 않는다.

## 화면·API·발송 연결

| 화면 항목 | API 필드 | 실제 적용 범위 |
| --- | --- | --- |
| 날씨 알림 | `notificationEnabled` | 모든 발송 대상의 상위 스위치 |
| 알림 시간 | `notificationTime` | 준비물 요약 확인 시각만 제어 |
| 우산 | `umbrellaEnabled` | 요약의 우산 추천 + 현재 비 안내의 필수 조건 |
| 양산 | `parasolEnabled` | 요약의 양산 추천 |
| 겉옷 | `outerwearEnabled` | 요약의 겉옷 추천; 앱 추천이 있어도 알림 적격 기준에 못 미치면 미포함 |
| 마스크 | `maskEnabled` | 요약의 마스크 추천 |
| 물 | `waterEnabled` | 요약의 물 추천 |
| 선크림 | `sunscreenEnabled` | 요약의 자외선 차단제 추천 |
| 호우특보 안내 | `heavyRainEnabled` | 공식 호우특보(R)의 발효 상태 진입·단계 변경·해제 |
| 대설·많은 눈 안내 | `heavySnowEnabled` | 공식 대설특보(S)의 상태 변화 + 예보 기반 많은 눈 대비 별도 알림 |
| 폭염특보 안내 | `heatwaveEnabled` | 공식 폭염특보(H)의 발효 상태 진입·단계 변경·해제 |
| 한파특보 안내 | `coldWaveEnabled` | 공식 한파특보(C)의 발효 상태 진입·단계 변경·해제 |
| 현재 비 안내 | `showerAndLightRainEnabled` | 아래 현재 비 조건에만 적용; 기존 필드명 유지 |
| 준비물 요약 알림 | `dailyWeatherEnabled` | 추천·알림 적격 준비물이 있을 때만 하루 한 번, 우선순위가 높은 최대 3개 |

### 준비물 요약

- `dailyWeatherEnabled`를 꺼도 현재 비·공식 특보·많은 눈 대비·도로 안내가 함께 꺼지지는 않는다.
- 준비물 각각의 스위치가 켜져도 추천이 없거나 유효시간이 지났다면 해당 준비물 알림을 만들지 않는다.
- 일반적인 ‘오늘 날씨’ 예보를 매일 보내는 기능이 아니다. 추천 준비물이 없으면 요약을 보내지 않는다.
- 추천 6종의 설정은 서버 추천 엔진에도 전달되므로 앱에서 표시할 추천 여부에 사용되는 기존 동작도 유지한다.

### 현재 비

- 서버에 등록된 정밀 좌표와 API 자료가 필요하다. 현재 앱은 GPS 정밀 위치가 유효한 경우에만 그 좌표를 보내고, 수동 지역·대략적 위치는 좌표를 보내지 않는다.
- 관측분석과 레이더가 함께 비로 판단한 경우에만 사용한다. 불일치 상태에서는 발송하지 않는다.
- `umbrellaEnabled`와 `showerAndLightRainEnabled`가 모두 켜져야 한다. 우산 준비 행동이 포함되기 때문이다.
- 한 강수 구간에서 반복 발송하지 않는다. 스위치를 끈 동안 확인한 비도 상태를 기록하므로 켰다는 이유만으로 같은 비를 다시 보내지는 않는다. 무강수가 확인된 뒤 다시 비로 바뀌면 새 구간이다.
- 소나기 시작 예보, 강도별 이슬비 구분, 특정 mm/h 미만 전용 알림을 뜻하지 않는다. 화면의 `소나기·약한 비 안내`를 `현재 비 안내`로 바로잡았다.
- 이 스위치를 꺼도 정기 준비물 요약의 우산은 별도 우산 스위치가 켜져 있으면 포함될 수 있다.

### 공식 특보와 많은 눈

- 예비특보·발효 예정·가능성 안내를 추가하지 않았다. 기존 공급자가 반환한 발효 특보의 상태 전이를 안내한다.
- 해당 특보 스위치를 끈 동안에도 확인한 특보 상태는 갱신한다. 다시 켠 직후 같은 상태를 재발송하지 않으며 이후 변화에 적용한다.
- 호우·폭염·한파 스위치는 임의의 내부 체감 수치 경보가 아니다. 물·겉옷·우산 준비물 요약을 함께 끄는 스위치도 아니다.
- 대설·많은 눈 스위치는 예외적으로 `IMPORTANT_HEAVY_SNOW_CAUTION`도 제어한다. 이 알림은 공식 특보 단정이 아니라 기존 예보 기반 많은 눈 대비 문구다.

## 개별 스위치가 없는 발송

| 발송 | 현재 제어·전제 |
| --- | --- |
| 강풍 등 나머지 공식 특보 | 전체 날씨 알림; 특보 구역과 발효 자료가 확인되는 경우 |
| 블랙아이스(도로살얼음) | 전체 날씨 알림; 등록 정밀 좌표와 지원 도로의 공식 발생 가능 정보 |
| 도로통제·출퇴근 경로 | 전체 날씨 알림; 등록 정밀 좌표와 현재 시행 중인 공식 도로통제 자료 |

이를 폭염·한파·소나기 스위치에 임의로 묶지 않았다. 개별 스위치 신설이나 발송 조건 변경은 별도 정책 변경이다. 빨래·반려견 산책·수면 등 화면의 생활 카드가 모두 독립 푸시로 발송되는 것은 아니다.

## 검증 위치

- 앱 `test/settings_notification_contract_test.dart`: 하위 12종 화면 스위치가 정확히 자기 필드만 바꾸는지, 10분 경계/자정/잘못된 시간, 설명과 큰 글씨 레이아웃.
- 서버 `test/notificationScheduler.test.ts`: 실제 로컬 Worker API → D1 저장 → 추천 엔진/스케줄러 → 모의 발송. 전체 끄기, 준비물 6종, 특보 4종의 시작/변경/해제, 현재 비 4개 스위치 조합, 별도 발송의 독립성.
- 서버 실행 코드·DB 스키마·운영 배포·기존 발송 조건은 이번에 변경하지 않았다. 실제 테스트 푸시는 보내지 않는다.
