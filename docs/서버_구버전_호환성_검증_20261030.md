# 서버 구버전 호환성 확인

2026년 10월 30일 **16:23 KST**, 실제 시험 서버 설치본을 기준으로 검증을 완료했다. 호환성 차이 한 가지를 발견해 시험 서버에 보완했고, 최종 비교에서 차이가 없어졌다.

## 발견 및 수정

구버전 앱의 **우산 ON·대설 알림 OFF** 설정에서 운영 서버는 눈 예보의 우산 요약을 발송하지만, 새 시험 서버는 새 항목 필터가 눈 관련 준비물 전체를 막아 요약을 생략했다. 처음 비교한 180조합 중 같은 원인의 2조합에서 이 차이가 재현됐다.

`preparationPolicy.ts` 한 파일만 보완했다. 새 눈 준비물 선택을 지원하지 않는 구버전의 눈 대비 우산은 기존 우산 설정을 따른다. 새 앱에서 눈 항목을 명시적으로 OFF로 설정한 경우는 계속 제외한다. DB 변경이나 새 마이그레이션은 없다.

소스 백업은 서버의 `legacy-compat-test-` 백업 디렉터리에 보관했으며 정확한 경로는 [검증 집계](./서버_구버전_호환성_검증_20261030.json)에 기록했다. 시험 API만 재시작했다. 최종 시험 API PID는787518, 운영 API·스케줄러 PID는742759·742823으로 유지됐다. 시험 스케줄러는 기존 비활성 상태다.

## 운영 반영 조건과 범위

현재 운영 사용자 DB에는 새 기능 열이 없으므로 운영 승격 시 백업 후 사용자 마이그레이션 **0005·0006·0007**을 먼저 적용하고 호환성 보완이 포함된 서버 코드를 반영해야 한다. 코드만 교체하는 배포는 이번 검증 범위의 조건을 충족하지 않는다.

이번에는 시험 서버의 호환성 보완만 수행했다. 운영 서버 소스·DB를 변경하지 않았고 실사용자 설정을 시험값으로 쓰지 않았다. 기존 APK/IPA를 직접 설치·실행한 검사는 아니며 서버/API 호환성 검사다. 앱 전체의 모든 과거 버전을 검증했다고 확대하지 않는다.

상세 도구·로그는 ignored `weather_care_server/build/compat-after-deploy-20261030`과 서버 `/tmp/weather-care-today-test-20261030-LzF3qFCE`의 `compat-*` 파일에 있다. 이전 배포의 소스 매니페스트 이후 바뀐 것은 이번 `preparationPolicy.ts` 한 파일이며, `compat-fixed-plan.json`이 최종 시험 소스 기준이다. 커밋·푸시는 수행하지 않았다.

## 동파 기본 ON 변경 후속 검사 — 로컬 미배포 수정본

후속 요청으로 동파 기본값을 ON으로 바꾼 로컬 코드를 커밋9faab59의 변경 전 코드와 비교했다. 기존 알림180조합은 전부 일치하며 두 설정 API의 저장·부분 갱신·입력 검증·인증20검사와 기존 스키마 값 보존·재적용 검사도 통과했다.

별도로 두 설정 경로에서 기존OFF·기존ON·신규 명시OFF·신규 필드 생략을 각각 비교했다. 기존6조합은 저장값과 실제 스케줄러의 동파 발송 결과가 그대로 유지됐다. 신규 필드 생략2조합만 요청한 정책대로 OFF→ON으로 바뀌었다. 완전한48시간 한파 합성 예보에서 기존/명시OFF는0건, ON은 반복 실행해도 하루1건이다. 동파 필드가 없던 구버전 앱도 신규 설정을 만들면 이 기본ON 정책을 적용받는다.

동파 기능 도입 전 커밋의 실제 Dart 알림 해석 코드를 추출해 PIPE_FREEZE 메시지 해석도 실행했다. 예외 없이 WEATHER_DETAILS 경로와 unknown 항목으로 처리한다. 전용 동파 상세 표시까지 지원한다는 뜻은 아니며 실제 과거 APK/IPA 실행 검사는 아니다.

이번 후속 검증은 로컬 변경 전후 모듈과 메모리SQLite를 사용했다. 서버 재배포·실제 DB 변경·FCM 발송·외부 요청은 없다. 도구·집계는 ignored `weather_care_server/build/pipe-default-compat-20261030`의 `matrix.json`, `pipe-matrix.json`, `old-parser.log`에 있다. 시험 서버에는 기본ON 변경이 아직 배포되지 않았다.
