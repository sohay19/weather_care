`SNO=0`, `SNO=NONE`, `적설없음` 원문은 해당 예보 구간에 새로 쌓일 눈이 없다는 뜻이다. 기존 눈까지 모두 녹았거나 현재 총 적설량이 0이라는 뜻으로 확대하지 않는다. `미만`·`범위`·`이상`은 기존 범주와 원문을 보존한다. `snowExpected` 역시 눈 예보 여부이지 현재 적설 유무가 아니다.

운영 일관측의 `snowfallAmount`는 호환 필드 이름을 유지하지만 의미는 일 최심신적설이다. `AVAILABLE`은 정상 수치(명시적 0 포함), `NO_RECORD`는 정상 응답에 수치 기록이 없음, `UNAVAILABLE`은 수집 실패다. 뒤의 두 상태는 0cm로 바꾸지 않는다. 적설 수치가 없다는 이유로 정상 기온·강수까지 결측 처리하지 않는다.

요청한 `tm`과 실제 관측 시각은 구분한다. 확인한 11:20·11:30 요청은 11:00 관측값을 반환했으므로, 응답 행의 `TM`을 적설 관측 시각으로 저장한다. 현재 적설은 시간별 신적설 합계나 하루 최댓값에서 계산하지 않는다. 유효한 현재 적설이 없으면 인근 유효 관측소를 사용하고 출처·거리·실제 관측 시각을 보존한다.

현재·과거 적설은 서로 다른 지표다. 현재 총 적설은 지면에 쌓인 눈의 깊이이며, 과거 최심신적설은 하루 새로 내린 눈의 최댓값이다. 하나를 연결해 다른 값을 대신 표시하지 않는다. 2026년 경계 승인과 공공데이터 운영계정 신청 대기는 계속 제외한다.

13:02 재확인에서도 강수 없음·0mm와 예보 `비`·`1mm 미만`의 혼재가 재현됐다. 비교 요청에 GPS를 주면 메인과 같은 오늘 값25.9℃를 반환해 서버 비교 로직은 정상이고, GPS 전달 수정은 앱 항목으로 분리한다. 12:50 실황 회차의 WSD 시간초과는 자동 재시도로 6개 파일 모두 저장되어 새 서버 수정 항목으로 추가하지 않았다. 10/9 16:50 회차 RN1 부분 누락은 같은 시점에도 남아 있다. 관련 서버 소스 3개는 배포 커밋의 SHA256과 일치하며 내부 재확인 3요청은 모두 HTTP200이다.

### 현재 강수 불일치 원인

예보 파서 `kmaWeatherProvider.ts`의 `weatherLabel`은 예보 PTY가 비이면 SKY의 구름 코드보다 `비` 문구를 우선 만든다. 강수량 범위·원문도 예보 PCP에서 만든다. 이후 `api/weather.ts`의 `currentFromUltraShortObservation`은 `...forecast`로 예보를 복사하고 실황 PTY·RN1에 해당하는 `precipitationType`·`precipitationAmount`만 바꾼다. `skyCondition`·`precipitationAmountRange`·`rawValue`는 다시 계산하거나 출처를 분리하지 않아 예보 값이 남는다. 따라서 실황이 강수 없음·0mm여도 화면에 `비`가 표시된다.

원인은 예보와 실황의 병합 누락이다. 현재 응답에서 강수 관련 문구·범위·원문의 의미를 실황 수치와 맞추고, 구름 상태 등 예보로 보완하는 항목은 출처를 분리해야 한다. 예보 구름 정보를 유지하는 정책 자체를 폐기할 이유는 없다.

### 현재 총 적설 미수집 원인

현재 총 적설 API는 승인 후 진단 호출·응답 검증만 수행됐다. 운영 수집기 `weatherCollectionJob.ts`에는 `kma_snow1.php` 호출이 없고, 전용 파서·캐시·주기 작업·현재 총 적설 API 필드도 없다. 기존 격자 실황은 T1H·REH·WSD·VEC·PTY·RN1을 수집한다. 기존 `snowfallAmount`는 예보 SNO 또는 과거 일자료 sd_day_max라 현재 총 적설로 대체할 수 없다. 이미 확인한 승인 응답은 정상이므로 운영 수집 미수행의 원인은 미구현이며 승인 대기로 분류하지 않는다.

### 과거 자료의 제외 기준

- 과거 최심신적설 기록·복원은 사용자 요청으로 필요 항목에서 제외한다. 기존 데이터나 수집 코드를 이번 원인 조사에서 삭제·변경하지 않았다.
- 과거 VEC(풍향)·PTY(강수형태)·RN1(강수량)은 현재 과거 출력에 필요하지 않아 복구 이슈에서 제외한다. `api/comparison.ts`의 어제 응답은 기온·체감온도만 반환하고 계산은 T1H·REH·WSD를 사용한다. 주간 과거 날씨는 별도 일관측 자료를 사용한다.
- 현재 시각의 풍향·강수형태·강수량은 현재 날씨에 쓰이므로 최신 실황의 6변수 수집은 유지 대상이다. 핵심 T1H·REH·WSD의 과거 이력도 어제 비교 때문에 필요하다. 과거 선택 파일의 불필요한 복구를 제외하는 것이 현재 수집이나 핵심 이력 복구를 중단한다는 뜻은 아니다.

## 결측과 추가 관찰

- 대기질 원본은 PM10 4개·PM2.5 15개·오존 7개 결측. 충남 시간초과 1건은 기존 3시간 내 관측을 유지하며 다음 재시도를 예약했다. 이번 점검에서 수정할 코드 장애로 확정하지 않는다.
- 원본283격자의 TMP·REH·POP·PCP·SNO가 10/12 11시~10/14 00시의22시각에서 결측이다. 지점 시간별 제공은 현재48개 슬롯, 표본 일예보는10/10~10/14가 존재한다. 원본 결측을 현재48시간 화면 장애로 해석하거나 사용자 승인된 마지막 연장 풍향 제외 정책을 이슈로 세지 않는다.
- 저장된 과거 실황 중 VEC160·PTY162·RN1164회차는 파일이 없다. 핵심3항목은 모든 저장 회차에 있고 어제 비교도 전수 정상이다. 과거 핵심만 복구한 회차와 실패 후 부분 재시도가 남은 회차를 구분한다.
- 최신 배포 이후 좌표 없는 위치 해석 로그1건을 확인했지만 경로·호출 주체가 없어 원인은 미확정이다. 이 로그를 앱 어제 비교의 GPS 누락과 같은 원인으로 단정하지 않는다.
- 기존 공개주소 Python403/Cloudflare1010은 자동 점검 요청 차단 기록이다. 이번 확인은 내부 API·캐시 기준이며 실제 앱 접근 장애로 단정하지 않는다.

작년 비교는 2026년 10월 이전 자료가 필요하므로 복원 대상에서 제외한다. 10월 이후라는 요구는 기존72시간 실황·7일 일관측 보관을 월 전체 보관으로 변경한다는 뜻이 아니다. 2026년 경계 승인과 공공데이터 운영계정 신청 대기는 위 이슈에서 제외했다. 도로살얼음은 비제공 계절이며 워치·꽃가루·대기정체·동파는 기존 다음 업데이트 계획이다.

## 정의·표기 정정 검증 결과

예보·관측의 눈 표기를 분리하고, 현재 적설값을 기존 `snowfallAmount`에서 만들지 않는 기준을 문서에 명시했다. 0과 미확보, 범주형 예보의 의미도 보존한다.

- 앱은 기존 로컬 수정에서 시간별·예보일 `예상 신적설`, 과거 관측일 `최심신적설`로 이미 구분되어 있어 이번 문서 정정에서는 추가 소스 변경을 하지 않았다.
- 관련 앱 테스트 `hourly_weather_test.dart`, `week_tab_test.dart`, `week_precipitation_test.dart` 54개가 통과했다. 모델·시간별 예보·Week 표시 파일 3개의 정적 분석 결과는 문제 0건이다.
- Word 명세 4개를 실제 PDF·PNG로 렌더링하고 총 72쪽을 검토했다. 추가한 정의 페이지의 줄바꿈·가독성과 전체 문서의 글자 깨짐·잘림을 확인했다.
- 문서 정의·표기 정정 작업에서는 서버 소스 수정, 제공처 재호출, 운영 배포와 커밋을 하지 않았다. 현재 적설 API의 정규 수집·앱 연결은 별도 미완료 항목이다.
