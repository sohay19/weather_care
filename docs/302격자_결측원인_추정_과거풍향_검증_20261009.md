# 302격자 실황 결측 원인 추정과 과거 풍향 확인

검사일: 2026-10-09. 실황 원인 추정은 앞선 122회차 전수 검사와 SGIS 2025년 2분기 원본 경계 대조를 바탕으로 한다. 과거 풍향은 운영 보관분에 국한하지 않고 기상청 APIHub 원본을 직접 호출했다. 앱·운영 런타임·수집 정책은 변경하지 않았다.

## 302격자 실황 결측의 가장 유력한 원인

**행정경계에 육지가 포함되는 격자와 기상청이 실황 값을 제공하는 격자가 일치하지 않는 문제**가 가장 유력하다. 행정경계와 조금이라도 겹치면 육지 대상 격자로 집계했으므로, 실제 육지 GPS가 있는 격자라도 그 격자 전체 또는 중심점은 기상청의 비관측 영역에 포함될 수 있다.

기상청 [동네예보 격자영역 정보](https://apihub.kma.go.kr/getAttachFile.do?fileName=%2820240305%29%EB%8F%99%EB%84%A4%EC%98%88%EB%B3%B4+%EA%B2%A9%EC%9E%90%EC%98%81%EC%97%AD+%EC%A0%95%EB%B3%B4.pdf)는 5km 간격의 149×253 격자, 비관측영역 값 -99, 좌측하단부터 우측상단 순서로 저장됨을 명시한다. 같은 내용은 [기상청 데이터위키](https://datawiki.kma.go.kr/doku.php?id=%EA%B8%B0%EC%83%81%EC%98%88%EB%B3%B4:%EB%82%A0%EC%94%A8%EC%98%88%EB%B3%B4:%EB%8B%A8%EA%B8%B0%EC%98%88%EB%B3%B4)에도 있다. 이 자료가 실황 내부 마스킹 구현이나 -999의 세부 원인까지 설명하는 것은 아니다.

| 후보 원인 | 실제 근거 | 판단 |
|---|---|---|
| 기상청의 제공 영역·해륙 구분과 행정경계의 차이 | 283격자의 실황 기온·습도·풍속이 122회차 모두 -99. 같은 283격자는 예보 기온·습도 등 234파일에서도 -99 | 가장 유력. 지속적인 공간 제외 패턴과 일치 |
| 작은 섬·해안이 5km 격자 또는 기상청 내부 지형자료에서 다르게 분류됨 | 전302 육지 비율 50% 미만, 288개는 10% 미만. 301개 중심점은 SGIS 국내 행정경계 밖 | 유력한 구체적 설명. 내부 해륙 기준·지형자료 연도 미확인 |
| 실황의 분석 영역·관측자료 가용 범위 차이 | 19격자는 실황 122회 모두 -999이나 예보 TMP/REH는 234회 모두 유효. 예보가 있는 곳에서도 실황만 없음 | 19격자의 후보. -999만으로 관측장비 고장이나 제공영역 제외를 확정하지 않음 |
| 일시적인 관측 지연·통신·품질검사 문제 | 관측 원본 생성에서 가능한 원인이지만 이번에는 동일 격자의 세 필드가 전체 기간 고정 결측 | 이번 패턴의 주원인으로는 근거가 약함. 19격자의 내부 분석 자료 확인은 필요 |
| 우리 서버의 시간초과·파싱 오류 | 전국 원본 파일을 정상 저장했고 해당 위치에 명시적인 -99/-999가 있음. 주변 격자는 유효, 예보 변수별 유효 영역도 다름 | 현재 302개 셀의 결측을 단순 시간초과나 늦은 조회로 설명하기 어려움 |

301개 중심점이 국내 행정경계 밖이라는 사실을 전부 바다라는 뜻으로 해석하면 안 된다. 북쪽 경계에 걸친 철원·양구·인제·고성 격자도 포함된다. 또한 행정경계 원본은 SGIS 2025Q2이며 2026 원본 다운로드는 대기 중이다. 기상청 내부 지형·제공영역과 일치한다고 가정하지 않았다.

유일하게 중심점이 행정경계 육지 안인 **(42,52), 진도군 조도면**도 육지 비율은 2.67%에 불과하고 원본은 -99다. 따라서 단순한 ‘격자 중심이 바다라서’라는 규칙만으로 전체 302개를 확정 설명할 수 없다. 기상청의 별도 해륙 마스크, 더 단순한 해안선 자료, 항목별 생산 영역이 후보이며 내부 정의 확인이 필요하다.

구분별로 -99의 283격자는 육지 비율 10% 미만 276개·중심점 육지 1개, -999의 19격자는 10% 미만 12개·중심점 육지 0개다. 기상청으로부터 -99/-999 실황 처리 기준과 해당 nx·ny의 제공영역 정의를 받으면 원인을 더 정확히 구분할 수 있다. 외부 문의는 아직 제출하지 않았다.

## 과거 풍향 직접 호출: 현재까지의 결과

최근 14일(9/25~10/8)의 05·17시 발표, 각 발표의 일반 구간 마지막 VEC 1개·연장 첫 시각 WSD 1개·연장 VEC 8개를 계획했다. 먼저 10/7과 10/1을 검사했고 재시도 예산에 도달하여 현재 부분 결과다.

| 발표(KST) | 일반 마지막 풍향 | 연장 첫 시각 풍속 | 연장 풍향 8파일 |
|---|---|---|---|
| 10/1 05시 | 정상 341,297B | 정상 341,297B | 8/8 HTTP 200·0B |
| 10/1 17시 | 정상 341,297B | 정상 341,297B | 첫 4개 HTTP 200·0B, 5번째 전송 실패, 재조회 예산 차단. 나머지 미조회 |
| 10/7 05시 | 정상 341,297B | 정상 341,297B | 8/8 HTTP 200·0B |
| 10/7 17시 | 정상 341,297B | 정상 341,297B | 8/8 HTTP 200·0B |

즉 **10/8~9만의 일시적 이상은 아니며, 적어도 10/1과 10/7의 발표에서도 같은 연장 구간 누락을 직접 확인했다.** 현재까지 모든 날짜를 연속으로 확인한 것은 아니므로 ‘최근 14일 매일 발생’으로 확정하지 않는다. 10/1 17시에서 네트워크 실패한 파일도 빈 응답으로 세지 않는다.

기존 10/8 17시·10/9 05시 보관 파일과 반복 로그에서는 일반 구간 정상/연장 8파일씩 누락이었다. APIHub의 [공식 예보기간 변경 안내](https://apihub.kma.go.kr/apiList.do?seqApi=10) 및 이전 연장 풍향이 정상인 공식 지점예보 검증을 함께 보면, 예보 자체 미생산보다는 전국 VEC 파일의 연장 구간 제공 처리 문제가 더 유력하다. 예전 예보기간 조건이 남았는지는 후보이며 확정된 내부 원인이 아니다.

## 호출 예산과 남은 검사

첫 실행 결과는 정상 파일 8회·빈 응답 28회·전송 실패 1회로 **실제 외부 호출 37회**다. 추가 시도 1개는 예약 단계에서 차단되어 제공처 호출이 발생하지 않았다. 정상 응답 본문 합계는 2,730,376B, 전송 실패 예약 1,000,000B를 포함한 장부 증가량은 3,730,376B다. APIHub 전체 일 한도 4.5GB 및 18,000회는 유지했다.

초기 24시간에는 재시도 장부 한도가 100MB다. 장부가 95,816,431B에서 99,546,807B가 되어 다음 1MB 예약이 차단됐다. 24시간이 지난 뒤 적용되는 400MB로 미리 바꾸거나 예산을 초기화하지 않았다. 초기 기준 시각은 10/8 17:27:01 KST이므로 10/9 17:27:01 이후부터 기존 정책의 다음 한도가 적용된다.

나머지 날짜를 확인하기 위해 이번 과거 진단에만 별도 최대 20MB 허용 여부를 사용자에게 요청했다. 승인을 받기 전에는 해당 추가 호출을 하지 않는다. 일반 재시도 정책·제공처 전체 한도는 유지하는 계획이다.

안전한 직접 호출 결과는 [과거 풍향 검증 JSON](풍향_과거발표_직접검증_20261009.json)에 있다. 최종 체크는 아직 부분 완료이며 연속 14일 확인 결과는 추가 예산 승인 또는 기존 초기 기간 종료 뒤 검사가 필요하다.
