# 서버 내 나의 데이터 삭제

구현 계약: 2026-09-11. 사용자 승인 범위는 기능 구현이며, 실제 사용자 데이터의 시험 삭제 승인은 아니다. 정식 개인정보처리방침을 대신하지 않는다.

## 사용자 흐름

1. Setting → 데이터·권한 안내 → `서버 내 나의 데이터 삭제`.
2. 삭제 범위와 알림 중단·남는 정보를 설명한 확인창에서 `삭제하기`를 누른다. 취소는 서버 요청을 하지 않는다.
3. 본인 확인과 DB 삭제가 성공하면 완료를 표시한다. 통신·인증·저장 오류는 완료로 표시하지 않으며 재시도 버튼을 제공한다.
4. 삭제 시도부터 등록·설정 전송을 중지하고 보안 저장소에 상태를 기록한다. 앱 복귀·재실행·토큰 갱신으로 등록하지 않는다. 완료가 불확실하면 같은 식별자·인증으로 재시도한다.
5. 삭제 완료 후 `서버 기능 다시 사용`을 별도로 확인하면 새 서버 식별자로 등록한다. 전체 날씨 알림 스위치를 자동으로 켜지 않는다.

삭제 중지 상태에서도 지역 격자의 익명 날씨 조회는 유지한다. 이때 설치 ID·인증 헤더·정밀 좌표는 조회에 붙이지 않는다. 기기에 저장한 지역, 하위 알림 설정, 준비물 체크는 보존하고 전체 날씨 알림을 끈다. 모든 서버 통신이나 SDK 처리가 중단된다는 의미는 아니다.

## 서버 삭제 범위

| 삭제 대상 | 실제 처리 |
| --- | --- |
| 설치 등록·격자·좌표·FCM 토큰·강수/도로 상태 | `installations`의 해당 설치 행 |
| 알림 설정 | `notification_settings` |
| 발송 이력 | `notification_history` |
| 특보 상태 | `installation_warning_state` |
| 본인 확인 정보·기존 설치 전환 정보 | `installation_credentials`, `installation_ownership_challenges`, `legacy_installation_ownership` |
| 마지막 앱 사용 확인 시각 | `installation_activity` (0008 이후) |

하나의 D1 batch 트랜잭션이며 중간 실패 시 전체 롤백한다. 인증 행은 마지막에 삭제하고 각 SQL 자체에도 동일 소유자 조건을 둔다. 삭제 후 되살리기를 막기 위한 영구 식별자/토큰 tombstone은 남기지 않는다. 새 등록은 서버 생성 ID만 사용한다.

다른 설치, 공용 기상 캐시, 과거 운영 로그·백업, Firebase·광고 서비스 데이터는 이 DELETE의 대상이 아니다. 이미 FCM에 전달 중인 알림의 취소를 보장하지 않는다. 이후 스케줄러는 발송 직전 존재·현재 토큰·알림 허용을 재확인하고, 늦은 결과 기록은 삭제된 설치에 행을 생성하지 않는다.

## 본인 확인과 기존 설치 전환

- 기기의 보안 저장소에 256비트 난수 비밀값을 저장한다. 서버에는 SHA-256 해시만 두고 고정 길이 시간 안전 비교를 한다. 비밀값은 HTTPS Authorization 헤더에서만 사용하며 URL·로그에 넣지 않는다.
- `POST /api/v1/installations/enroll`은 개인정보 없이 인증용 ID를 준비한다. 앱은 ID·비밀값 저장 성공 후에만 등록정보를 전송한다. 호출자는 ID를 지정해 생성할 수 없다. 익명 등록 남용은 Cloudflare 위치별/IP별 20회/60초로 완화하며 정확한 전역 한도는 아니다.
- 기존 ID가 있으면 덮어쓰기/선점하지 않는다. 마이그레이션 시점에 보존한 기존 알림 수신 경로로 비표시 FCM 증명을 전송한다. 호출자가 새 토큰을 제시하는 방식은 허용하지 않는다.
- 증명은 설치 ID·요청 ID·새 비밀값 해시에 묶이고 5분 만료·성공 후 삭제, 요청은 설치당 1분 간격이다. FCM 메시지는 표시용 알림 없이 data만 보내고 TTL 60초다. 앱은 앞서 연 전경 수신 대기에서 해당 요청 ID의 증명만 받아 claim한다.
- 저장된 토큰이 없거나, 토큰이 만료됐거나, 전경 증명을 받지 못하거나, 기존 비밀값을 잃은 경우에는 무인 소유권 복구를 허용하지 않는다. 코드소하(CODESOHA) `sy40222@gmail.com` 문의를 안내한다. 이메일만으로 자동 삭제 승인이 되는 것은 아니며 수동 확인 절차는 별도 운영 기준이다.
- 만료 증명과 등록·설정이 끝내 만들어지지 않은 인증 준비정보는 정리한다. 인증 준비정보는 생성 15분 후부터 10분 주기 작업 또는 새 등록 시 정리한다. 이는 인증 준비정보의 기술적 유효기간이며 일반 이용자 데이터 보유기간을 정한 것이 아니다.
- 삭제된 ID로 PUT/설정 저장/claim을 재실행해도 복원할 수 없다. DB 트리거도 이전 Worker 버전의 늦은 INSERT와 고아 발송 이력 생성을 막는다. 기존 앱의 인증 없는 등록·설정 API는 더 이상 허용하지 않으므로 앱 업데이트가 필요하다.

## 클라이언트 구현

`ServerDataAccess`가 모든 등록/설정 변경과 삭제를 직렬화한다. 먼저 전송 중지 상태를 적용하고 진행 중 요청을 마친 뒤 DELETE한다. 삭제 완료 마커를 기기에 저장하지 못하면 기존 인증정보를 유지해 재시도한다. 보안 저장소를 읽지 못하면 임의로 새 ID를 만들지 않고 전송을 차단한다.

`InstallationApiClient`가 로컬 설치 ID를 인증된 서버 ID로 변환하고, 중지 상태에서 개인 식별자·정밀 좌표를 제거한다. 기존 GPS·FCM 자동 등록 진입점도 별도로 중지 조건을 검사한다. 삭제 및 재사용은 별도 확인창이며 360px/2배 글씨에서 스크롤된다.

보안 저장소는 `flutter_secure_storage 10.3.2`를 사용한다. 11.1.0은 현재 Dart 3.9.2/geolocator 의존성과 충돌하여 도입하지 않았다. Android 백업 비활성화 및 iOS Keychain entitlement를 반영했다. iOS 빌드·실기기는 Windows에서 미검증이다.

## 검증 및 후속 항목

자동 테스트는 격리 D1과 합성 ID/가짜 FCM 송신기를 사용한다. 실제 사용자 ID·토큰·좌표를 삭제 검증에 사용하지 않는다. 인증 누락/다른 비밀값 거부, 대상 한정 삭제, DB 롤백, 재시도, 지연 등록/발송 경합, 기존 설치 증명·만료·재생 방지, 앱 보안 저장 실패·재시작·확인/취소·큰 글씨·복귀 후 중지 상태를 검증한다.

전체 앱 311개·서버 225개 테스트, 앱 정적 분석, 서버 타입 검사, Android 빌드, 배포 사전 검증을 통과했다. 운영 마이그레이션과 Worker `f939d1df-d119-4227-84d9-47025c458c5b` 배포 완료. `scripts/verify_server_data_deletion.mjs`는 기존 ID를 받지 않고 새 합성 설치만 생성·검증·삭제한다. 운영에서도 이를 통과했고 기존 데이터는 유지했다. 에뮬레이터 업데이트 시 기존 설치의 비표시 소유 확인은 완료됐으며 삭제 확인창은 열어 본 뒤 취소했다.

2026-09-11 후속 결정으로 장기 미사용 등록정보와 발송 이력의 보유기간을 **1년**으로 확정하고 자동 정리·등록 만료 후 명시적 재사용 흐름을 구현했다. [보유기간 계약](./서버_데이터_보유기간.md)을 따른다. 위 311/225 테스트 수와 배포 버전은 최초 직접 삭제 기능의 검증 기록이다.

남은 정책: 운영 로그/백업 만료와 복원 시 처리, 외부 SDK 데이터 권리 행사, 수동 본인 확인 절차, 정식 방침 공개 URL. 이 기능만으로 이를 완료했다고 하지 않는다.
