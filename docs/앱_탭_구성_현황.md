# 날씨챙겨 앱 탭 구성 현황

- 기준일: 2026-08-24
- 기준: `weather_care_app/lib` 현재 구현 코드
- 수정 진행 순서: **Main → Today → Detail → Week → Setting**
- 하단 내비게이션 표시 순서: **Today → Detail → Main → Week → Setting**
- 앱 최초 진입 탭: **Main** (`selectedIndex = 2`)

> 이 문서는 기획 메모가 아니라 현재 구현 상태를 기준으로 관리한다.
>
> 표기: **완료**는 코드와 회귀 테스트까지 반영된 항목, **부분 완료**는 UI만 있고 저장·운영 연동이 남은 항목이다.

## 적용 상태 한눈에 보기

| 영역 | 상태 | 이번 반영 핵심 |
| --- | --- | --- |
| 공통 날씨 아이콘 | 완료 | 비를 구름+빗방울로 표시하고 맑음·구름 많음·흐림·강수 형태를 구분 |
| Today | 부분 완료 | 3시간 간격 5개 시점과 행동형 상태 문구 적용 |
| Detail | 부분 완료 | 헤더/카드 재구성, 지표 기준 팝업, 수치 근거, 환경 태그와 위험 강조 적용 |
| Week | 부분 완료 | 비/눈 일수, 준비물 최대 3개, 상태별 아이콘 적용 |
| Setting | 부분 완료 | 공통 페이지 헤더, 알림 시간 비활성화, 주의 알림 확장, 실제 데이터 출처 표기 |

## 1. 공통 화면 구조

### 탭 및 상태 유지

- 5개 탭은 `HomeScreen`의 `IndexedStack`으로 구성된다.
- 탭을 이동해도 각 탭의 위젯 상태는 유지된다.
  - 예: Today에서 체크한 준비물, Setting에서 바꾼 토글 상태
- 하단 내비게이션 높이는 74px이며 모든 탭 라벨을 항상 표시한다.
- 선택 전후 아이콘 색상은 동일하게 유지하고 아이콘 모양과 배경 표시로 선택 상태를 구분한다.
- Today의 준비물 정보 버튼을 누르면 Detail 탭으로 이동한다.
  - 선택한 준비물과 관련된 근거를 우선 배치하고 해당 카드로 이동한다.

### 날씨 데이터 조회 상태

날씨 데이터는 다음 순서로 조회한다.

1. 운영 서버의 Today/Weekly API를 병렬 호출한다.
2. 운영 서버 조회에 실패하면 선택 팝업을 표시한다.
   - 추천 동작: `운영 서버 다시 시도`
   - 보조 동작: `단기예보만 보기`
   - 운영 서버가 준비물 추천과 TODO를 제공한다는 점을 안내해 재연결을 우선 권유한다.
3. 사용자가 보조 동작을 선택하고 앱에 KMA 키가 있으면 기상청 단기예보를 직접 조회한다.
4. 직접 조회도 불가능하면 날씨 화면 대신 상태 안내를 표시한다.

| 조회 상태 | Main | Today | Detail | Week | Setting |
| --- | --- | --- | --- | --- | --- |
| 운영 서버 연결 | 전체 기능 | 전체 기능 | 전체 기능 | 전체 기능 | 접근 가능 |
| 기상청 직접 조회 | 원시 날씨 + 생활 날씨 미지원 | 브리핑 + 준비물/타임라인 미지원 | 현재/시간별 날씨 + 판단 근거 미지원 | 날짜별 원시 예보 + 준비물 미지원 | 접근 가능 |
| 날씨 조회 불가 | 상태 안내 | 상태 안내 | 상태 안내 | 상태 안내 | 항상 접근 가능 |

### 공통 새로고침

- 모든 탭 헤더에서 새로고침 버튼을 제거했다.
- Main, Today, Detail, Week, Setting과 날씨 미지원 상태 화면은 모두 아래로 당겨서 새로고침할 수 있다.
- 새로고침 때도 운영 서버를 먼저 조회하며 실패하면 동일한 선택 팝업을 표시한다.

### 공통 날씨 아이콘 규칙

날씨 상태 아이콘은 Main 현재 날씨, Detail 현재/시간별 날씨, Week 날짜별 날씨에 같은 규칙으로 적용한다. **우산 아이콘은 날씨 상태가 아니라 준비물·알림 항목에서만 사용한다.**

- 해+구름, 겹친 구름, 구름+비/눈처럼 여러 요소를 조합한 아이콘은 상태별 독립 위젯으로 캡슐화한다.
- 조합 위젯은 부모 영역이 더 커도 지정한 정사각 크기를 유지해 구름과 강수 요소가 서로 떨어지지 않도록 한다.

| 서버 상태 | 아이콘 표현 | 구분 원칙 |
| --- | --- | --- |
| 맑음 | 해 | 구름 없음 |
| 구름 많음 | 해 + 구름 | 해가 일부 보이는 다소 흐린 상태 |
| 흐림 | 겹친 구름 | 하늘을 구름이 덮은 상태 |
| 빗방울·이슬비·가랑비·약한 비 | 구름 + 빗방울 1개 | 약한 강수 형태 |
| 비 | 구름 + 빗방울 2개 | 일반적인 비 |
| 소나기 | 구름 + 빗방울 3개 | 비와 별도 형태로 구분 |
| 눈날림 | 윤곽 구름 + 작은 눈송이 | 약한 눈날림 |
| 눈 | 구름 + 눈송이 | 일반적인 눈 |
| 빗방울/눈날림 | 윤곽 구름 + 작은 빗방울 + 작은 눈송이 | 약한 혼합 강수 |
| 비/눈 | 채운 구름 + 빗방울 + 눈송이 | 일반 혼합 강수 |
| 알 수 없음 | 물음표 | 미정의 상태를 맑음으로 오인하지 않음 |

## 2. Main 탭

### 목적

현재 날씨와 오늘의 핵심 생활 정보를 한 화면에서 빠르게 확인하는 탭이다.

### 화면 구성 순서

1. **페이지 헤더**
   - 날짜와 요일
   - `{지역명}이라면 확인하세요`
   - `화면을 아래로 당기면 최신 날씨 정보를 가져와요`
   - 별도 앞 아이콘과 새로고침 버튼 없음
2. **상단 날씨 카드**
   - 서버가 만든 감성 브리핑을 말줄임 없이 표시
   - 기온·날씨를 직접 나열하지 않고 우산, 그늘, 옷깃, 발걸음처럼 간접적으로 표현
   - 7개 대표 장면, 완성형 템플릿 20개, 슬롯별 후보 10개로 조합
   - 날짜·지역별로 문장을 고정하고 같은 완성 문장은 7일 동안 반복하지 않음
   - 하늘 상태에 따른 배경 톤
   - 현재 기온과 체감온도 또는 `체감 미지원`
   - 체감온도 아래에 하늘 상태·체감 느낌을 두 문장으로 풀어 쓴 안내와 하늘 상태 아이콘 표시
   - 체감 안내는 13pt 글자로 표시하고 작은 화면에서도 말줄임 없이 자연스럽게 줄바꿈
   - 숫자는 기상청 계절별 체감온도 산식, 표현은 한국인 PT 감각 경계와 기상청 `33/35/38℃` 위험값을 함께 사용
   - `어제와 비교` 영역에서 어제 저장값 대비 기온·체감온도·PM2.5 우선 미세먼지 차이를 단위와 함께 표시
   - 어제와 오늘의 하늘 상태가 모두 있으면 `어제 맑음 · 오늘 구름 많음`처럼 함께 표시
   - 어제 저장값이 없거나 운영 서버 미연결이면 비교 데이터가 쌓이거나 서버가 연결될 때 표시된다고 안내
   - 습도 / 풍속 / 자외선 지수 / 미세먼지
   - 미세먼지는 PM2.5를 우선 표시하고, 없으면 PM10으로 대체
   - 지표 수치는 안전(블루) / 주의(앰버) / 위험(레드) 색상으로 구분
3. **Check List 대시보드**
   - 타이틀 앞에 `TODAY` 라벨 표시
   - `Check List`
   - `오늘 날씨에 체크해야할 일들이에요`
   - 서버 생활 문구 중 앞의 3개를 표시
   - 서버 문구가 3개보다 적으면 서버가 안전한 기본 TODO를 채우고, 구버전 서버 호환을 위해 앱도 부족한 슬롯을 보완
   - 각 항목은 아이콘과 `제목 + 설명` 묶음을 가로로 배치하고, 3개 항목은 세로로 나열
   - 카드를 누르면 같은 생활항목의 Detail 근거를 우선 배치하고 해당 카드로 이동
   - 우산·양산·겉옷·마스크·물·선크림처럼 챙겨 나갈 항목은 서버 점수에 따라 배경·아이콘 색으로 중요도를 구분하고 테두리는 표시하지 않음
     - 80점 이상: 높은 중요도(앰버)
     - 60~79점: 중간 중요도(블루)
     - 60점 미만: 낮은 중요도(옅은 블루)
   - 일반 행동 TODO는 중립 배경을 유지해 챙길 물건과 시각적으로 구분
   - 운영 서버 미연결 시 `운영 서버 미연결로 미지원`

### 레이아웃 규칙

- `CustomScrollView`, `SliverPadding`, `SliverList`로 상단 카드와 Check List를 자연 높이로 배치한다.
- 콘텐츠가 화면 높이를 넘으면 Main 전체를 아래 방향으로 스크롤할 수 있으며, 최상단에서는 당겨서 새로고침할 수 있다.
- 화면 너비가 380px 미만이면 compact 레이아웃을 사용한다.
  - 카드 간격과 내부 여백 축소
  - 일부 글자와 아이콘 크기 축소
- 상단 날씨 카드와 Check List에 고정 높이 비율을 배정하지 않는다.

### 데이터 및 동작

- `TodayWeatherResponse`의 `region`, `brief`, `current`, `lifestyleMessages`와 어제 `ComparisonResponse`를 사용한다.
- 운영 서버는 Today 조회 때 현재 기온·체감온도·PM10·PM2.5·하늘 상태를 D1 일별 스냅샷에 저장하고, 한국시간 기준 어제 날짜의 값을 비교 API로 반환한다.
- 비교 가능한 양쪽 값이 모두 있는 지표만 차이를 표시하며 기온·체감온도는 `°C`, 미세먼지는 `㎍/㎥` 단위를 사용한다.
- 운영 서버는 기상청 생활기상지수 V5의 자외선 예측과 에어코리아 실시간 PM10·PM2.5를 `current`에 병합한다.
- `environmentalSources`로 자외선·대기질의 실시간 조회/캐시/stale/미지원 상태를 구분하며, 환경 Provider 실패는 단기예보 응답 전체를 실패시키지 않는다.
- 생활 문구 응답의 `score`를 중요도 색상 기준으로 사용하며, 구버전 서버에서 점수가 없으면 0점으로 처리한다.
- PM2.5 나쁨 시작값은 화면 색상·서버 마스크 추천·브리핑 모두 36㎍/㎥, PM10은 81㎍/㎥로 통일한다. PM 수치가 낮아도 에어코리아 통합등급이 `나쁨` 이상이면 마스크를 추천한다.
- 강수 장면과 행동 판단은 Detail 강조 기준과 같은 강수확률 40%부터 적용한다.
- 날씨 상태 문자열로 Main의 mood를 결정한다.
- 현재 위치는 고정 격자 `nx=60`, `ny=121`로 조회하고 있어 Setting의 위치 선택과 아직 연결되지 않는다.

### 지표 색상 기준

| 지표 | 양호(블루) | 주의(앰버) | 위험(레드) |
| --- | --- | --- | --- |
| 습도 | 35% 초과, 70% 미만 | 35% 이하 또는 70~79% | 80% 이상 |
| 풍속 | 6m/s 미만 | 6~8.9m/s | 9m/s 이상 |
| 자외선 | 6 미만 | 6~7 | 8 이상 |
| PM2.5 | 35㎍/㎥ 이하 | 36~75㎍/㎥ | 76㎍/㎥ 이상 |
| PM10 대체값 | 80㎍/㎥ 이하 | 81~150㎍/㎥ | 151㎍/㎥ 이상 |

미세먼지 구간은 [에어코리아 대기환경정보 등급](https://www.airkorea.or.kr/web/main)을 사용한다. 값이 없으면 `--`와 중립 색상을 표시한다.

### 체감온도 표현 기준

| 체감값 | 표현 |
| --- | --- |
| 38℃ 이상 | 위험한 더위 |
| 35~37.9℃ | 더위 경계 |
| 33~34.9℃ | 더위 주의 |
| 28~32.9℃ | 더움 |
| 20~27.9℃ | 조금 더움 |
| 10~19.9℃ | 선선한 편 |
| 0~9.9℃ | 쌀쌀한 편 |
| 0℃ 미만 | 추운 날씨 |

33/35/38℃는 공식 특보의 일 최고값·지속일수 판정 자체가 아니라 현재 한 시점의 행동 신호다. 연구 근거, 산식, 적용 한계와 한국인 대상 추가 연구는 [체감온도 계산·표현 기준](./체감온도_표현_기준.md)에 정리한다.

- [x] 360×800에서 Main 세로 스크롤·당겨서 새로고침·오버플로 없음 검증

## 3. Today 탭

### 목적

오늘 챙길 준비물과 시간대별 행동 시점을 확인하는 탭이다.

### 화면 구성 순서

1. **페이지 헤더**
   - `TODAY`
   - `오늘을 챙겨요`
   - `오늘의 준비물과 시간대별 안내`
2. **오늘 브리핑 카드**
   - 오늘의 한 줄 브리핑
   - 추천 준비물 개수
   - 추천이 없으면 `오늘은 특별한 준비물이 없어요.`
   - 직접 조회 상태에서는 준비물과 생활 시점이 미지원임을 안내
3. **Check List**
   - 추천 우선순위가 높은 순서로 준비물 표시
   - 추천된 항목만 표시
   - 1~3열 Wrap 레이아웃, 항목 높이 164px
   - 준비물명과 체크 상태만 표시하고 예보 시각은 타임라인에서 안내
   - 카드 탭: `챙길게요` ↔ `챙겼어요` 상태 전환
   - 정보 버튼: Detail 탭의 관련 근거로 이동
   - 추천이 없으면 빈 가방 안내
4. **간단한 타임라인**
   - 첫 유효 예보 시각부터 3시간 간격으로 5개 시점 표기(총 12시간 범위)
   - 시간 라벨
   - 추천 준비물이 필요한 이유를 나타내는 상태 제목
     - 예: `비가 예보됐어요`, `기온이 낮게 예보됐어요`
   - 상세 설명
   - `이 시간에 필요해요` 아래 해당 시간대 추천 준비물, 최대 3개
   - 추천 준비물 선택: Detail 탭의 해당 근거로 이동·강조

### 데이터 및 동작

- Home에서 추천을 우선순위 내림차순으로 정렬한 뒤 `recommended=true`인 항목만 전달한다.
- Check List는 준비물 확인·체크, 타임라인은 필요한 시각 확인을 담당한다.
- 준비물 체크 상태는 앱 메모리에만 유지되고 서버나 로컬 저장소에 저장되지 않는다.
- 전체 화면은 세로 스크롤이며 당겨서 새로고침할 수 있다.
- 운영 서버 미연결 시 `Check List`와 `간단한 타임라인`은 각각 미지원 카드로 교체된다.
- 시간 목록은 서버가 1시간 예보의 인덱스 `0·3·6·9·12`를 선택해 생성하므로 시작 시각은 현재 시각에 따라 달라진다.

### 현재 한계 및 확인 포인트

- [ ] 준비물 카드의 크기·열 수·표시 정보 검토
- [ ] `챙길게요/챙겼어요` 기능 유지 및 저장 범위 결정

- [ ] 추천이 많거나 없는 경우 레이아웃 확인

## 4. Detail 탭

### 목적

현재 수치, 서버 판단 근거, 시간별 예보를 숫자로 확인하는 탭이다.

### 화면 구성 순서

1. **페이지 헤더**
   - `DETAIL`
   - `날씨 자세히보기`
   - `상세한 날씨 정보를 확인해요`
2. **현재 상세 날씨 카드**
   - 별도 섹션 아이콘·타이틀·서브타이틀 없이 수치부터 표시
   - 왼쪽에 현재 기온, 오른쪽에 하늘 상태와 공통 날씨 아이콘 표시
   - 체감온도
   - 습도: 값이 있을 때만 표시
   - 자외선: 값이 있을 때만 표시
   - PM2.5를 우선하고 없으면 PM10을 사용하며 화면 라벨은 `미세먼지`로 통일
   - 체감/습도/자외선/미세먼지 항목을 누르면 현재값과 구간 기준 팝업 표시
3. **챙길 이유**
   - 타이틀 앞 아이콘 없음
   - 우선순위가 높은 추천 중 최대 3개
   - 추천 아이콘, 제목, 설명
   - 추천 설명 뒤에 강수확률·강수량·자외선·적설·기온·미세먼지·체감온도 중 관련 수치 표시
   - 추천이 없으면 별도 준비물 추천이 없다는 안내
   - 운영 서버 미연결 시 미지원 카드
4. **타임라인**
   - 시간, 하늘 상태와 아이콘
   - 기온과 체감온도
   - 비: 강수확률과 강수량
   - 눈: 예상 여부와 적설량
   - 바람: 풍속
   - 자외선과 미세먼지는 값이 있는 시간대에만 태그 표시
   - 태그는 `Wrap`으로 배치해 두 줄 이상 허용
   - 강수확률 40% 이상 또는 눈 예상과 강수확률 40% 이상인 행 강조
   - 기온 또는 체감온도 33℃ 이상인 행은 주의색으로 강조

### 데이터 및 동작

- `TodayWeatherResponse.current`, `recommendations`, `hourly`를 사용한다.
- 기상청 직접 조회에서도 현재 날씨와 시간별 상세는 표시할 수 있다.
- 시간별 자외선은 유효한 3시간 구간에, 에어코리아 관측 미세먼지는 현재와 첫 시간대에만 표시한다.
- 시간별 예보는 한국시간 기준 오늘 날짜와 같은 항목만 표시하며, 오늘 23시 이후의 다음 날 예보는 제외한다.
- 전체 화면은 세로 스크롤이며 당겨서 새로고침할 수 있다.
- Today 준비물의 정보 버튼으로 이동하면 관련 근거를 우선 배치하고 자동 스크롤하며 `선택한 항목의 근거`로 강조한다.

### 현재 한계 및 확인 포인트

- [x] 현재 카드 헤더 제거와 기온/하늘 상태 재배치
- [x] 체감·습도·자외선·미세먼지 기준 팝업 적용
- [x] 챙길 이유에 추천별 관련 수치 추가
- [x] 시간별 자외선·미세먼지 태그와 강수/눈/고온 강조 적용
- [ ] 현재 상세 지표 종류와 노출 순서 추가 검토
- [ ] PM10·풍속 등 누락 지표 추가 여부 검토
- [ ] 결측값을 숨길지 `미지원`으로 보여줄지 기준 통일
- [ ] 판단 근거 최대 3개 제한 검토
- [x] Today에서 선택한 준비물을 관련 Detail 근거에 연결
- [ ] 시간별 행의 정보 밀도와 강수 강조 기준 검토
- [x] 한국시간 기준 오늘 날짜의 시간 슬롯만 표시하고 다음 날 예보 제외

## 5. Week 탭

### 목적

제공 가능한 날짜 범위의 날씨와 대표 준비물을 미리 확인하는 탭이다.

### 화면 구성 순서

1. **페이지 헤더**
   - `WEEK`
   - `이번주 날씨`
   - `한 주의 날씨와 대표 준비물을 미리 살펴봐요`
2. **한눈에 보는 이번주**
   - 비·소나기·눈·혼합 강수 예보 일수
   - 전체 기간 중 최고 기온
   - 준비물이 있는 날의 수 또는 `미지원`
3. **날짜별 카드 목록**
   - 날짜
   - 첫 번째 항목에 `오늘` 표시
   - 날씨 아이콘과 상태
   - 대표 준비물 최대 3개
   - 준비물이 없으면 `준비물 없음`, 운영 서버 미연결이면 준비물 미지원 안내
   - 최저/최고 기온

### 데이터 및 동작

- `WeeklyWeatherResponse.days`의 전체 항목을 세로 목록으로 표시한다.
- 서버의 날짜별 준비물은 해당 날짜의 시간대별 기상청 체감온도로 계산한다. 시간대별 체감값이 없을 때 일 최고기온을 체감온도로 대입하지 않는다.
- 비/눈 예보 일수는 날씨 문구에 `비`, `소나기`, `눈`이 포함됐는지로 계산한다.
- 첫 번째 응답 항목을 실제 날짜 비교 없이 오늘로 처리한다.
- 운영 서버 미연결 시 기상청 직접 조회의 날짜별 날씨는 표시하고 준비물만 미지원으로 처리한다.
- 전체 화면은 세로 스크롤이며 당겨서 새로고침할 수 있다.

### 현재 한계 및 확인 포인트

- [ ] 탭 이름과 실제 제공 기간의 정합성 검토
- [ ] 상단 3개 요약 지표 유지 여부 검토
- [ ] 날짜·요일 표현 방식 검토
- [ ] 강수확률·강수량 등 날짜별 추가 정보 필요 여부 검토
- [x] 대표 준비물 표시 한도를 최대 3개로 확대
- [x] 준비물 없음 문구와 공통 날씨 아이콘 규칙 적용
- [ ] 첫 항목이 아니라 실제 날짜를 기준으로 `오늘`을 표시하도록 개선할지 결정
- [ ] 빈 목록과 일부 날짜 결측 상태 정의

## 6. Setting 탭

### 목적

기준 지역과 알림 종류를 설정하는 탭이다. 현재는 UI 데모 상태이며 설정 저장과 실제 기능 연결은 구현되지 않았다.

### 화면 구성 순서

1. **페이지 헤더**
   - `SETTING`
   - `설정`
   - `내 위치와 필요한 알림만 편안하게 맞춰보세요.`
   - 설정 아이콘 표시
2. **기준 지역**
   - 현재 위치 사용
   - 지역 직접 선택
   - 현재 안내 지역은 문구상 `수원`으로 고정
3. **날씨 알림 전체 스위치**
   - 끄면 하위 준비물/주의 알림 스위치가 비활성화된다.
   - 알림 시간 영역도 흐리게 표시되고 입력을 받지 않는다.
4. **알림 시간**
   - 기본값 `07:00`
   - 현재 행과 화살표만 있으며 시간 선택 동작은 없다.
5. **챙겨요 알림**
   - 우산
   - 양산
   - 겉옷
   - 마스크
   - 물
   - 선크림
   - 현재 서버의 준비물 추천 6종과 일치하므로 연결되지 않은 스위치는 추가하지 않음
   - 우비·장화·장갑·모자는 향후 서버 추천 타입과 판단 기준이 추가될 때 검토
6. **주의 및 날씨 안내**
   - `안전과 간단한 타임라인 알림을 관리해요`
   - 폭우 주의
   - 폭설 주의
   - 폭염 주의
   - 한파 주의
   - 소나기·약한 비 주의
     - 한 스위치로 관리하지만 소나기·이슬비·가랑비는 같은 현상으로 간주하지 않음
   - 오늘 날씨
7. **현재 구현 상태 안내**
   - 설정은 화면 안에서만 바뀌고 서버에 저장되지 않는다는 안내
8. **데이터 출처 안내**
   - `날씨·자외선은 기상청, 미세먼지는 에어코리아 공식 API를 사용합니다.`

### 데이터 및 동작

- 모든 초기 스위치는 켜짐 상태이고 위치 모드는 GPS, 알림 시간은 07:00이다.
- 전체 알림을 끄면 알림 시간과 모든 하위 스위치는 비활성화되지만 각 하위 값은 보존된다.
- 설정 변경은 `SettingsScreen` 내부 메모리에만 반영된다.
- 탭 이동 후 돌아오면 `IndexedStack` 때문에 상태가 유지되지만 앱 재시작 시 초기화된다.
- Home의 날씨 조회에 사용하는 설정 인스턴스와 Setting의 인스턴스가 분리되어 있다.
- 위치 모드를 바꿔도 실제 좌표, 지역명, 날씨 조회 대상은 바뀌지 않는다.

### 운영 반영 전 확인

- Today 타임라인과 Week 준비물 3개 제한은 서버 코드 변경을 포함하므로 운영 Worker 재배포가 필요하다.
- 새 Setting 스위치는 현재 화면 메모리에서만 동작한다. 앱 재시작 후 유지하거나 실제 알림을 제어하려면 로컬/서버 저장 계약과 알림 스케줄러 연결이 추가로 필요하다.
