# 302격자 공공데이터포털 실황 직접 검증

검증 시각: 2026-10-09 12:42 KST. 사용자 요청에 따라 예보와 별도로 실황을 직접 호출했다. 운영 수집·캐시·앱·AWS 대체 정책은 변경하지 않았다.

## 확인 결과

검사 API는 `VilageFcstInfoService_2.0/getUltraSrtNcst`, 요청 발표일·시각은 `20261009/1100`이다. 공식 문서의 정시 자료를 사용했으며 12:42 조회이므로 그날 11시 자료를 충분히 지난 뒤 확인한 결과다. 정상 비교 격자 (71,130)는 같은 요청에서 6항목 모두 유효했다.

각 응답의 HTTP 상태는 200, 결과코드는 00, nx·ny는 요청한 격자와 동일하고 발표일·시각도 정확히 20261009/1100이었다. 302개 모두 8행이 반환됐으며 좌표 고유성도 확인했다. 따라서 인증 실패, 잘못된 격자 요청, 페이지 누락 때문에 정상 값을 못 읽은 결과가 아니다. **API 호출 성공과 유효 관측값 존재는 구분해야 한다.**

정상 비교 격자 (71,130)는 기온 19.4℃·습도 60%·풍속 1m/s·풍향 139°·강수형태 0·강수량 0을 반환했다. (42,52) 조도면과 (35,106) 근흥면의 예보는 앞선 검사에서 정상이나, 이번 실황은 위 결측값과 동일했다.

## 10분 시각도 조회할 수 있는가

공공데이터포털의 이 API는 **매 정시의 대표 AWS 관측자료**다. [공식 서비스 설명과 요청 명세](https://www.data.go.kr/data/15084084/openapi.do)에 자료 출처 및 정시 기준이 명시되어 있다. 운영에서 사용하는 APIHub `nph-dfs_odam_grd`의 10분 격자 자료와 같은 제공 주기가 아니다. [APIHub 공식 명세](https://apihub.kma.go.kr/apiList.do?seqApi=10)는 격자 실황을 10분 간격으로 발표한다고 설명한다.

| 1100 | 1100 | 정시 자료와 일치 |
| 1110 | 1100 | 아님 |

모두 HTTP 200·결과코드 00이라도 반환 시각은 11:00이었다. ‘11:20’을 넣는 것만으로 11:20의 10분 실황을 가져온 것이 아니다. 이 분 단위 검사는 정상 대조 격자 1곳에서 수행했고 302격자에 5시각씩 재호출한 것이 아니다.

## 같은 시간대 APIHub 원본 대조

새 APIHub 호출을 하지 않고 운영 DB의 11:00·11:20·11:30·11:40·11:50 실황 원본을 대조했다. 11:10 원본은 DB에 없으므로 존재 여부를 이 검사로 판단하지 않았다.

- 기온·습도·풍속·풍향: 저장된 위 5회차 모두 대상 302격자 결측. 각 항목 원본은 283개 -99, 19개 -999.
- 강수량: 파일이 있는 11:20·30·40·50에서 302개 결측. 11:00은 항목 파일이 없어 셀 결측과 별도로 구분했다.
- 정상 대조 격자에서는 기온이 11:00 19.4→11:20 20.7→11:30 21.1→11:40/50 21.4℃로 달라졌다. APIHub의 10분 자료와 공공데이터포털에서 반복 반환한 11시 정시 자료를 같은 시각의 자료라고 해석하면 안 된다.

## 적용 판단 및 검증 범위

이번 302격자 결측은 **공공데이터포털 실황으로 제공처만 바꿔 해결되지 않았다.** 예보는 동일 좌표의 정상값이 있었지만 실황에서는 두 경로 모두 정상값이 없었다. 이번 정시 API 검사는 10/9 11시 1회차이며 모든 과거 시각의 정시 관측까지 검사한 것은 아니다.

실제 운영 해결책은 기존에 검토한 같은 시각 인근 유효 격자 보충이나 제공 영역에 대한 기상청 확인이 필요하다. 정시 데이터를 10분 실황으로 표시하거나 예보를 실황으로 바꾸지 않는다. 이번 작업은 진단용 호출만 했으며 정시 AWS 관측 대체를 운영에 복원하지 않았다.

공공데이터포털 호출은 302격자+정상 대조 1격자+분 시각 검사 5회, **총 308회·283,184B**였다. APIHub 추가 호출은 0회이며 앞서 요청한 20MB APIHub 진단 예산을 사용하거나 승인으로 간주하지 않았다. 공공데이터포털 기존 승인 키를 사용했고 인증·한도 오류가 나면 중단하도록 구성했으며 모든 호출이 완료됐다. 원문·키·인증 URL은 기록하지 않고 안전한 값·시각·좌표만 저장했다.
