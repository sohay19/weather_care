# 만 14세 미만 이용 제한 설계

2026-09-14 사용자 결정: 날씨챙겨는 만 14세 이상만 이용할 수 있으며, 만 14세
미만에게는 보호자 동의를 통한 예외 이용 경로를 제공하지 않는다. 이 결정은 2026-09-11의
아동 이용 포함·법정대리인 동의 연결 계획을 대체한다.

**상태: 앱과 서버 소스 구현 완료, 운영 배포 전.** 앱의 로컬 시작 차단과 서버의
연령정책 미확인 설치 기본 차단을 구현했다. D1 마이그레이션과 새 앱을 실제 운영에
배포하기 전까지 운영 서버의 기존 FCM 등록은 계속 유효할 수 있다.

## 이용 상태

| 상태 | 앱 서비스 | Firebase·Analytics | UMP·광고 | 위치·서버 등록·알림 |
| --- | --- | --- | --- | --- |
| 연령 미확인 / 저장 오류 | 이용 전 대기 | 시작 안 함 | 시작 안 함 | 시작 안 함 |
| 만 14세 이상 | 이용 가능 | 기존 개별 동의 조건 | 기존 광고 조건 | 기존 권한·설정 조건 |
| 만 14세 미만 | 이용 불가 | 시작 안 함 | 시작 안 함 | 시작 안 함 |

만 14세 이상을 성인으로 표현하지 않는다. 이용 가능 여부와 Analytics·광고·위치·알림의
개별 동의 또는 권한은 서로 다른 조건이다.

## 앱 시작 경계

- 앱은 다른 온라인 기능보다 먼저 `만 14세 이상이에요`와 `만 14세 미만이에요`를
  중립적으로 표시한다. 생년월일은 입력받지 않는다.
- 일반 저장소와 보안 저장소에 같은 유효값이 있을 때만 저장된 선택을 인정한다. 누락,
  불일치, 손상, 읽기·쓰기 실패와 시간 초과는 미확인으로 처리한다.
- 만 14세 이상 확인 전에는 HomeScreen, Firebase 앱, Analytics, UMP·Mobile Ads,
  위치 요청, 알림 권한·FCM 토큰 등록 및 날씨 서버 연결을 시작하지 않는다.
- 만 14세 미만을 선택하면 `만 14세 이상만 이용할 수 있다`는 로컬 화면만 유지한다.
  보호자 확인, 이메일 동의, 제한 기능 이용 같은 예외 경로를 표시하거나 제공하지 않는다.
- 선택 실수를 고칠 수 있도록 이용 불가 화면에 `연령대를 다시 선택할게요`를 제공한다.
  이는 강한 본인확인이나 연령 검증 수단이 아니며 사실과 다른 선택을 기술적으로 막지 못한다.
- 백그라운드 Dart FCM 진입도 저장된 만 14세 이상 상태를 확인한 뒤에만 Firebase를
  초기화한다. Android는 FCM·Analytics 자동 시작을 OFF로 두고 Firebase·Mobile Ads
  조기 초기화 provider를 제거했다. iOS는 FCM·Analytics 자동 시작을 OFF로 설정했다.

## 서버 기본 차단

- 새 앱은 설치 등록, 신규 설치 자격 발급, 기존 설치 소유권 이전 요청에
  `minimumAgeConfirmed=true`, `agePolicyVersion=1`을 보낸다. 이 값은 앱의 로컬
  자기확인 결과이며 정부 발급 신원 또는 생년월일 증명이 아니다.
- 서버는 위 두 필드가 정확하지 않거나 누락된 신규 등록·자격 발급·기존 설치 이전 요청을
  거부한다.
- D1 `0009_minimum_age_policy.sql`은 기존 설치를 `age_policy_version=0`, 확인 시각 없음으로
  유지한다. 기존 행을 만 14세 이상으로 추정하거나 일괄 승인하지 않는다.
- 알림 스케줄러는 현재 정책 버전과 확인 시각이 모두 있는 설치만 조회하고, FCM 전송
  직전에도 같은 조건을 다시 검사한다. 따라서 마이그레이션 적용 직후 기존 설치의 알림은
  새 앱이 만 14세 이상 상태에서 재등록할 때까지 중단된다.
- 삭제·열람 관련 기존 인증 경로는 연령정책 미확인 상태에서도 막지 않는다. 기존 자료의
  삭제 기회까지 연령 확인으로 제한하지 않는다.

## 사용자 문구

- 최초 확인: `날씨챙겨는 만 14세 이상만 이용할 수 있어요. 생년월일은 입력하지 않아요.`
- 이용 불가 제목: `날씨챙겨를 이용할 수 없어요`
- 이용 불가 설명: `날씨챙겨는 만 14세 이상만 이용할 수 있어요.`
- 차단 범위: `만 14세 미만은 날씨·위치·알림·이용 통계·광고를 포함한 앱 서비스를 이용할 수 없어요.`

## 배포·검증 순서

1. 운영 D1에 `0009_minimum_age_policy.sql` 적용. 이 시점부터 기존 알림은 기본 중단된다.
2. 같은 서버 코드를 배포해 현재 정책 확인이 없는 설치 등록과 알림 발송을 거부한다.
3. 새 앱을 배포하고 만 14세 이상 이용자의 재등록으로 알림을 다시 활성화한다.
4. 스토어 대상 연령, 이용약관, 개인정보처리방침과 광고 설정을 `만 14세 이상` 정책에 맞춘다.
5. Android 실물과 iOS에서 최초 실행, 잘못 선택 후 정정, 재시작, 업그레이드, 백그라운드
   알림 및 네트워크 경계를 검증한다.

  더 강한 연령 확인이 필요하면 별도의 최소수집·보관·오류 정정·삭제 설계가 필요하다.
- SDK와 플러그인 코드는 앱 바이너리에 포함된다. 온라인 초기화를 차단한 것이며 라이브러리
  코드의 포함이나 Flutter 플러그인 등록 자체를 제거한 것은 아니다.
- Android 에뮬레이터 검증만 완료했다. Android 실물, iOS 런타임과 패킷 수준 검증은
  아직 남아 있다.
- 이 정책과 기술적 차단은 현행 법령, 스토어 및 광고 정책 검토를 대신하지 않는다.
