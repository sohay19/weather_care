# 알림·위젯·앱 통합 브리핑 정책 v2 구현

## 적용 범위

이 문서는 `알림_위젯_앱_통합_브리핑_정책_v2.md`를 현재 코드에 적용한 결과를 설명한다. 전달받은 원문은 `docs/전달원본/알림_위젯_앱_통합_브리핑_정책_v2.md`에 원본 그대로 보관한다.

적용 대상은 다음과 같다.

- 서버 `/main`, `/today` 응답
- 앱 Main 상단 브리핑
- Flutter가 생성하는 홈 위젯 snapshot
- Android 홈 위젯
- iOS WidgetKit 홈 위젯
- 설정 시각에 발송하는 날씨 요약 알림

Week는 날짜 단위 예보라는 기존 역할을 유지하며 현재 시각의 대표 scene을 복사하지 않는다. Detail과 시간별 Timeline도 각각 현재 관측 근거와 해당 `forecastAt` 자료를 표시하는 기존 역할을 유지한다.

## 서버 계약

서버는 `briefing`과 `briefingTimeline`을 함께 응답한다. 기존 앱 호환을 위해 `brief`와 `briefExpiresAt`도 유지하되 각각 현재 intent의 `copy.medium`과 다음 재평가 경계를 사용한다.

`briefing`의 핵심 필드는 다음과 같다.

| 구분 | 필드 |
| --- | --- |
| 식별 | `briefingId`, `locationKey`, `sceneId`, `topic`, `scope` |
| 시간 | `targetFrom`, `targetUntil`, `validFrom`, `validUntil`, `nextBriefingBoundary` |
| 출처 | `dataRole`, `observedAt`, `forecastAt`, `issuedAt`, `sourceLocation`, `qualityFlags` |
| 판단 | `severity`, `confidence`, `evidenceFields`, `headlineFact`, `supportingFact` |
| 행동 | `action`, `recommendedItems` |
| 체감 | `evidenceFields`의 `apparentTemperature`, `temperature` |
| 문구 | `copyVariantKey`, `copy.short`, `copy.medium`, `copy.long`, 알림 제목·본문 |

대표 scene은 눈, 비, 시야, 대기질, 오존, 자외선, 체감 더위·추위·쾌적, 바람, 고습·저습, 맑은 시야, 기본 안내를 동일한 선택기와 렌더러에서 만든다. 관측 자료는 현재형으로, 미래 자료는 예보형으로 구분한다.

`locationKey`는 격자에 행정구역 코드를 결합한다. 앱은 Today·Main·Week 요청에 선택 지역의 `regionCode`와 전체 지역명을 전달하므로, `57/125`를 공유하는 항동과 부천 일부 지역도 서로 다른 브리핑으로 식별한다.

연속 강수 슬롯은 하나의 사건 구간으로 합친다. 예를 들어 15~16시와 16~17시가 연속된 비 예보라면 모든 채널이 같은 15~17시 대상 구간을 사용한다.

## 시간 만료와 전환

- 현재 관측 브리핑의 freshness는 30분으로 제한한다.
- 비·눈은 사건 종료 시각 뒤에 후보에서 제거한다.
- 자외선은 일출 전과 일몰 이후에 후보에서 제거한다.
- `briefingTimeline`은 현재부터 당일 자정까지 scene이 바뀌는 경계를 포함한다.
- 유효한 다음 entry가 없으면 `최신 날씨를 확인해 주세요.`를 표시한다.
- 긴 문장을 잘라 short를 만들지 않고 채널별 완성 문장을 서버가 생성한다.

## 채널별 사용

| 채널 | 사용 문구 | 갱신 방식 |
| --- | --- | --- |
| Main 상단 | `copy.medium` | 앱 타이머와 복귀 시 timeline 재평가 |
| 중간 Android/iOS 위젯 | `copy.short` | 저장된 timeline에서 현재 entry 선택 |
| 큰 Android/iOS 위젯 | `copy.long` | 저장된 timeline에서 현재 entry 선택 |
| 요약 알림 | `notificationTitle`, `notificationBody` | 발송 시점에 서버가 다시 선택 |

Android는 다음 timeline 경계에 `AlarmManager` 갱신을 예약한다. iOS는 각 경계의 WidgetKit timeline entry를 미리 만들며 `.never` 정책을 사용하지 않는다. 두 위젯 모두 경계 전환을 위해 앱 실행이나 네트워크 요청을 요구하지 않는다.

준비물 아이콘은 활성 intent의 `recommendedItems`에 포함된 항목만 표시한다. 따라서 짧은 위젯과 큰 위젯이 준비물 때문에 서로 다른 대표 주제를 고르지 않는다.

요약 알림은 사용자가 켠 준비물 종류만 행동 scene 후보로 허용한다. 이미 끝난 낮 자외선이나 강수는 발송 시점 후보에서 제외하고, 유효한 습도·체감 등 다음 scene을 사용한다.

## 호환성과 배포

- 새 snapshot schema는 `2`이다.
- 새 서버 응답을 받기 전 구버전 응답은 앱에서 기존 `brief`를 사용할 수 있다.
- 새 구조가 존재하지만 현재 entry가 만료된 경우 과거 행동 문구로 되돌아가지 않는다.
- 서버와 앱 코드는 함께 배포하는 것이 권장되지만, 기존 필드를 유지하므로 순차 배포도 가능하다.

## 고정 회귀 테스트

- 비 scene의 short/medium/long/알림이 동일한 대상 구간과 우산 행동을 유지한다.
- 일몰 직전에는 UV를 허용하고 일몰 뒤에는 UV·선크림·양산 문구를 제거한다.
- 앱을 열지 않아도 위젯 timeline이 일몰 경계에서 저녁 scene으로 전환된다.
- 종료된 강수 scene을 재사용하지 않는다.
- 현재 관측과 미래 예보의 자료 역할과 시각을 섞지 않는다.
- `오후 15시`, `현재 지금`, 자외선이 기온 상승의 원인이라는 문구를 금지한다.
- 20시 요약 알림에 끝난 낮 UV 행동을 넣지 않는다.
- short가 long 문자열을 단순 절단한 값이 아님을 검사한다.

항동 중기예보 회귀 기준은 별도 지역 resolver와 `/weekly` 통합 테스트에서 계속 다음 값으로 고정한다.

```text
서울특별시 구로구 항동 + 57/125
midTermTaRegId   = 11B10101
midTermLandRegId = 11B00000
```
