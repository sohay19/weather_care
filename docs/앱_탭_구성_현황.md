# 날씨챙겨 앱 탭 구성 현황

- 기준일: 2026-08-21
- 기준: `weather_care_app/lib` 현재 구현 코드
- 수정 진행 순서: **Main → Today → Detail → Week → Setting**
- 하단 내비게이션 표시 순서: **Today → Detail → Main → Week → Setting**
- 앱 최초 진입 탭: **Main** (`selectedIndex = 2`)

## 1. 공통 화면 구조

### 탭 및 상태 유지

- 5개 탭은 `HomeScreen`의 `IndexedStack`으로 구성된다.
- 탭을 이동해도 각 탭의 위젯 상태는 유지된다.
  - 예: Today에서 체크한 준비물, Setting에서 바꾼 토글 상태
- 하단 내비게이션 높이는 74px이며 모든 탭 라벨을 항상 표시한다.
- 선택 전후 아이콘 색상은 동일하게 유지하고 아이콘 모양과 배경 표시로 선택 상태를 구분한다.
- Today의 준비물 정보 버튼을 누르면 Detail 탭으로 이동한다.
  - 현재는 선택한 준비물의 위치로 이동하지 않고 Detail 탭 전체 화면만 연다.

### 날씨 데이터 조회 상태

날씨 데이터는 다음 순서로 조회한다.

1. 운영 서버의 Today/Weekly API를 병렬 호출한다.
2. 운영 서버 조회에 실패하면 선택 팝업을 표시한다.
   - 추천 동작: `운영 서버 다시 시도`
   - 보조 동작: `단기예보만 보기`
   - 운영 서버가 준비물 추천과 TODO를 제공한다는 점을 안내해 재연결을 우선 권유한다.
3. 사용자가 보조 동작을 선택하고 앱에 KMA 키가 있으면 기상청 단기예보를 직접 조회한다.
4. 직접 조회도 불가능하면 날씨 화면 대신 상태 안내를 표시한다.

| 조회 상태 | Main | Today | Detail | Week | Setting |
| --- | --- | --- | --- | --- | --- |
| 운영 서버 연결 | 전체 기능 | 전체 기능 | 전체 기능 | 전체 기능 | 접근 가능 |
| 기상청 직접 조회 | 원시 날씨 + 생활 날씨 미지원 | 브리핑 + 준비물/타임라인 미지원 | 현재/시간별 날씨 + 판단 근거 미지원 | 날짜별 원시 예보 + 준비물 미지원 | 접근 가능 |
| 날씨 조회 불가 | 상태 안내 | 상태 안내 | 상태 안내 | 상태 안내 | 항상 접근 가능 |

### 공통 새로고침

- 모든 탭 헤더에서 새로고침 버튼을 제거했다.
- Main, Today, Detail, Week, Setting과 날씨 미지원 상태 화면은 모두 아래로 당겨서 새로고침할 수 있다.
- 새로고침 때도 운영 서버를 먼저 조회하며 실패하면 동일한 선택 팝업을 표시한다.

## 2. Main 탭

### 목적

현재 날씨와 오늘의 핵심 생활 정보를 한 화면에서 빠르게 확인하는 탭이다.

### 화면 구성 순서

1. **페이지 헤더**
   - 날짜와 요일
   - `{지역명}이라면 확인하세요`
   - `오늘의 핵심만 한 화면에 정리했어요`
   - 별도 앞 아이콘과 새로고침 버튼 없음
2. **상단 날씨 카드**
   - 서버가 만든 감성 브리핑, 최대 3줄
   - 기온·날씨를 직접 나열하지 않고 우산, 그늘, 옷깃, 발걸음처럼 간접적으로 표현
   - 7개 대표 장면, 완성형 템플릿 20개, 슬롯별 후보 10개로 조합
   - 날짜·지역별로 문장을 고정하고 같은 완성 문장은 7일 동안 반복하지 않음
   - 하늘 상태에 따른 배경 톤
   - 현재 기온, 10글자 이내 날씨 표현, 하늘 상태 아이콘
   - 다음 줄에 `체감온도`, 10글자 이내 체감 비유, 체감온도 또는 `체감 미지원`
   - 습도 / 풍속 / 자외선 지수 / 미세먼지
   - 미세먼지는 PM2.5를 우선 표시하고, 없으면 PM10으로 대체
   - 지표 수치는 안전(블루) / 주의(앰버) / 위험(레드) 색상으로 구분
3. **Check List 대시보드**
   - 타이틀 앞에 `TODAY` 라벨 표시
   - `Check List`
   - `오늘 날씨에 체크해야할 일들이에요`
   - 서버 생활 문구 중 앞의 3개를 표시
   - 서버 문구가 3개보다 적으면 서버가 안전한 기본 TODO를 채우고, 구버전 서버 호환을 위해 앱도 부족한 슬롯을 보완
   - 각 항목은 아이콘과 `제목 + 설명` 묶음을 가로로 배치하고, 3개 항목은 세로로 나열
   - 우산·양산·겉옷·마스크·물·선크림처럼 챙겨 나갈 항목은 서버 점수에 따라 배경·아이콘 색으로 중요도를 구분하고 테두리는 표시하지 않음
     - 80점 이상: 높은 중요도(앰버)
     - 60~79점: 중간 중요도(블루)
     - 60점 미만: 낮은 중요도(옅은 블루)
   - 일반 행동 TODO는 중립 배경을 유지해 챙길 물건과 시각적으로 구분
   - 운영 서버 미연결 시 `운영 서버 미연결로 미지원`

### 레이아웃 규칙

- `CustomScrollView`와 `SliverFillRemaining`으로 한 화면을 채우면서 당겨서 새로고침을 지원한다.
- 화면 높이가 620px 미만이면 compact 레이아웃을 사용한다.
  - 카드 간격과 내부 여백 축소
  - 일부 글자와 아이콘 크기 축소
- 상단 날씨 카드보다 Check List 대시보드에 더 큰 높이 비중을 배정한다.

### 데이터 및 동작

- `TodayWeatherResponse`의 `region`, `brief`, `current`, `lifestyleMessages`를 사용한다.
- 생활 문구 응답의 `score`를 중요도 색상 기준으로 사용하며, 구버전 서버에서 점수가 없으면 0점으로 처리한다.
- 날씨 상태 문자열로 Main의 mood를 결정한다.
- 현재 위치는 고정 격자 `nx=60`, `ny=121`로 조회하고 있어 Setting의 위치 선택과 아직 연결되지 않는다.

### 지표 색상 기준

| 지표 | 양호(블루) | 주의(앰버) | 위험(레드) |
| --- | --- | --- | --- |
| 습도 | 35% 초과, 70% 미만 | 35% 이하 또는 70~79% | 80% 이상 |
| 풍속 | 6m/s 미만 | 6~8.9m/s | 9m/s 이상 |
| 자외선 | 6 미만 | 6~7 | 8 이상 |
| PM2.5 | 35㎍/㎥ 이하 | 36~75㎍/㎥ | 76㎍/㎥ 이상 |
| PM10 대체값 | 80㎍/㎥ 이하 | 81~150㎍/㎥ | 151㎍/㎥ 이상 |

미세먼지 구간은 [에어코리아 대기환경정보 등급](https://www.airkorea.or.kr/web/main)을 사용한다. 값이 없으면 `--`와 중립 색상을 표시한다.

## 3. Today 탭

### 목적

오늘 챙길 준비물과 시간대별 행동 시점을 확인하는 탭이다.

### 화면 구성 순서

1. **페이지 헤더**
   - `TODAY`
   - `오늘을 챙겨요`
   - `{지역명}의 준비물과 생활 시점 안내`
2. **오늘 브리핑 카드**
   - 오늘의 한 줄 브리핑
   - 추천 준비물 개수
   - 추천이 없으면 `오늘은 특별한 준비물이 없어요.`
   - 직접 조회 상태에서는 준비물과 생활 시점이 미지원임을 안내
3. **오늘의 가방**
   - 추천 우선순위가 높은 순서로 준비물 표시
   - 추천된 항목만 표시
   - 1~3열 Wrap 레이아웃, 항목 높이 196px
   - 카드 탭: `챙길게요` ↔ `챙겼어요` 상태 전환
   - 정보 버튼: Detail 탭으로 이동
   - 추천이 없으면 빈 가방 안내
4. **오늘 하루 타임라인**
   - 시간 라벨
   - 시간대 상태 제목
   - 상세 설명
   - 해당 시간대 추천 준비물, 최대 3개

### 데이터 및 동작

- Home에서 추천을 우선순위 내림차순으로 정렬한 뒤 `recommended=true`인 항목만 전달한다.
- 준비물 체크 상태는 앱 메모리에만 유지되고 서버나 로컬 저장소에 저장되지 않는다.
- 전체 화면은 세로 스크롤이며 당겨서 새로고침할 수 있다.
- 운영 서버 미연결 시 `오늘의 가방`과 `오늘 하루`는 각각 미지원 카드로 교체된다.

### 현재 한계 및 확인 포인트

- [ ] 브리핑 카드의 필요성과 정보 중복 여부 검토
- [ ] 준비물 카드의 크기·열 수·표시 정보 검토
- [ ] `챙길게요/챙겼어요` 기능 유지 및 저장 범위 결정
- [ ] 준비물 정보 버튼의 이동 방식 검토
- [ ] 타임라인 시간 구간과 표현 방식 검토
- [ ] 준비물과 타임라인 간 중복 정보 정리
- [ ] 추천이 많거나 없는 경우 레이아웃 확인

## 4. Detail 탭

### 목적

현재 수치, 서버 판단 근거, 시간별 예보를 숫자로 확인하는 탭이다.

### 화면 구성 순서

1. **페이지 헤더**
   - `DETAIL`
   - `상세 날씨`
   - `추천을 만든 시간별 근거를 숫자로 확인해요`
2. **현재 상세 날씨 카드**
   - 현재 기온
   - 하늘 상태
   - 체감온도
   - 습도: 값이 있을 때만 표시
   - 자외선: 값이 있을 때만 표시
   - PM2.5: 값이 있을 때만 표시
3. **오늘의 판단 근거**
   - 우선순위가 높은 추천 중 최대 3개
   - 추천 아이콘, 제목, 설명
   - 추천이 없으면 별도 준비물 추천이 없다는 안내
   - 운영 서버 미연결 시 미지원 카드
4. **시간대별 상세**
   - 시간, 하늘 상태와 아이콘
   - 기온과 체감온도
   - 비: 강수확률과 강수량
   - 눈: 예상 여부와 적설량
   - 바람: 풍속
   - 강수확률 40% 이상인 행을 강조

### 데이터 및 동작

- `TodayWeatherResponse.current`, `recommendations`, `hourly`를 사용한다.
- 기상청 직접 조회에서도 현재 날씨와 시간별 상세는 표시할 수 있다.
- 전체 화면은 세로 스크롤이며 당겨서 새로고침할 수 있다.
- Today 준비물의 정보 버튼으로 이동해도 해당 추천을 별도로 강조하거나 자동 스크롤하지 않는다.

### 현재 한계 및 확인 포인트

- [ ] 현재 상세 지표 종류와 노출 순서 검토
- [ ] PM10·풍속 등 누락 지표 추가 여부 검토
- [ ] 결측값을 숨길지 `미지원`으로 보여줄지 기준 통일
- [ ] 판단 근거 최대 3개 제한 검토
- [ ] Today에서 선택한 추천을 Detail에서 연결해 보여줄지 결정
- [ ] 시간별 행의 정보 밀도와 강수 강조 기준 검토
- [ ] 시간별 데이터가 많을 때 탐색 방식 검토

## 5. Week 탭

### 목적

제공 가능한 날짜 범위의 날씨와 대표 준비물을 미리 확인하는 탭이다.

### 화면 구성 순서

1. **페이지 헤더**
   - `WEEK`
   - `한 주 날씨`
   - `날짜별 날씨와 대표 준비물을 미리 살펴봐요`
2. **이번 주 한눈에 요약**
   - 비 예보 일수
   - 전체 기간 중 최고 기온
   - 준비물이 있는 날의 수 또는 `미지원`
3. **날짜별 카드 목록**
   - 날짜
   - 첫 번째 항목에 `오늘` 표시
   - 날씨 아이콘과 상태
   - 대표 준비물 최대 2개
   - 준비물이 없거나 미지원인 상태 안내
   - 최저/최고 기온

### 데이터 및 동작

- `WeeklyWeatherResponse.days`의 전체 항목을 세로 목록으로 표시한다.
- 비 예보 일수는 날씨 문구에 `비` 또는 `소나기`가 포함됐는지로 계산한다.
- 첫 번째 응답 항목을 실제 날짜 비교 없이 오늘로 처리한다.
- 운영 서버 미연결 시 기상청 직접 조회의 날짜별 날씨는 표시하고 준비물만 미지원으로 처리한다.
- 전체 화면은 세로 스크롤이며 당겨서 새로고침할 수 있다.

### 현재 한계 및 확인 포인트

- [ ] 탭 이름과 실제 제공 기간의 정합성 검토
- [ ] 상단 3개 요약 지표 유지 여부 검토
- [ ] 날짜·요일 표현 방식 검토
- [ ] 강수확률·강수량 등 날짜별 추가 정보 필요 여부 검토
- [ ] 대표 준비물 최대 2개 제한 검토
- [ ] 첫 항목이 아니라 실제 날짜를 기준으로 `오늘`을 표시하도록 개선할지 결정
- [ ] 빈 목록과 일부 날짜 결측 상태 정의

## 6. Setting 탭

### 목적

기준 지역과 알림 종류를 설정하는 탭이다. 현재는 UI 데모 상태이며 설정 저장과 실제 기능 연결은 구현되지 않았다.

### 화면 구성 순서

1. **상단 제목**
   - `설정`
   - `내 위치와 필요한 알림만 편안하게 맞춰보세요.`
2. **기준 지역**
   - 현재 위치 사용
   - 지역 직접 선택
   - 현재 안내 지역은 문구상 `수원`으로 고정
3. **날씨 알림 전체 스위치**
   - 끄면 하위 준비물/주의 알림 스위치가 비활성화된다.
4. **알림 시간**
   - 기본값 `07:00`
   - 현재 행과 화살표만 있으며 시간 선택 동작은 없다.
5. **챙겨요 알림**
   - 우산
   - 양산
   - 겉옷
   - 마스크
   - 물
   - 선크림
6. **주의 및 날씨 안내**
   - 폭설 주의
   - 오늘 날씨
7. **현재 구현 상태 안내**
   - 설정은 화면 안에서만 바뀌고 서버에 저장되지 않는다는 안내
8. **데이터 출처 안내**
   - `날씨 정보는 기상청 공식 API를 사용합니다.`

### 데이터 및 동작

- 모든 초기 스위치는 켜짐 상태이고 위치 모드는 GPS, 알림 시간은 07:00이다.
- 설정 변경은 `SettingsScreen` 내부 메모리에만 반영된다.
- 탭 이동 후 돌아오면 `IndexedStack` 때문에 상태가 유지되지만 앱 재시작 시 초기화된다.
- Home의 날씨 조회에 사용하는 설정 인스턴스와 Setting의 인스턴스가 분리되어 있다.
- 위치 모드를 바꿔도 실제 좌표, 지역명, 날씨 조회 대상은 바뀌지 않는다.

### 현재 한계 및 확인 포인트

- [ ] Setting 헤더를 다른 탭과 같은 구조로 통일할지 검토
- [ ] GPS 권한과 위치 갱신 흐름 정의
- [ ] 지역 직접 선택 화면과 지역 저장 방식 정의
- [ ] 알림 시간 선택 UI 구현 범위 결정
- [ ] 알림 종류와 명칭 최종 확정
- [ ] 전체 알림을 끌 때 하위 값 보존 방식 확인
- [ ] 로컬 저장·서버 저장·FCM 연결 범위 결정
- [ ] 설정과 실제 Home 조회/추천/알림 기능 연결
- [ ] 데이터 출처 및 개인정보·권한 안내 위치 검토
